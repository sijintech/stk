# 在桌面检查 MuFerro 执行环境

在运行 MuFerro 案例之前，可以向所选 Runtime 提交一次独立的诊断任务，查看计算端的环境脚本、
SDK 目录、程序文件、动态库、MPI 启动器、许可目录和样例文件是否就位。检查结果不能证明
MuPRO 版本正确、许可可用，也不能证明案例能够运行。

命令行方式见[显式检查执行环境](runtime-mupro.md#显式检查执行环境)。

## 准备条件

- 已在 **Jobs / 任务** 中保存一个直连或 [SSH](ssh.md) Runtime，且该连接当前可用。
  Hub 连接不提供这项检查。
- 计算端已由管理员配置 MuPRO 环境，即 `MUPRO_SDK_PREFIX`、`STK_MUPRO_ENV_SCRIPTS`、
  `MUPROROOT` 或站点的 `preamble`，配置方法见 [MuPRO 节点环境](runtime-mupro.md#节点环境)。
  桌面不会传入 SDK、脚本、程序或许可路径，检查使用的是计算端自己的配置。
- 桌面后端版本支持执行环境检查。版本过旧时，面板只显示“更新桌面后端以启用执行环境检查”。

## 操作流程

1. 打开**项目表格**中的项目，在**表格**视图展开**材料仿真**（英文界面为 *Simulations*），
   把**计算引擎**设为 **MuFerro**。只有选择 MuFerro 时才会出现“执行环境检查”。
2. 在**运行环境**中选择保存好的 Runtime。若列表为空，点**管理…**前往任务页添加。
3. 设置**运行方式**和资源，规则与[准备案例](simulation-muferro.md#原生界面流程)相同：
   集群登录节点要选 Slurm/PBS 集群作业，并填写时限；队列、账户、内存可以在
   **高级执行选项（JSON）**中填写。检查只沿用运行方式、时限、内存、队列、账户和名称。
   诊断任务固定申请一个 CPU。**MPI 进程数**和**每进程线程数**对检查不起作用，
   也不会让检查去运行求解器。
4. 展开**执行环境检查**，在**诊断工作区**中二选一：
   - **新诊断工作区（检查时创建）**（默认）：按钮显示为**创建诊断工作区并检查**。
     只有点这个按钮才会在 Runtime 上新建一个空的诊断工作区并提交检查，
     单纯选中这一项不会创建任何东西。
   - 选一个已有的 Runtime 工作区：按钮显示为**检查执行环境**。
5. 点击按钮。桌面先在本机保存检查请求，然后提交诊断任务。面板保持可见并且上下文不变时，
   可能会在短时间内自动读取原任务的状态；没有自动读取或任务尚未结束时，手动点**读取原任务结果**。

这项检查不会改动以下内容：任务页当前选中的工作区、待处理的上传、桌面 Python 会话、
查看器和项目修订。它也不会上传项目或案例文件，不会调用 AI 模型，因此不产生模型费用。

检查会在计算端创建一个真实任务并占用执行资源。管理员配置的环境脚本会照常执行，
产生配置所带来的效果，所以它不是被动读取，也不能算“无副作用”的检查。

## 检查记录

**检查记录（保留原配置）**下拉框列出当前项目在当前 Runtime 上最近的检查请求，每项显示
请求创建时间和状态。每条记录都冻结了提交时的 Runtime、诊断工作区选择、运行方式和选项。
之后修改面板上的运行方式、资源或高级选项，只会影响下一次检查，不会改写已有记录。
**检查记录中的执行后端**显示的是记录里保存的值。

| 状态 | 含义与可做的事 |
|---|---|
| 检查请求已保存，尚未提交 | 请求已经保存，但还没有发出任务。原因可能是保存后面板被隐藏、上下文改变，或桌面重启。点**按原配置开始检查**，会按记录中的 Runtime 和原配置提交。重开面板不会自动开始。 |
| 提交结果未确认 | 提交过程中断，无法确定 Runtime 是否已经接受任务。点**按原配置恢复提交**，会使用同一请求和同一幂等键，已接受的任务不会被重复提交。不要为了弄清结果另发一次新的检查。 |
| 正在创建诊断工作区 / 正在提交检查 | 操作进行中。 |
| 检查已接受 / 检查进行中 | 任务已在 Runtime 上。点**读取原任务结果**查看最新状态。 |
| 已取得检查记录 | 已读取并校验诊断结果，见下一节。这不代表所有检查都通过。 |
| 检查未完成 | 没有得到可校验的结果，例如任务被取消、基础设施故障、结果文件不合规，或计算端版本过旧。记录保留原任务和错误信息。 |

同一 Runtime 上如果已有选项相同、仍未结束的记录，检查按钮暂时不可用。先在记录中继续处理
那条请求：开始、恢复提交或读取结果。

关闭或隐藏面板、切换项目或引擎、修改运行环境或选项，都会停止自动读取，但不会取消已经被
接受的任务。重新打开时，面板会重新读取 Runtime 的连接信息和工作区列表，但不会提交、恢复或读取
任何检查任务。记录的状态只来自本机保存的记录，原任务的最新状态要手动点**读取原任务结果**获取。需要取消原任务时，使用通用任务命令，例如
`suan jobs --profile NAME cancel TASK_ID`（见 [runtime 使用指南](runtime.md#输入与任务)）。

## 读懂结果

已取得的记录会显示汇总、采集时间、七项检查的状态，以及固定的一行“MuPRO 版本未验证 ·
许可未签出 · 未运行算例”。

| 汇总 | 含义 | 任务终态 |
|---|---|---|
| 前置检查通过 | 七项检查均为“通过”，未配置环境脚本时该项可以是“未配置”。 | 成功，退出码 0 |
| 部分前置检查未完成 | 没有失败项，但有“需补充”或“未检查”的项。 | 成功，退出码 0 |
| 前置检查失败 | 至少一项失败。 | 失败，退出码 1 |

各项检查的确切含义见[观察格式](specs/mupro-preflight-1.md#json)。需要注意以下几点：

- 无论汇总如何，以下三件事都没有验证：MuPRO 的软件版本、许可签出、求解器算例。
  找到可执行文件或许可目录，不能证明程序就是 MuPRO、许可有效或案例能运行。
  因此，退出码 0 或“前置检查通过”不表示求解器已就绪、许可可用或结果在科学上可信。
  实际运行仍要靠提交案例并[逐次校验](runtime-mupro.md#校验stk-mupro-1)。
- 显示的时间是计算端采集环境的时间，可能已经过时。再次点**读取原任务结果**读的是同一份
  结果，不会重新检查，时间也不会更新。想得到新的观察，需要再明确提交一次检查。
- 结果中不包含原始路径、主机地址、环境变量值、凭据或诊断输出。排查时不要把许可文件、
  Runtime 令牌或 SSH 密钥发给他人。需要看具体路径时，请管理员在计算端运行
  `python -m suan.mupro check --json`，见[本机预检观察](runtime-mupro.md#本机预检观察)。

## 故障排查

| 现象 | 原因与处理 |
|---|---|
| 只显示“更新桌面后端以启用执行环境检查” | 桌面后端版本过旧。更新 STK 桌面后再试。 |
| 显示“选择可连接的直连或 SSH 运行环境” | 尚未选择 Runtime，Runtime 离线，或当前是 Hub 连接。在**运行环境**中选择可用的直连或 SSH Runtime。 |
| 恢复或读取时提示目标已变化（`target changed` 或 `endpoint differs`） | 记录绑定提交时的 Runtime。保存的连接若后来改指了另一台服务器，旧请求会冲突，不会被悄悄改投到新地址。要处理旧记录，先把连接恢复到原来的服务器，再开始、恢复或读取它。若要检查新服务器，请把它另存为一个新连接后在那里检查。在原连接名下，只要还有选项相同、未结束的旧记录，检查按钮就保持不可用。新的检查无论如何都不能用来确认旧的“提交结果未确认”记录。 |
| 任务已被接受，读取后却显示“检查未完成”，错误为 `could not be verified` | 面板只保存这条通用信息，不保存计算端返回的原始诊断。常见原因是计算端 STK 版本过旧、缺少诊断入口，或者任务被取消。具体原因可以用状态行中的任务 ID 查询：`suan mupro preflight-result --profile NAME TASK_ID` 或 `suan jobs --profile NAME logs TASK_ID`。若是版本过旧，请管理员升级计算端 STK。桌面不会改用本机检查代替。 |
| 前置检查失败，或有“需补充”的项 | 环境配置不完整。把失败或需补充的项目名称告诉管理员，由管理员按 [MuPRO 节点环境](runtime-mupro.md#节点环境)修正，然后另做一次检查。 |
| 出现错误信息和**重新读取检查记录**按钮 | 读取连接、工作区或本机记录时出错，或者一次操作失败，检查暂时停用，其他功能照常可用。点**重新读取检查记录**后，面板会重新列出记录，可以从中看到失败的提交是否其实已被接受。若提示本机检查记录不可用（`journal is unavailable`），请保留原记录并联系维护者，不要删除或重建记录。 |

## 范围与限制

- Linux 已通过合成 SDK、实际 Runtime worker 和中英文原生窗口验收。真实 MuPRO 安装、许可、
  SSH、集群调度和 macOS、Windows 的此面板仍待对应环境验收。
- 检查不会改变 [MuPRO HDF5 结果](specs/mupro-hdf5-1.md)和 DAT 结果的格式，也不会改变
  案例的准备、提交、收集流程和 AI 助手的权限。AI 助手没有发起这项检查的工具。
- 检查不选择节点，也不代表某台主机可以长期使用。登录节点和计算节点的环境可能不同，
  需要在实际运行案例的后端上检查。
