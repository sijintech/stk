# STK render payload v2 (`stk.payload/2`)

> 中文摘要：本文档定义渲染数据包 v2：glTF 风格的 JSON 清单 + 以 sha256 寻址的二进制缓冲区（也可打包为单文件 `.stkp`），
> 图层类型 triangles、slice_image、lines、points、instances、volume、overlay；颜色表以 256 项 RGBA8 查找表传输，
> 坐标为相对 float64 `render_origin` 的 float32；按 phone/web/desktop 预算裁剪，并可降级为 scene v1。Web、离屏 VTK 与 Blender 共用此格式。

Status: frozen for Milestone 1 (Phase A). Schema: `suan/contracts/schemas/payload-2.schema.json`.
Example: `docs/specs/examples/payload-v2/` (`manifest.json` + `<sha256>.bin` buffers + `example.stkp`,
regenerated by `make_example.py`). Producer: `suan/render/payload.py` (Phase B3). Consumers: web
vtk.js (`web/src/payload.ts`, `layers.ts`, Phase B5), the offscreen VTK renderer (subprocess), the
scene v1 downgrade and, from Milestone 3, Blender.

## 1. Principles

- One payload feeds every renderer, so headless PNGs, the web view and Blender show the same thing.
- Attribute values travel **raw**; clients map them to colours on the GPU. A colormap change costs
  zero bytes. Colours are display aids: picking returns a float64 position (or instance index) and
  the client probes the original data (`view.probe`).
- Buffers are content-addressed (sha256), so unchanged buffers are never re-sent between frames.
- Positions are float32 **relative to** the float64 `render_origin` (as in scene v1).
- Clients skip layers of unknown `type` and ignore unknown keys that start with `x-`.

## 2. Manifest

| key | required | meaning |
|---|---|---|
| `schema` | yes | `"stk.payload/2"` |
| `source` | no | `{graph, graph_hash ("sha256:…"), view, time {step, time}, profile, reduced, generated_at, generator}` |
| `render_origin` | yes | float64 `[x, y, z]` in the scene's physical frame |
| `length_unit` | yes | unit of all coordinates (`grid_index`, `nm`, `unspecified`, …) |
| `bounds` | no | `[[xmin,ymin,zmin],[xmax,ymax,zmax]]` **relative to `render_origin`** (all 3D layers) |
| `buffers` | yes | `[{id, uri, sha256, byteLength, encoding: "raw"}]` |
| `accessors` | yes | `[{id, buffer, byteOffset, count, type, components, normalized?, min?, max?}]` |
| `colormaps` | no | continuous LUTs and categorical palettes (§5) |
| `layers` | yes | ordered; drawn in order (overlays on top) (§6) |
| `view` | no | an `stk.view/1` document (camera in physical coordinates, viewport, background, lighting, `visibility {layer id: bool}`) |
| `stats` | no | `{triangles, instances, points, line_segments, voxels, texels, bytes}` |
| `budget` | no | `{profile, limits {…}, reductions [{layer, reason, from, to}]}` |
| `extensions`, `x-*` | no | |

## 3. Buffers and accessors

- A **buffer** is raw little-endian bytes identified by `sha256` (hex of the bytes) with
  `byteLength`. `uri` is `"sha256:<hex>"` (hub blob store `GET /api/v1/blobs/<hex>`, or a sibling
  file `<hex>.bin` in the directory form) or `"#<k>"` inside a `.stkp` file (§9). `encoding` is
  `"raw"` (HTTP handles compression).
- An **accessor** is a tightly packed array view: `count` tuples of `components` values of `type`
  starting at `byteOffset`. No stride, no sparse storage.

| `type` | bytes | typed array |
|---|---|---|
| `i8` / `u8` | 1 | Int8Array / Uint8Array |
| `i16` / `u16` | 2 | Int16Array / Uint16Array |
| `i32` / `u32` | 4 | Int32Array / Uint32Array |
| `f32` | 4 | Float32Array |
| `f64` | 8 | Float64Array |

- `byteOffset` is a multiple of 8 (producers pad buffers with zeros), so typed-array views need no
  copy. `byteOffset + count × components × bytes ≤ byteLength`.
- `normalized: true` (integer types only) maps unsigned values to [0, 1] and signed to [−1, 1].
- `min`/`max` (per component) are optional hints; decoders may use them for validation.

Conventional accessor types: positions `f32×3`; normals `f32×3`; triangle and line indices `u32×1`
(`u16` allowed when < 65536 points); categorical attributes `i16`/`i32` (or `u8`/`u16`); continuous
attributes `f32`; LUTs `u8×4`.

## 4. Coordinates and precision

- Physical position = `(layer.origin ?? render_origin) + position` (computed in float64 by clients
  that need it, e.g. picking). A layer may carry its own absolute `origin` for far-apart multi-scale
  layers.
- The producer keeps `render_origin` fixed per (graph, view) rather than per frame, so geometry
  buffers of static layers are identical across frames (see the scene node's `render_origin`).
- Slice-image planes and volume grids are also relative to the layer origin.
- Optional quantized positions (int16 with `normalized: true` and a per-layer scale) are reserved for
  the phone profile; M1 producers write `f32`.

## 5. Colormaps

`colormaps[]` entries:

- **continuous**: `{id, name, categorical: false, lut: <accessor u8×4, count 256>, size: 256,
  nan_color?, below_color?, above_color?}`. Built-in names produced by `suan/render/colormaps.py`:
  `viridis`, `cividis` (CC0 data), `coolwarm`, `turbo`, `gray`.
- **categorical**: `{id, name, categorical: true, entries: [{value, name, color [r,g,b(,a)], family?,
  direction?, aliases?}], unknown_color?}` (e.g. `stk:cubic-26-orientation`, `stk-legacy:ferro27`,
  `stk:categorical`; see `domain-classifiers.md` §6).

Mapping a value v with range [lo, hi] (colour spec `range`, else the attribute `range`):

- continuous: t = (v − lo)/(hi − lo) (t = 0.5 when hi = lo); index = min(255, floor(t × 256)) for
  0 ≤ t ≤ 1 (VTK lookup-table bins; in Blender: a 256×1 image texture with **Closest** sampling at
  u = t); t < 0 → `below_color` or entry 0; t > 1 → `above_color` or entry 255; NaN → `nan_color`
  (default (0.5, 0.5, 0.5, 1)). RGBA8 → float = byte / 255.
- categorical: exact integer match with an entry; otherwise `unknown_color` (default (0.5, 0.5,
  0.5)). Sampling is always nearest (`interpolate: "nearest"`); categorical values are never
  interpolated.
- `stk:orientation-hsl` is the only **function colormap**: it colours by direction (`color.by:
  "direction"`) with `max_magnitude` and `lightness_range` (`domain-classifiers.md` §6.2). It needs no
  `colormaps[]` entry.

**Colour spec** (`appearance.color`): `{by: "solid" | "attribute" | "direction", solid,
attribute, component (int | "magnitude" | null), colormap (id or "stk:orientation-hsl"), range,
interpolate: "linear" | "nearest", max_magnitude, lightness_range}`. `component: null` on a
multi-component attribute means the magnitude. Defaults: `by: "solid"`, `solid: [0.8, 0.8, 0.8]`,
`interpolate: "linear"` (forced to `nearest` for categorical attributes).

## 6. Layers

Common keys: `id` (unique), `type`, `node` (graph node id), `name`, `visible` (default true),
`origin`, `pick {probe: {node, dataset}}` (where `view.probe` should read: a node of the graph that
produced the payload, upstream of the layer; clients walk upstream from it, or from `node` when `pick`
is absent, to the source), `time`.

An **attribute** is `{accessor, association: "point" | "cell", categorical?, palette?, range?,
unit?, quantity?, component_names?}`: point attributes have one tuple per position (per sample for
slice images, per instance for instances), cell attributes one per triangle / segment.

### 6.1 `triangles`

`positions` (f32×3), `indices` (count a multiple of 3; counter-clockwise front faces), optional
`normals` (f32×3 per point; if absent clients compute smooth or flat normals per `shading`),
`attributes`, `appearance {color, opacity (1), shading: "smooth" | "flat", lighting (true),
edges {visible, color, width_px}}`, optional `lods [{level ≥ 1, positions, normals, indices,
attributes}]` ordered coarse to fine (the main arrays are the finest).

### 6.2 `slice_image`

A planar grid of samples drawn as one textured quad (replaces extracting a plane as triangles; exact
nearest sampling for labels). `plane {origin, u, v}` (relative to the layer origin): `origin` is the
position of sample (0, 0), `u` the vector from sample (0, 0) to (w−1, 0), `v` from (0, 0) to
(0, h−1). `size [w, h]`; each attribute accessor holds w·h tuples, u index fastest. Clients draw the
quad over `origin … origin+u+v` with texel centres on the samples (texture coordinate of sample i is
(i + 0.5)/w). `appearance {color, opacity, lighting (default false)}`.

### 6.3 `lines`

`positions`, `mode: "segments"` (`indices` = point index pairs) or `"polylines"` (`indices` =
connectivity, `offsets` = n + 1 offsets into it), `attributes`, `appearance {color, opacity,
width_px (1), lighting (false)}`.

### 6.4 `points`

`positions`, optional `radii` (f32×1, world units), `attributes`, `appearance {color, opacity,
render_as: "points" | "spheres", size_px, radius}`, `progressive {shuffled, seed}`.

### 6.5 `instances` (glyphs)

`positions` (f32×3), `directions` (f32×3, raw vectors), optional `scales` (f32×1),
`attributes`, `glyph {shape, resolution (8), center (false)}`, `appearance {color, opacity,
scale {by: "uniform" | "magnitude" | "attribute", attribute?, factor > 0}, lighting}`,
`progressive`.

Canonical glyph geometry (unit length along +x; VTK source defaults):

| shape | geometry |
|---|---|
| `arrow` | shaft cylinder radius 0.03 from x = 0 to 0.65, cone tip radius 0.1 from 0.65 to 1.0 (`vtkArrowSource`) |
| `cone` | cone of height 1, base radius 0.25 at x = 0, apex at x = 1 |
| `line` | segment from (0, 0, 0) to (1, 0, 0) |
| `sphere` | sphere of radius 0.5 centred at the origin |
| `cube` | cube of edge 1 centred at the origin |

Per instance i: s = `scales[i]` if present, else `factor` (uniform), `factor × |d_i|` (magnitude) or
`factor × attribute_i` (attribute). Transform = translate(position_i) · rotate(+x → d_i/|d_i|) ·
scale(s) · translate(−0.5, 0, 0 if `center` and shape ∈ {arrow, cone, line}). Instances with
|d_i| = 0 are not drawn. `resolution` is the number of sides of cylinders/cones and the sphere's
longitude count. Instances are stored in a seeded random order when `progressive.shuffled`, so any
prefix is an unbiased subsample (clients may draw while loading).

### 6.6 `volume`

`grid {dimensions [nx, ny, nz], origin (relative to the layer origin), spacing, direction (row-major
3×3, default identity)}`; `data` = accessor of nx·ny·nz scalars, **x fastest, then y, then z**
(`u8`, `u16` or `f32`); physical value = stored × `value_scale` + `value_offset` (defaults 1, 0);
`value_range` = physical [min, max]; `unit`, `quantity`; `transfer_function {colormap (id),
range [lo, hi] (two finite physical values mapped over the LUT as in §5), opacity [[value, alpha], …]
(finite physical values, alpha in [0, 1], piecewise linear, constant beyond the ends)}`;
`sampling: "linear" | "nearest"` (nearest for labels); `shade` (false); optional `lods [{level,
data, dimensions, spacing}]` (2× mip levels, coarse to fine).

- **Categorical volumes.** `transfer_function.colormap` may reference a **categorical** palette
  (§5) instead of a continuous LUT (label volumes): the colour transfer function has two points per
  entry, `value − 0.499` and `value + 0.499`, both with the entry's `color`, so every integer label
  with an entry gets exactly its colour (a label without an entry gets an interpolated or clamped
  colour; hide it with the opacity function). `range` is then the label range and is not
  used for colour; `sampling` is `nearest`. The offscreen renderer and the web viewer follow this
  rule. The encoder's default opacity of a categorical volume (`stk.render.volume@1` with
  `opacity: null`) is one alpha (0.8) for every label ≥ 0 and 0 for negative labels (−1 =
  unclassified/no data/air): `[[lo, 0], [−0.5, 0], [−0.499, 0.8], [hi, 0.8]]` over the label range
  `[lo, hi]` (`[[lo, 0.8], [hi, 0.8]]` without negative labels), so the lowest label never becomes
  transparent the way a ramp over the range would make it.
- **Opacity unit distance.** Opacity values are per unit of length equal to the **smallest grid
  spacing** `min(spacing)` of the layer's grid (VTK `SetScalarOpacityUnitDistance(min(spacing))`,
  vtk.js `setScalarOpacityUnitDistance`): an `alpha` is the opacity accumulated over one voxel of
  the finest axis, so the picture does not depend on the absolute scale of the spacing (grid
  indices, nm or m) and a strided (reduced) volume looks like the full one.

### 6.7 `overlay`

Screen-space items: `kind`, `anchor` (`top_left`, `top`, `top_right`, `left`, `center`, `right`,
`bottom_left`, `bottom`, `bottom_right`), `offset_px [x, y]` (inward from the anchor), `size_px
[w, h]`, `title`, `source_layer` (the layer it explains).

| kind | keys |
|---|---|
| `scalar_bar` | `colormap` (continuous id), `range` (two finite numbers), `unit`, `orientation` (`vertical`), `label_count` (5, 2–20), `format` (`.3g`; the Python/d3 format subset `[sign][#][0][width ≤ 2 digits][,][.precision ≤ 2 digits][e E f F g G %]` or `[sign][#][0][width][,]d` (integers)) |
| `legend` | `colormap` (categorical id), `values` (entries to list; default all), `columns` (1) |
| `orientation_legend` | `colormap: "stk:orientation-hsl"`, `lightness_range`: a shaded sphere whose surface point n is coloured `orientation-hsl(n, M = 1)` |
| `text` | `text`, `font_size_px`, `color` |
| `axes_triad` | `labels` (`["x", "y", "z"]`); red x, green y, blue z arrows following the camera rotation |

All overlay texts (titles, labels, `text`) are plain text: renderers draw them literally and never
interpret markup (VTK's MathText would otherwise treat `$…$` and `|` specially and draw the title
`|v|` as `v`).

## 7. Profiles and budgets

Producers enforce budgets; clients may refuse payloads over their limits.

| profile | triangles | instances | points | volume voxels | bytes |
|---|---|---|---|---|---|
| `phone` | 300 000 | 50 000 | 200 000 | 128³ (u8) | 32 MiB |
| `web` | 2 000 000 | 500 000 | 2 000 000 | 256³ (u16) | 128 MiB |
| `desktop` (offscreen) | 20 000 000 | 5 000 000 | 20 000 000 | 1024³ (f32) | 2 GiB |

Reductions: triangles are decimated (`lods` may keep the full mesh for desktop), instances and
points keep a prefix of the shuffled order, volumes are strided by an integer factor (and quantized
per the profile encoding), slice images are strided. Each reduction sets `source.reduced: true` and
appends `budget.reductions[{layer, reason, from, to}]`.

## 8. Negotiation and transport

- Requests carry `{"accept": ["stk.payload/2", "stk.scene/1"], "profile": "web", "budget": {…}}`.
- Hub: `graph.evaluate` returns only the manifest (small JSON). The node agent uploads missing
  buffers first (`HEAD`/`PUT /api/v1/blobs/{sha256}`, hash-verified, idempotent); clients `GET
  /api/v1/blobs/{sha256}` with Range support and `Cache-Control: private, max-age=31536000,
  immutable`.
- Directory form (CLI `--out`, tests, the example): `manifest.json` + one `<sha256>.bin` per buffer.

## 9. `.stkp` single-file form

Little-endian:

```
offset 0   "STKP"                     4 bytes
       4   u32 version = 2
       8   u64 total file length
      16   chunks, each:
             u64 length of data (unpadded)
             4 bytes type: "JSON" or "BIN "
             u32 reserved = 0
             data, zero-padded ("JSON": space-padded) to a multiple of 8
```

Chunk 0 is the JSON manifest (UTF-8); chunk k ≥ 1 is buffer k in `buffers` order, referenced as
`"uri": "#k"` (buffers keep their `sha256`). Every chunk's data starts 8-byte aligned, so typed
arrays can view the file directly; u64 lengths allow volumes over 4 GiB. (The chunk header carries a
reserved u32 so that data stays 8-byte aligned.)

## 10. Decoder validation (web `payload.ts`, `suan/render/payload.py`)

Reject (with a clear error) when: `schema` differs; a buffer's bytes do not hash to `sha256` or
`byteLength` differs; an accessor is out of its buffer or misaligned; `count`/`components` mismatch
the layer's needs (positions ×3; triangle indices a multiple of 3; attribute counts per association;
`slice_image` w·h; volume nx·ny·nz; LUT 256 × 4 u8); an index is ≥ the position count; a position
or origin is non-finite; a referenced accessor/colormap id is missing; a volume `transfer_function`
`range`/`opacity` or a scalar bar `range`/`label_count`/`format` is malformed (§6.6, §6.7); any
member has the wrong JSON type (e.g. a string where an object is expected). `suan/render/payload.py`
raises `PayloadError` for all of these.

## 11. Scene v1 downgrade (`suan/render/v1.py`)

For clients that accept only `stk.scene/1` (C++ `SPACE_STK`, the current web viewer, Synorder):
take the first `triangles` layer (else expand `instances` into triangles, else convert a
`slice_image` into two triangles per texel quad), decimate to the v1 budget (80 000 vertices,
480 000 indices) with `scene._poly_mesh`, colour by the active attribute (magnitude for vectors),
keep `render_origin`, and return a scene that passes `suan.blender_client.scene.validate_scene`.

## 12. Example

`docs/specs/examples/payload-v2/manifest.json` (and `example.stkp`) contains:

- `domains` (`triangles`): three cubes, 72 points, 36 triangles, categorical point attribute
  `domain` (i16: STK labels 1 `T[100]`, 7 `O[110]`, 19 `R[111]`) coloured with palette `pal0`
  (`stk:cubic-26-orientation`, 28 entries) and a continuous attribute `height`;
- `arrows` (`instances`): 32 arrows in shuffled order, coloured by `stk:orientation-hsl`, scaled by
  magnitude;
- `density` (`volume`): an 8³ `u8` Gaussian blob with a 9-stop viridis LUT (`cm0`, an example LUT) and
  an opacity ramp;
- `box` (`lines`, segments) and overlays `scalar_bar`, `legend` (values 1, 7, 19),
  `orientation_legend`, `axes_triad`, `text`;
- `render_origin` `[100, 50, 25]` (all coordinates are relative to it) and an `iso` view.
