# STK render payload v2 (`stk.payload/2`)

> 中文摘要：本文档定义渲染数据包 v2：glTF 风格的 JSON 清单 + 以 sha256 寻址的二进制缓冲区（也可打包为单文件 `.stkp`），
> 图层类型 triangles、slice_image、lines、points、instances、volume、overlay；颜色表以 256 项 RGBA8 查找表传输，
> 坐标为相对 float64 `render_origin` 的 float32；按 phone/web/desktop 预算裁剪，并可降级为 scene v1。Web、离屏 VTK 与 Blender 共用此格式。

Status: frozen for Milestone 1 (Phase A); rules reconciled across the decoders on 2026-09-25 (see
[Changes](#changes)). Schema: `suan/contracts/schemas/payload-2.schema.json`.
Example: `docs/specs/examples/payload-v2/` (`manifest.json` + `<sha256>.bin` buffers + `example.stkp`,
regenerated by `make_example.py`). Producer: `suan/render/payload.py` (Phase B3). Consumers: web
vtk.js (`web/src/payload.ts`, `layers.ts`, Phase B5), the offscreen VTK renderer (subprocess), the
desktop viewer (`desktop/engine/lib/stk_io`, `stk_viewer_model`), the scene v1 downgrade and, from
Milestone 3, Blender. This document is normative; `suan/render/payload.py` is the reference validator and
encoder, and the web and desktop decoders give the same verdicts (§10).

## 1. Principles

- One payload feeds every renderer, so headless PNGs, the web view and Blender show the same thing.
- Attribute values travel **raw**; clients map them to colours on the GPU. A colormap change costs
  zero bytes. Colours are display aids: picking returns a float64 position (or instance index) and
  the client probes the original data (`view.probe`).
- Buffers are content-addressed (sha256), so unchanged buffers are never re-sent between frames.
- Positions are float32 **relative to** the float64 `render_origin` (as in scene v1).
- Clients skip layers of unknown `type` and overlays of unknown `kind` (with a warning, §10) and ignore
  unknown keys that start with `x-`.

### 2.1 View camera

Every client shows `view.camera` the same way (web `camera.ts` `cameraPose`, which is canonical;
`suan.render.layers.camera_pose` for the offscreen renderer; desktop `stk_viewer_model` `camera_pose`).
Positions are physical (graph spec §7) and become relative to `render_origin`; members that are not
numbers of the stated kind take their defaults.

- **Preset**: `camera.preset`, else `view.preset`, when it is a non-empty string; an unknown name is
  fitted like `iso`. Without one, a camera with `position` and `focal_point` (3 finite numbers each) is
  numeric; otherwise the preset is `iso`.
- **View angle** θ: `view_angle_deg` when it is a finite number in (0, 180), else 30. **Zoom**: a
  finite `zoom` > 0, else 1.
- **Numeric camera** (`position` ≠ `focal_point`): used as given, and it wins over a preset. Its `zoom`
  narrows the view angle to θ / zoom (VTK `Camera.Zoom`) unless a preset is also named: a producer's
  fitted preset has its zoom built into the position already.
- **Preset camera** (otherwise, also when `position` = `focal_point`): fitted to the bounds (the
  manifest `bounds`, else those of the drawn layers) with centre c and radius r (half the diagonal, 1
  when 0): focal point c, position c + u · r / sin(θ/2) / zoom (u and the preset view-up as graph spec §7).
- **View-up**: an explicit `view_up` (3 finite numbers) is honoured, also together with a preset,
  unless it is within 1e-6 of the view direction (|unit(up) × d| < 1e-6, d the unit direction of
  projection). Then, and without one, a numeric camera is **z-up**, or y-up when the view direction is
  within 1e-6 of the z axis (|d_z| > 0.99 once parallel); a preset keeps its own view-up.
- **Projection**: `projection: "parallel"` is orthographic with `parallel_scale` (a finite number > 0,
  else r / zoom); anything else is perspective.

## 3. Buffers and accessors

- A **buffer** is raw little-endian bytes identified by `sha256` (hex of the bytes) with
  `byteLength`. `uri` is `"sha256:<hex>"` (hub blob store `GET /api/v1/blobs/<hex>`, or a sibling
  file `<hex>.bin` in the directory form) or `"#<k>"` inside a `.stkp` file (§9). `encoding` is
  `"raw"` (HTTP handles compression).
- An **accessor** is a tightly packed array view: `count` tuples of `components` values of `type`
  starting at `byteOffset`. No stride, no sparse storage.

| `type` | bytes | typed array |
|---|---|---|
| `i8` / `u8` | 1 | Int8Array / Uint8Array |
| `i16` / `u16` | 2 | Int16Array / Uint16Array |
| `i32` / `u32` | 4 | Int32Array / Uint32Array |
| `f32` | 4 | Float32Array |
| `f64` | 8 | Float64Array |

- `byteOffset` is a multiple of 8 (producers pad buffers with zeros), so typed-array views need no
  copy. `byteOffset + count × components × bytes ≤ byteLength`.
- `normalized: true` (integer types only) maps unsigned values to [0, 1] and signed to [−1, 1].
- `min`/`max` (per component) are optional hints; decoders may use them for validation.

Conventional accessor types: positions `f32×3`; normals `f32×3`; triangle and line indices `u32×1`
(`u16` allowed when < 65536 points); categorical attributes `i16`/`i32` (or `u8`/`u16`); continuous
attributes `f32`; LUTs `u8×4`.

## 4. Coordinates and precision

- Physical position = `(layer.origin ?? render_origin) + position` (computed in float64 by clients
  that need it, e.g. picking). A layer may carry its own absolute `origin` for far-apart multi-scale
  layers.
- The producer keeps `render_origin` fixed per (graph, view) rather than per frame, so geometry
  buffers of static layers are identical across frames (see the scene node's `render_origin`).
- Slice-image planes and volume grids are also relative to the layer origin.
- Optional quantized positions (int16 with `normalized: true` and a per-layer scale) are reserved for
  the phone profile; M1 producers write `f32`.

## 5. Colormaps

`colormaps[]` entries:

- **continuous**: `{id, name, categorical: false, lut: <accessor u8×4, count 256>, size: 256,
  nan_color?, below_color?, above_color?}`. Built-in names produced by `suan/render/colormaps.py`:
  `viridis`, `cividis` (CC0 data), `coolwarm`, `turbo`, `gray`.
- **categorical**: `{id, name, categorical: true, entries: [{value, name, color [r,g,b(,a)], family?,
  direction?, aliases?}], unknown_color?}` (e.g. `stk:cubic-26-orientation`, `stk-legacy:ferro27`,
  `stk:categorical`; see `domain-classifiers.md` §6). `value` is a unique integer, `name` a string and
  every colour (`color`, `unknown_color`, `nan_color`, `below_color`, `above_color`) 3 or 4 numbers in
  [0, 1].

Mapping a value v with range [lo, hi] (colour spec `range`, else the attribute `range`):

- continuous: t = (v − lo)/(hi − lo) (t = 0.5 when hi = lo); index = min(255, floor(t × 256)) for
  0 ≤ t ≤ 1 (VTK lookup-table bins; in Blender: a 256×1 image texture with **Closest** sampling at
  u = t); t < 0 → `below_color` or entry 0; t > 1 → `above_color` or entry 255; NaN → `nan_color`
  (default (0.5, 0.5, 0.5, 1)). RGBA8 → float = byte / 255.
- categorical: exact integer match with an entry; otherwise `unknown_color` (default (0.5, 0.5,
  0.5)). Sampling is always nearest (`interpolate: "nearest"`); categorical values are never
  interpolated. A non-integer (or non-finite) label value always gets the unknown grey, also with the
  generic `stk:categorical` colours of labels without a palette (it is never truncated to a
  neighbouring label).
- `stk:orientation-hsl` is the only **function colormap**: it colours by direction (`color.by:
  "direction"`) with `max_magnitude` and `lightness_range` (`domain-classifiers.md` §6.2). It needs no
  `colormaps[]` entry.

**Colour spec** (`appearance.color`): `{by: "solid" | "attribute" | "direction", solid,
attribute, component (int | "magnitude" | null), colormap (id or "stk:orientation-hsl"), range,
interpolate: "linear" | "nearest", max_magnitude, lightness_range}`. `component: null` on a
multi-component attribute means the magnitude. Defaults: `by: "solid"` (also when `by` is absent or
null), `solid: [0.8, 0.8, 0.8]`, `interpolate: "linear"` (forced to `nearest` for categorical
attributes). `attribute` must name an attribute of the layer (`by: "attribute"`, and `by: "direction"`
when given); `colormap` must name a colormap of the payload or be `stk:orientation-hsl`, the only
colormap of `by: "direction"`; `range` is two finite numbers.

## 6. Layers

Common keys: `id` (unique), `type`, `node` (graph node id), `name`, `visible` (default true),
`origin`, `pick {probe: {node, dataset}}` (where `view.probe` should read: a node of the graph that
produced the payload, upstream of the layer; clients walk upstream from it, or from `node` when `pick`
is absent, to the source), `time`.

An **attribute** is `{accessor, association: "point" | "cell", categorical?, palette?, range?,
unit?, quantity?, component_names?}`: point attributes have one tuple per position (per sample for
slice images, per instance for instances), cell attributes one per triangle / segment.

### 6.1 `triangles`

`positions` (f32×3), `indices` (count a multiple of 3; counter-clockwise front faces), optional
`normals` (f32×3 per point; if absent clients compute smooth or flat normals per `shading`),
`attributes`, `appearance {color, opacity (1), shading: "smooth" | "flat", lighting (true),
edges {visible, color, width_px}}`, optional `lods [{level ≥ 1, positions, normals, indices,
attributes}]` ordered coarse to fine (the main arrays are the finest).

### 6.2 `slice_image`

A planar grid of samples drawn as one textured quad (replaces extracting a plane as triangles; exact
nearest sampling for labels). `plane {origin, u, v}` (relative to the layer origin): `origin` is the
position of sample (0, 0), `u` the vector from sample (0, 0) to (w−1, 0), `v` from (0, 0) to
(0, h−1). `size [w, h]`; each attribute accessor holds w·h tuples, u index fastest. Clients draw the
quad over `origin … origin+u+v` with texel centres on the samples (texture coordinate of sample i is
(i + 0.5)/w). `appearance {color, opacity, lighting (default false)}`.

### 6.3 `lines`

`positions`, `mode: "segments"` (`indices` = point index pairs) or `"polylines"` (`indices` =
connectivity, `offsets` = n + 1 `u32` offsets into it, rising from 0 to the index count),
`attributes`, `appearance {color, opacity, width_px (1), lighting (false)}`. Cell attributes have one
value per **segment**, also for polylines (Σ max(n_k − 1, 0) values for polylines of n_k points); one
value per polyline is rejected.

### 6.4 `points`

`positions`, optional `radii` (f32×1, world units), `attributes`, `appearance {color, opacity,
render_as: "points" | "spheres", size_px, radius}`, `progressive {shuffled, seed}`.

### 6.5 `instances` (glyphs)

`positions` (f32×3), `directions` (f32×3, raw vectors), optional `scales` (f32×1),
`attributes`, `glyph {shape, resolution (8), center (false)}`, `appearance {color, opacity,
scale {by: "uniform" | "magnitude" | "attribute", attribute?, factor (a finite number > 0, default 1)},
lighting}`, `progressive`.

Canonical glyph geometry (unit length along +x; VTK source defaults):

| shape | geometry |
|---|---|
| `arrow` | shaft cylinder radius 0.03 from x = 0 to 0.65, cone tip radius 0.1 from 0.65 to 1.0 (`vtkArrowSource`) |
| `cone` | cone of height 1, base radius 0.25 at x = 0, apex at x = 1 |
| `line` | segment from (0, 0, 0) to (1, 0, 0) |
| `sphere` | sphere of radius 0.5 centred at the origin, `resolution` longitudes and max(3, ⌊`resolution` / 2⌋ + 1) latitude rows, poles included (VTK `PhiResolution`) |
| `cube` | cube of edge 1 centred at the origin |

Per instance i: s = `scales[i]` if present, else `factor` (uniform), `factor × |d_i|` (magnitude) or
`factor × attribute_i` (attribute). Transform = translate(position_i) · rotate(+x → d_i/|d_i|) ·
scale(|s|) · translate(−0.5, 0, 0 if `center` and shape ∈ {arrow, cone, line}). Instances whose
direction is zero or not finite, or whose s is not finite (e.g. a NaN in `scales`), are not drawn;
they are valid data. `resolution` is the number of sides of cylinders/cones and the sphere's
longitude count. Instances are stored in a seeded random order when `progressive.shuffled`, so any
prefix is an unbiased subsample (clients may draw while loading).

### 6.6 `volume`

`grid {dimensions [nx, ny, nz], origin (relative to the layer origin), spacing, direction (row-major
3×3, 9 finite numbers, default identity)}`; `data` = accessor of nx·ny·nz scalars, **x fastest, then y,
then z** (`u8`, `u16` or `f32`); physical value = stored × `value_scale` + `value_offset` (finite
numbers, defaults 1, 0); `value_range` = physical [min, max] (two finite numbers); `unit`, `quantity`;
`transfer_function {colormap (id), range [lo, hi] (two finite physical values mapped over the LUT as
in §5), opacity [[value, alpha], …] (at least two points; finite physical values, alpha in [0, 1],
piecewise linear, constant beyond the ends)}`; `sampling: "linear" | "nearest"` (nearest for labels);
`shade` (false); optional `lods [{level, data, dimensions, spacing}]` (2× mip levels, coarse to fine;
`data` holds the product of the lod's `dimensions`).

- **Colour transfer function.** A continuous LUT is spread over `range` with one point per bin at its
  centre, lo + (k + 0.5) / 256 · (hi − lo), with entry k's colour. A **degenerate range** (hi ≤ lo) is a
  single point at lo with LUT entry 128 (the t = 0.5 colour of §5), so the whole volume has one colour.
- **Opacity points** are sorted by value; of several points with the same value **the last one wins**
  (VTK and vtk.js `AddPoint` replace a point; `colormaps.opacity_at` does the same).

- **Categorical volumes.** `transfer_function.colormap` may reference a **categorical** palette
  (§5) instead of a continuous LUT (label volumes): the colour transfer function has two points per
  entry, `value − 0.499` and `value + 0.499`, both with the entry's `color` quantized to RGBA8 (byte /
  255, like every payload colour), so every integer label with an entry gets exactly its colour (a label without an entry gets an interpolated or clamped
  colour; hide it with the opacity function). `range` is then the label range and is not
  used for colour; `sampling` is `nearest`. The offscreen renderer and the web viewer follow this
  rule. The encoder's default opacity of a categorical volume (`stk.render.volume@1` with
  `opacity: null`) is one alpha (0.8) for every label ≥ 0 and 0 for negative labels (−1 =
  unclassified/no data/air): `[[lo, 0], [−0.5, 0], [−0.499, 0.8], [hi, 0.8]]` over the label range
  `[lo, hi]` (`[[lo, 0.8], [hi, 0.8]]` without negative labels), so the lowest label never becomes
  transparent the way a ramp over the range would make it.
- **Opacity unit distance.** Opacity values are per unit of length equal to the **smallest grid
  spacing** `min(spacing)` of the layer's grid (VTK `SetScalarOpacityUnitDistance(min(spacing))`,
  vtk.js `setScalarOpacityUnitDistance`): an `alpha` is the opacity accumulated over one voxel of
  the finest axis, so the picture does not depend on the absolute scale of the spacing (grid
  indices, nm or m) and a strided (reduced) volume looks like the full one.

### 6.7 `overlay`

Screen-space items: `kind`, `anchor` (`top_left`, `top`, `top_right`, `left`, `center`, `right`,
`bottom_left`, `bottom`, `bottom_right`), `offset_px [x, y]` (inward from the anchor), `size_px
[w, h]`, `title`, `source_layer` (the layer it explains).

| kind | keys |
|---|---|
| `scalar_bar` | `colormap` (continuous id), `range` (two finite numbers), `unit`, `orientation` (`vertical`), `label_count` (5, an integer 2–20), `format` (`.3g`; the format subset below) |
| `legend` | `colormap` (categorical id), `values` (entries to list; default all), `columns` (1) |
| `orientation_legend` | `colormap: "stk:orientation-hsl"`, `lightness_range`: a shaded sphere whose surface point n is coloured `orientation-hsl(n, M = 1)` |
| `text` | `text`, `font_size_px`, `color` |
| `axes_triad` | `labels` (`["x", "y", "z"]`); red x, green y, blue z arrows following the camera rotation |

All overlay texts (titles, labels, `text`) are plain text: renderers draw them literally and never
interpret markup (VTK's MathText would otherwise treat `$…$` and `|` specially and draw the title
`|v|` as `v`).

An overlay whose `kind` is an unknown string, or whose presentation members have a wrong type (§10), is
skipped with a warning; a missing or non-string `kind` is an error.

**Scalar-bar labels.** `label_count` labels at lo + (hi − lo) · k / (count − 1). `format` is the
subset `[sign][#][0][width][,][.precision][type]` of Python's format-spec mini-language (width and
precision at most two digits; type `e E f F g G %`, none, or `d` without a precision; the whole string,
so `".3g\n"` is not a format), with Python's semantics in every client (`suan.render.payload.format_label`,
web `formatNumber`, desktop `format_label`):

- digits are rounded **half to even** on the exact binary value of the number (`0.125` with `.2f` is
  `0.12`, `0.375` is `0.38`; JavaScript's `toFixed` would round ties away from zero);
- `d` formats the value **rounded to the nearest integer, ties to even** (Python `round()`: 2.5 → `2`,
  3.5 → `4`, −2.5 → `−2`), as an integer (so `+05d`, `,d` pad and group it);
- a label that shows zero never carries a minus sign: −0.0 and a negative value that rounds to zero
  print as positive zero (−0.0001 with `.2f` is `0.00`, with `+.2f` `+0.00`; Python's `z` option);
- non-finite values print as `inf`, `-inf`, `nan` (upper case for `E F G`), also with `d`;
- a format outside the subset (only reachable by calling the formatters directly, since decoders reject
  it) falls back to `.3g`.

## 7. Profiles and budgets

Producers enforce budgets; clients may refuse payloads over their limits.

| profile | triangles | instances | points | volume voxels | bytes |
|---|---|---|---|---|---|
| `phone` | 300 000 | 50 000 | 200 000 | 128³ (u8) | 32 MiB |
| `web` | 2 000 000 | 500 000 | 2 000 000 | 256³ (u16) | 128 MiB |
| `desktop` (offscreen) | 20 000 000 | 5 000 000 | 20 000 000 | 1024³ (f32) | 2 GiB |

Reductions: triangles are decimated (`lods` may keep the full mesh for desktop), instances and
points keep a prefix of the shuffled order, volumes are strided by an integer factor (and quantized
per the profile encoding), slice images are strided. Each reduction sets `source.reduced: true` and
appends `budget.reductions[{layer, reason, from, to}]`.

## 8. Negotiation and transport

- Requests carry `{"accept": ["stk.payload/2", "stk.scene/1"], "profile": "web", "budget": {…}}`.
- Hub: `graph.evaluate` returns only the manifest (small JSON). The node agent uploads missing
  buffers first (`HEAD`/`PUT /api/v1/blobs/{sha256}`, hash-verified, idempotent); clients `GET
  /api/v1/blobs/{sha256}` with Range support and `Cache-Control: private, max-age=31536000,
  immutable`.
- Directory form (CLI `--out`, tests, the example): `manifest.json` + one `<sha256>.bin` per buffer.

## 9. `.stkp` single-file form

Little-endian:

```
offset 0   "STKP"                     4 bytes
       4   u32 version = 2
       8   u64 total file length
      16   chunks, each:
             u64 length of data (unpadded)
             4 bytes type: "JSON" or "BIN "
             u32 reserved = 0
             data, zero-padded ("JSON": space-padded) to a multiple of 8
```

Chunk 0 is the JSON manifest (UTF-8); chunk k ≥ 1 is buffer k in `buffers` order, referenced as
`"uri": "#k"` (buffers keep their `sha256`). Every chunk's data starts 8-byte aligned, so typed
arrays can view the file directly; u64 lengths allow volumes over 4 GiB. (The chunk header carries a
reserved u32 so that data stays 8-byte aligned.)

Decoders reject a file whose total length field differs from the file size (in either direction:
trailing bytes are an error), a chunk whose reserved field is not 0, truncated chunks, padding past
the end, a first chunk that is not `JSON` or a later one that is not `BIN `, a buffer whose `uri` is
not `#k` (k ≥ 1, no leading zero) naming a chunk of the file, and a manifest that is not UTF-8 (strict:
no overlong forms or surrogates; a byte-order mark is an error) RFC 8259 JSON (§10).

## 10. Decoder validation

`suan/render/payload.py` (the reference: `PayloadError` with an RFC 6901 JSON-pointer `path`), web
`payload.ts` (`PayloadError`) and desktop `stk_io` (`io::PayloadError`, same paths as Python) accept and
reject exactly the same payloads and skip the same layers. `desktop/tests/unit` holds them to it on a
corpus of spec cases, `.stkp` corruptions and a seeded mutation corpus
(`fixtures/payload/cases.json`, the web verdicts in `web_vectors.json`, regenerated by
`make_fixtures.py` then `make_web_vectors.mjs`).

**JSON values.**

- A manifest is RFC 8259 JSON in UTF-8 without a byte-order mark; `NaN`/`Infinity` literals and numbers
  that overflow a double (`1e400`) are errors.
- A member of the wrong JSON type is an error. Booleans are never numbers. A **finite number** is a JSON
  number that is not ±∞. An **integer** is a JSON number with an integral value within ±(2⁵³ − 1):
  `5` and `5.0` are the same number (JavaScript decoders cannot tell them apart), `1e300` is not an
  integer. Counts, offsets, lengths, sizes, dimensions, category values and `label_count` are integers.
- An optional member whose value is `null` counts as **absent** (its default applies). A required member
  that is `null` fails its type check.
- **Ids** (`buffers`, `accessors`, `colormaps`, `layers`) match `[A-Za-z0-9_][A-Za-z0-9_.:-]{0,127}` over
  the whole string (so `"a\n"` is not an id), are unique within their list, and are none of
  `__proto__`, `constructor`, `prototype` (they would address the prototype chain of JavaScript
  objects).

**Errors** (the payload is rejected):

- manifest: not an object; `schema` differs; a required key (§2) is missing; `render_origin` not 3 finite
  numbers; `length_unit` not a non-empty string; `bounds` not `[[3 finite], [3 finite]]`; `view` not an
  object with `schema: "stk.view/1"`;
- buffers (a list of objects): `uri` other than `"sha256:<its sha256>"` (`"#k"` inside a `.stkp`, §9);
  `encoding` other than `"raw"`; `sha256` not 64 lower-case hex digits; `byteLength` not an integer equal
  to the data size; bytes that do not hash to `sha256`;
- accessors (a list of objects): unknown `buffer` or `type`; `count` < 0, `components` < 1 or > 16,
  `byteOffset` < 0 or not a multiple of 8 (integers); running past the end of the buffer; `normalized`
  not a boolean, or true on a float type;
- colormaps (a list of objects): `categorical` not a boolean; categorical: `entries` not a list of
  objects, an entry `value` that is not an integer, a `name` that is not a string, a colour that is not
  3 or 4 numbers in [0, 1], duplicate values, a bad `unknown_color`; continuous: `lut` not a 256 × 4 `u8`
  accessor, `size` not 256, a bad `nan_color`/`below_color`/`above_color`;
- layers (a list of objects): a bad or duplicate `id`; `name` not a string; `type` not a string; for a
  known type a missing required key (§6) or `origin` not 3 finite numbers, and:
  - accessor references that are missing or have the wrong type, components or count (positions f32×3;
    normals f32×3 per point; indices u32/u16×1, a multiple of 3 for triangles and 2 for segments;
    radii and scales f32×1; directions f32×3 per instance; volume data u8/u16/f32×1 with nx·ny·nz
    values, also per lod; attribute counts per association);
  - `attributes` not an object of objects; an `association` other than `point`, or `cell` where the type
    has cells (triangles: per triangle; lines: per segment); a `palette` that is not a categorical
    colormap; `appearance` or a colour spec (§5) that is not an object; an unknown `color.by`,
    attribute or colormap; `direction` colouring with another colormap; a malformed `color.range`;
  - triangles: `lods` not a list of objects, or lods whose positions, indices, normals and attributes
    fail the rules of the main arrays;
  - slice_image: `plane` origin/u/v not 3 finite numbers each; `size` not two integers ≥ 1; no attribute;
  - lines: an unknown `mode`; polylines without `offsets`, or offsets not a `u32` accessor rising from 0
    to the index count; cell attributes not one value per segment;
  - instances: `glyph` not an object or an unknown `shape` (§6.5 table); `appearance.scale` not an
    object, an unknown scale `attribute`, a `factor` that is not a finite number > 0;
  - volume: `dimensions` not 3 integers ≥ 1; `origin`/`spacing` not 3 finite numbers, a spacing ≤ 0;
    `direction` not 9 finite numbers; `value_range` not two finite numbers; `value_scale`/`value_offset`
    not finite numbers; `transfer_function` not an object, an unknown `colormap`, `range` not two finite
    numbers, `opacity` with fewer than two points or a point that is not [finite value, alpha in
    [0, 1]]; `lods` not a list of objects, a lod without 3 integer `dimensions` ≥ 1;
  - overlay: `kind` missing or not a string; for a known kind: `scalar_bar` without a continuous
    `colormap`, `range` not two finite numbers, `label_count` not an integer from 2 to 20, a `format`
    outside the subset of §6.7; `legend` without a categorical `colormap`; `text` without a string
    `text`;
- data: a non-finite position (also in triangle lods); an index ≥ the position count; polyline offsets
  that do not rise from 0 to the index count.

**Warnings** (the layer is skipped, never rejected, for forward compatibility §1): a layer whose `type`
is an unknown string; an overlay whose `kind` is an unknown string; an overlay (of a known kind) with a
presentation member of a wrong type: `title`, `anchor`, `source_layer` not strings; `offset_px` not 2
finite numbers; `size_px` not a positive number or 2 positive numbers; a scalar bar's `unit` or
`orientation` not a string; a legend's `values` not a list of integers or `columns` not an integer; an
orientation legend's `lightness_range` not 2 finite numbers; a text's `font_size_px` not a positive
number or `color` not 3 or 4 finite numbers; an axes triad's `labels` not 3 strings. The decoders return
warnings separately from errors, each with the JSON pointer of the layer (`/layers/<i>`), its id and a
message (`Payload.warnings` in Python, `LoadedPayload.skipped` on the web, `io::Payload::warnings` on
the desktop), and no client draws those layers.

Display hints that do not affect decoding (`visible`, `node`, `pick`, `time`, glyph `resolution` and
`center`, appearance `opacity`, `shading`, `lighting`, `width_px`, accessor `min`/`max`, …) are not
validated; clients read them with their defaults. In an insecure browser context (no WebCrypto) the web
viewer cannot hash buffers and reports that as a warning.

## 11. Scene v1 downgrade (`suan/render/v1.py`)

For clients that accept only `stk.scene/1` (C++ `SPACE_STK`, the current web viewer, Synorder):
take the first `triangles` layer (else expand `instances` into triangles, else convert a
`slice_image` into two triangles per texel quad), decimate to the v1 budget (80 000 vertices,
480 000 indices) with `scene._poly_mesh`, colour by the active attribute (magnitude for vectors),
keep `render_origin`, and return a scene that passes `suan.blender_client.scene.validate_scene`.

## 12. Example

`docs/specs/examples/payload-v2/manifest.json` (and `example.stkp`) contains:

- `domains` (`triangles`): three cubes, 72 points, 36 triangles, categorical point attribute
  `domain` (i16: STK labels 1 `T[100]`, 7 `O[110]`, 19 `R[111]`) coloured with palette `pal0`
  (`stk:cubic-26-orientation`, 28 entries) and a continuous attribute `height`;
- `arrows` (`instances`): 32 arrows in shuffled order, coloured by `stk:orientation-hsl`, scaled by
  magnitude;
- `density` (`volume`): an 8³ `u8` Gaussian blob with a 9-stop viridis LUT (`cm0`, an example LUT) and
  an opacity ramp;
- `box` (`lines`, segments) and overlays `scalar_bar`, `legend` (values 1, 7, 19),
  `orientation_legend`, `axes_triad`, `text`;
- `render_origin` `[100, 50, 25]` (all coordinates are relative to it) and an `iso` view.

## Changes

2026-09-25, reconciliation of the decoders and renderers (Python, web, desktop); rules the spec did not
state before are marked *new*:

- §10 rewritten as the complete list. The web decoder now rejects what Python rejects (categorical
  colours outside [0, 1], duplicate or non-integer category values, scalar-bar `format` and
  `label_count`, unknown glyph shapes and `color.by`, non-object volume `lods`, a `view` without its
  schema, unknown associations, bad polyline offsets, alpha outside [0, 1], a non-zero `.stkp` reserved
  field, invalid UTF-8). Python and the desktop now reject what the web rejected: a non-string category
  `name`, a non-finite `grid.direction`, `value_range` that is not two finite numbers, fewer than two
  volume opacity points, a glyph scale `factor` ≤ 0, the ids `__proto__`, `constructor`, `prototype`,
  a non-string layer `name`, slice images without attributes.
- *New*: integers are integral numbers within ±(2⁵³ − 1) (`5.0` is accepted where `5` is); optional
  members that are `null` count as absent; ids, formats and patterns are matched over the whole string
  (a trailing newline never matches); `NaN`/`Infinity`, overflowing numbers and a byte-order mark make
  the manifest invalid JSON; a missing or non-string layer `type` or overlay `kind` is an error.
- Unknown layer types and overlay kinds are skipped with a warning, never rejected (Python used to
  reject unknown overlay kinds); overlays with malformed presentation members are skipped with a warning
  everywhere (*new* in Python and the desktop). Decoders return warnings separately from errors.
- §5: `color.by` defaults to `solid` when absent (Python used to reject a missing `by`); non-integer
  label values are grey everywhere (Python's `stk:categorical` used to truncate them).
- §6.3: polyline cell attributes are per segment only (the web accepted one value per polyline).
- §6.5: the sphere glyph has max(3, ⌊resolution / 2⌋ + 1) latitude rows (the web used
  max(4, resolution)); instances with a non-finite scale are not drawn (the web drew them); `factor`
  defaults to 1.
- §6.6: a degenerate transfer-function range (hi ≤ lo) is one colour, LUT entry 128 (the offscreen
  renderer spread the LUT over [lo, lo + 1]); categorical volume colours are quantized to RGBA8
  everywhere; of duplicate opacity values the last point wins (`colormaps.opacity_at` used to sort by
  alpha).
- §6.7: labels follow Python format semantics in every client (round half to even, `d` rounds ties to
  even, no `-0`; the web used `toFixed`/`Math.round` and a smaller grammar); the desktop has one
  `format_label` instead of a Python and a web variant.
- §2.1 (*new*): the camera rules of the interactive viewer (z-up unless looking along z within 1e-6,
  explicit `view_up` honoured with presets, angles ≥ 180° replaced by 30) now also drive the offscreen
  renderer.
- §9: the length field must equal the file size exactly (the web accepted trailing bytes).
