# 在 STK 中运行完整 MuFerro 仿真

项目工作台提供原始案例导入、参数编辑、输入生成/冻结、运行提交、日志、结果收集与三维查看。
这些操作也可以通过桌面 Python 中的 `stk.muferro` 调用；项目内容保存在 SQLite 和项目文件目录中，
关闭 Python 会话不会丢失输入版本、运行方案或结果关联。
多行参数的准备、提交与失败恢复见[仿真批次指南](simulation-batches.md)。

## 准备条件

- macOS/Windows/Linux 桌面连接一台 Linux Runtime；在 **Jobs / 作业** 中保存并选择直连或
  [SSH 连接](ssh.md)。本流程首版暂不支持 Hub 准备阶段的审核暂停。
- 计算主机已安装 muFerro 并配置运行库和许可目录，见[MuPRO 配置指南](runtime-mupro.md)。
  客户端不需要安装求解器；STK 不读取或复制许可文件。服务器环境中的 SDK、许可及库配置由 worker 继承。
- 本机有干净的案例目录，包含 `input.toml`、材料 TOML、必要的 include 文件和可选的 `.in` 输入。
  首版只导入 `.toml`/`.in` 普通文件，最多 100 个文件、256 MiB；拒绝符号链接、许可目录和已有结果。
  案例的 `temperature`、`dt` 必须明确给出且为正数；其余检查复用 MuFerro 适配器。

## 原生界面流程

1. 从文件菜单打开**项目表格**，新建或打开项目；旧项目先按提示备份并升级至格式 5。
2. 展开 **MuFerro 仿真**，填写（或“浏览…”选择）原始案例目录，点击**导入并冻结案例**。源目录保持原样，
   工作副本保存在 `inputs/muferro/<案例 ID>/`，原始字节保存到项目的不可变输入对象中。
3. 在下方表格选择 **MuFerro cases / 仿真参数**，选择刚导入的一行。使用现有单元格编辑器修改温度、
   步数、时间步长和输出间隔；这些字段同样支持项目公式。尝试次数默认为 1。
   原始输入版本字段是内部关联，通常无需手工修改；修改其他原生参数时，在 VSCode 编辑案例并重新导入。
4. 在面板的**运行环境**下拉框选择 Runtime（或点**管理…**到 Jobs 添加），检查运行方式与资源，点击**准备选中案例**。
   默认在 Runtime 主机直接运行单 rank（`{"backend":"local","ranks":1,"threads_per_rank":1}`）。
   集群登录节点应选择 Slurm/PBS 集群作业并填写时限（分钟），不能直接运行；其他选项在**高级执行选项（JSON）**中填写。
   多行一起运行见[仿真批次](simulation-batches.md)的“运行所选行”。
   选项是 `muferro_spec` 的资源/节点环境参数，路径指向计算主机；输入位置和工作区由流程管理。
5. 展开**运行记录**，加载并选择新方案，检查冻结参数、命令、输入哈希，然后点击**提交运行**。
   准备和参数编辑不启动求解器。通过**刷新状态**跟踪进度，或明确取消；
   MuFerro 面板的**显示日志**展示选中任务 stdout/stderr 的前 64 KiB，完整日志在 Jobs 中查看。
6. 状态成功后，点击 **MuFerro 仿真 → 收集并校验**。下载到 `results/muferro/<运行 ID>/`，
   比对远端文件 SHA-256、冻结输入哈希、原生完成记录、进度、能量和帧头；
   **MuFerro results / 仿真结果**记录运行/任务 ID、温度、最终步、归一化总能量、程序哈希和文件。
7. 点击**查看已收集结果**，在原生 Viewer 打开铁电畴预设。显示的是最近已输出的极化帧；
   例如 101 步、输出间隔 100 时，能量最终步为 101，极化场最新帧为 100，二者不混为同一步。

查看器使用科学/VTK 依赖，快速启动脚本安装相应环境。若首次打开提示预设仍在加载，等待加载完成后再次点击。
这里的铁电畴显示方向分类，不代表标量能量大小；数值比较使用结果表或相应分析预设。

## 重复操作、恢复与重算

- 相同案例行、参数定义、资源选项和连接重复准备时，复用已有方案；准备响应丢失后可重新点击恢复其 ID。
  重复提交同一方案使用已有运行记录的幂等键，不创建第二个任务。
- 改变参数后准备会创建新方案；相同参数也需要重新计算时，先增加该行的**尝试次数**。
  旧方案和旧结果继续保留，参数状态显示为已变化。失败任务的重算同样创建独立尝试。
- 准备期间的并发参数修改或输入文件变化会拒绝保存不一致的方案，不会自动提交旧配置。
  已创建的工作区、文件和快照保留；外部操作不随表格撤销而回滚。
- 传输失败或中断时，在 Transfers 检查并明确恢复同一传输，再重新执行准备/收集。
  等待超时不表示服务器任务已停止；关闭桌面不会取消已提交计算。
- 重复收集不会增加任务或结果行；本地文件已被修改时拒绝覆盖或纳入结果。
  删除已完成下载的本地文件后，旧传输记录不会自动重新下载；在 Jobs 使用新的下载请求恢复到原位置，再收集。
- 关闭重开后，加载项目运行记录即可刷新、收集和查看；无需恢复旧 Python 变量。
  本机已收集的结果可离线查看；刷新、准备、提交和收集需要原连接。

结果收集默认最多 1 GiB、10000 个文件；Python 可显式调整 `max_bytes`。
运行时校验检查全部能量行、进度及必要场的帧头，不代表验证所有体素或物理模型正确性。
本轮真实案例另用独立数值读取器检查全部场值，并与固定案例的参考能量比较，见[验收记录](runtime-validation.md)。

## Python 操作

在桌面 Python 面板选择当前项目，分步执行：

```python
p = stk.project
case = stk.muferro.import_case(
    '/path/to/clean-case', expected_revision=p.snapshot()['project']['revision'])

# 可在表格中先修改参数。准备会上传冻结副本，但不提交任务。
run = stk.muferro.prepare(
    case['record_id'], 'runtime:lab',
    expected_revision=p.snapshot()['project']['revision'], launcher='none')

# 明确提交；之后可继续使用原生运行面板。
p.runs.submit(run['id'])
p.runs.refresh(run['id'])

# 任务成功后分别执行：
result = stk.muferro.collect(run['id'])
stk.muferro.view(run['id'])
```

工作区、任务、传输和 Viewer 使用既有共享 API；没有额外调度器或自动重试循环。
`project=` 可明确传入已打开的项目对象；未指定时使用本次脚本开始执行时选中的项目，切换界面不会重定向旧句柄。
