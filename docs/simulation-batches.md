# 参数表驱动的仿真批次

批次保存明确的案例行、当时的参数、连接、执行选项和模板版本。准备、提交、刷新、取消、收集是
独立动作；保存批次不会上传输入或启动任务。首个注册模板为 `muferro/1`，复用
[MuFerro 单次工作流](simulation-muferro.md)和已有 Runtime 调度器。

## 原生界面

1. 导入 MuFerro 案例，在项目表格中选择案例行。展开**仿真批次**，可点击**复制当前案例参数值**，
   再到表格中编辑新行的温度等参数。复制的是当前计算值，写为字面量；原始输入版本共用不可变副本，
   不复制公式或自动改变稳定引用。新行出现在表格末尾，选择后编辑。
2. 选择一个参数行，点击**加入当前行**；重复添加所需行，或点击**选择全部案例**。
   可移除当前行或清空选择；排序不改变加入的记录 ID。每批最多 100 行。
3. 在**运行环境**下拉框选择已保存的直连或 SSH Runtime（同时成为 Jobs 的当前连接；没有时点击**管理…**到 Jobs 添加），
   在**运行方式**、**MPI 进程数**、**每进程线程数**中设置资源；集群作业（Slurm/PBS）还需**时限（分钟）**。
   其他 `muferro_spec` 选项在折叠的**高级执行选项（JSON）**中填写，上方字段编辑的是同一个对象。
   - **在 … 上运行所选 N 行**：一次点击保存批次、准备全部行，并提交准备成功的行；准备失败的行不提交，
     错误留在成员表中。任务被接受后不等待完成，刷新与收集仍按下文步骤明确进行。
     对相同行与选项再次点击复用同一批次、方案与任务，不会重复提交。
   - **仅保存批次**：只冻结所选范围，之后按下列步骤逐步准备、检查和提交。
   在**已保存批次**中选择要操作的批次，查看冻结的案例、温度和连接。
4. 点击**准备全部**，生成、冻结并上传各行输入，保存独立运行方案。也可在批次成员表选择一行，
   只**准备选中行**。准备错误逐行保存，其他行继续；任务仍未提交。
5. 选中成员后，可在**仿真运行记录**检查其冻结参数、输入和命令；展开该面板查看详情。
   检查后明确点击**提交全部**或**提交选中行**。Runtime 按已有资源限制调度，批次本身不新增调度器。
6. 点击**刷新全部**或**刷新选中行**更新状态；状态是最近一次观察，不是持续轮询。
   成功后收集全部或指定行。部分未成功时，成功行仍收集，其他行显示错误。
   结果进入原有 MuFerro 结果表；选中成员的运行后，沿用 MuFerro 面板的日志和三维查看按钮。
7. 保存的批次及逐行操作结果在项目关闭重开后仍可见；未保存的行选择只属于当前界面。

批次执行使用其保存的连接和选项。之后改变运行环境、Jobs 当前连接或执行选项不会改变旧批次。
一次运行中，批次在点击时的修订上保存，准备在保存后的修订上进行，提交时每行仍按冻结的批次意图核对参数，
之后改动的参数被拒绝而不是被采用。
当前范围只支持本机桌面到 Linux Runtime 的直连/SSH；不支持 Hub 批次准备，也不提供任意代码模板。

## 部分失败、中断与重算

- 相同参数、模板、连接和选项保存同一组行时复用同一批次，选择顺序不影响身份。
  不同批次中相同案例配置也可复用原运行方案；批次不隐含“再跑一次”。
- 准备响应丢失、进度写入响应丢失或脚本中断后，重新打开同一批次，明确重做该操作即可恢复已有方案。
  重复提交复用每个运行的固定幂等键，不启动第二个任务。
- 保存批次后修改参数，尚未准备的行会拒绝采用新值。可恢复原值后再次准备，或为新参数保存新批次。
  已有运行继续保留冻结输入；首次提交旧参数仍由原运行记录的过期检查拒绝，不由批次隐式同意。
- 准备/传输失败：检查逐行错误和 Transfers，恢复传输后仅重新准备失败行。
  任务失败或被取消后需要重新计算：在案例表增加**尝试次数**，只选择需要重算的行，保存新批次并准备，
  最后明确提交。不会自动重算成功行，也不会覆盖旧结果。
- 脚本中断停止后续成员；已接受的服务器任务继续运行。通过批次取消或原运行面板明确取消任务。
- 最近操作结果使用普通项目表格保存，会推进项目修订并进入修改历史。撤销这些元数据不会撤销
  上传、提交、取消或下载；删除批次也不会取消服务器任务或删除不可变运行记录。
  如进度写入遇到修订冲突，批次停止，已保存的运行仍可在 Runs 中恢复。

## Python

```python
p = stk.project
stk.batches.templates()  # 内置 muferro/1，另加经 stk.engines 注册的引擎

batch = stk.batches.create(
    'muferro/1', [first_case_id, second_case_id], 'runtime:lab',
    options={'launcher': 'none', 'ranks': 1, 'threads_per_rank': 1},
    expected_revision=p.snapshot()['project']['revision'])

# 或一次完成保存、准备与提交（只提交准备成功的行）：
# stk.batches.run('muferro/1', rows, 'runtime:lab', options={...}, expected_revision=...)

# 每一步单独执行；inspect 只读本机保存的观察，不连接服务器。
stk.batches.inspect(batch['id'])
prepared = stk.batches.execute(
    batch['id'], 'prepare', expected_revision=p.snapshot()['project']['revision'])
print(prepared['ok'], prepared['items'])  # 检查每行，批次脚本结束不代表全部成功。

submitted = stk.batches.execute(
    batch['id'], 'submit', expected_revision=p.snapshot()['project']['revision'])

# 只操作指定成员；也支持 refresh、cancel、collect。
result = stk.batches.execute(
    batch['id'], 'refresh', record_ids=[first_case_id],
    expected_revision=p.snapshot()['project']['revision'])
```

各 API 均可显式传入 `project=`。未指定时使用脚本开始时绑定的项目，切换界面不会重定向执行。
批次意图最多 1 MiB，以内容确定稳定 ID；直接编辑内部冻结范围会被拒绝，应从期望的参数行创建新批次。
内置模板注册与批次协调在 `suan/workflows/`，项目数据只引用已注册版本，不能通过字符串加载任意 Python 模块。
完整可视化模板编辑、批量参数生成器和 AI 对话入口仍是后续开发。
