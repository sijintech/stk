# 冻结输入的本机 LaTeX 工作流

`latex-compile/1` 将外部 LaTeX 编译作为项目工作流中的明确运行步骤。它不属于 Viewer 的自动求值图；
刷新、打开项目、恢复工作空间、查看编译记录及日志均不启动编译。当前实现和验收状态见
[开发计划](development-plan.md)与[运行验收](runtime-validation.md)，不能把受控编译器夹具当作真实 TeX 安装验收。

## 准备输入与编译器

1. 将源文件登记到 Files，并捕获 Snapshot。文件名需要在所绑定文件集合中唯一。
2. 在项目工作流中加入参数表、Files/Snapshot 和本机 `latex-compile/1` 步骤；
   将参数表的 `rows` 和文件步骤的 `files` 分别接入编译步骤的同名必需端口。
3. 明确填写编译器的绝对路径、引擎和文件选择，再保存工作流。编译器需要已安装的 TeX Live 或 MiKTeX；
   STK 不在读取或准备时安装编译器、字体或在线 TeX 包。缺少路径时应先安装并选择本机工具链。
4. 勾选参数行，明确点击运行。准备阶段只核对元数据和编译器文件摘要；版本探测与编译发生在启动之后。

参数：

| 参数 | 含义 |
|---|---|
| `compiler_path` | 已安装的 `pdflatex` 或 `xelatex` 可执行文件绝对路径 |
| `engine` | `pdflatex`（默认）或 `xelatex` |
| `entry_path` | 主源文件的虚拟路径，默认 `main.tex`，必须在已选文件中 |
| `assets` | 显式选择数组，每项为 `{"source":"上游文件名","path":"编译目录内相对路径"}` |
| `timeout_seconds` | 1–300 秒，默认 60；覆盖版本探测及一次编译 |

例如，`assets` 可填写：

```json
[
  {"source": "main.tex", "path": "main.tex"},
  {"source": "methods.tex", "path": "chapters/methods.tex"},
  {"source": "plot.png", "path": "figures/plot.png"}
]
```

输入最多 60 个文件，每个 4 MiB、合计 24 MiB；支持 `.tex`、`.bib`、`.bst`、`.sty`、`.cls`、
`.png`、`.jpg`、`.jpeg`、`.pdf`。虚拟路径须保持原文件后缀、可移植且不相互覆盖，不能使用保留的 `_stk` 名称。
编译器及输入一经准备即冻结：之后修改工作副本或工作流不会替换这次运行的源版本。
若输入来自前序模拟步骤，执行时只消费该步骤已经成功捕获的 Snapshot，不读取它的活动工作目录。

## 查看结果与失败

在运行详情中选择参数行，点击对应步骤的“查看编译记录”。可以查看失败、取消和先前尝试，
明确读取编译输出、错误或 TeX 日志的下一页。查看与刷新记录均不会重试。
日志返回的是有界字节页；桌面连续解码 UTF-8，避免中文跨页时被截断。

选择一条诊断后，明确点击“在 VS Code 打开选中位置”。STK 只将日志定位到本次已经选择的输入，
并核对当前登记文件的实际摘要。源文件已修改、删除或项目修订不符时，拒绝用旧错误定位当前文件。
VS Code 缺失或系统未注册 `vscode://` 处理时会保留编译记录并显示错误；可安装并启用后重试打开。
切换项目、工作流、运行或选中行会使先前在途的定位请求失效。

每次明确重试使用新的尝试编号和目录，不覆盖旧回执。原执行者仍活着、证据损坏或无法确认旧执行状态时，
不能借重试启动另一份编译。恢复只标记已失去执行者的尝试，不重新运行编译器。

编译使用固定无 shell-escape、非交互、首错停止、文件行号及专用输出目录参数；MiKTeX 另禁用自动安装器。
当前是一次引擎执行，尚无自动 BibTeX/Biber、索引生成或多遍交叉引用收敛链；需要这些步骤的文档不能据一次成功
声称参考文献及引用已经收敛。TeX 是用户明确选择的本机程序，这些参数不等同于操作系统沙箱。
保留文件预算不代表临时磁盘或编译进程内存的全局上限。

## 保存 PDF 报告与重新打开

成功后，`report.pdf`、`stdout.txt`、`stderr.txt` 和 `compiler.txt` 登记为 Files，并捕获为任务的输出 Snapshot。
原输入 Snapshot、冻结编译器和日志诊断身份保留在编译回执中，原输入副本也保留在该尝试目录。
PDF 最多 4 MiB；PDF 头检查只用于文件接纳，不代替 PDF 解码或实际页面呈现验收。

在 Reports 中明确创建报告，选择该任务的输出 Snapshot，以 `report.pdf` 为入口并勾选所需日志附件；
将工作流运行列为来源。保存后再明确预览或导出。导出的普通报告包含本次勾选的冻结资产，
不会自动包含整套 TeX 工具链或未选中的输入源文件。要保留整个可复核项目，使用项目归档并保留原输入 Snapshot
和编译记录；改变工具链后重新编译属于新运行。

`.tex` 和 `.log` 作为报告附件时只保存 UTF-8 原文，不执行编译或解释日志。重新打开已保存 PDF 报告也不会调用编译器。
原生 PDF 预览仍受当前平台能力与验收状态约束；Linux 的原生文档预览为 Unsupported。

脚本只读入口为 `stk.project.workflow_runs.compilation(...)`、`compilation_log(...)` 和
`compilation_source(...)`；调用者必须指定原运行、步骤、行和尝试号。它们不接受任意宿主目录或 PID，
`compilation_source` 只返回核验位置，不替脚本打开外部编辑器。详细结构见
[桌面桥规范](specs/stk-desktop-bridge-v1.md)。
