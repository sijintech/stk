# 项目上下文与讨论记录

格式 7 为项目增加显式选择的上下文快照、文字讨论及草案来源关联。它们保存在项目 SQLite 中，
不需要模型服务或 Runtime。记录问题、引用数据、保存修改草案和应用修改是不同操作；
消息中的普通文字、Markdown、代码块或“已批准”等表述都不会执行代码、修改参数或提交计算。

已有项目需先按[项目指南](project.md#数据库备份与显式升级)备份并升级。普通打开不迁移，
格式 6 的[修改草案](project-drafts.md)仍可使用原有接口。新建项目使用格式 7。

## 在原生界面中使用

更新源码并运行[快速启动脚本](../desktop/QUICKSTART.md)后，打开“项目表格”编辑器，选择 **讨论** 页签：

1. 展开 **捕获选定上下文**，填写名称。可以先在 **表格** 页选中一行，再点击
   **使用当前数据行及其全部字段**；也可以在讨论页选择表格，通过行、字段下拉框和
   **添加 / 移除行**、**添加 / 移除字段** 明确组合范围。选择全部行/字段仍受上限约束。
2. 核对行数、字段数和单元格数，必要时展开 **检查选定 ID**，再点击 **在当前修订捕获**。
   在 **捕获单元格** 表中查看记录、字段/单位、保存的值和状态；选中一行，展开 **选中的捕获单元格**
   检查原始内容。**捕获数据与诊断** 仍提供完整捕获 JSON。页面会标明缺失、省略和项目已变化的情况，
   捕获本身不更改参数。
3. 在 **填写消息** 中输入问题或说明，再点击 **保存消息**。消息引用页面当前显示的上下文。
   消息与代码块以普通文字保存和显示；这里没有 Markdown 渲染，也不会运行代码。
4. 如需提出修改，到 **修改检查** 页计算预览并保存草案。回到 **讨论 → 消息**，选中消息并点击
   **查看选定记录**，核对文字及上下文 ID，再点击 **关联当前已保存草案**。
   草案基础修订必须与消息所引用上下文的来源修订一致，关联不应用修改。
5. 在 **提案** 列表选中关联并点击 **载入草案以检查**，进入已有的修改检查流程。
   若检查页已有另一份草案，先核对并清除编辑区草案，再载入；当前已经载入同一草案时直接切换过去。
   检查页显示来源消息和上下文 ID，可用 **刷新草案来源** 重试查询或查看后来添加的关联。
   仍需明确预览并应用，过期草案按[草案恢复规则](project-drafts.md)另起新草案。

**上下文 / 消息 / 提案** 各自分页，每页最多 100 项，使用 **刷新列表** 与前后页按钮读取保存记录。
选中列表项不等于载入详情；点击 **查看选定记录** 才读取完整上下文或消息。
查看已载入消息时，**查看消息上下文** 可切换到这条消息实际引用的上下文。

**捕获单元格** 是只读的展开表，每一行对应一个“记录 UUID + 字段 UUID”。值列提供简短单行摘要，
详细区保留该单元格的身份、字面量、公式/引用定义及求值部分，避免把摘要当作完整内容。
状态区分字面量、显式 `null`、未设置、计算值、公式错误、求值不可用、已省略及表格/记录/字段缺失。
若捕获时省略了整个内容，页面显示省略说明，不用当前项目的数据补出单元格。

这张表只展示所载入的捕获版本。实时值、字段名称、表格筛选甚至来源对象删除，都不会改变已保存的内容；
它也不会重新计算公式。项目 **表格** 页的搜索筛选不缩小上下文捕获范围，捕获仍使用明确选择的行和字段。
本次视图改进沿用格式 7 与现有上下文 API，不增加迁移或执行操作。

重新打开项目不会自动载入上次查看的上下文或消息，也不恢复运行中的请求。进入讨论页会按需读取摘要列表，
再由用户选择详情；读取和恢复不捕获新数据、不应用草案。未点击保存的输入不属于持久记录。

## 明确捕获选中的数据

上下文固定项目 UUID、来源修订、标题、时间和所选表格、记录、字段的 UUID。
捕获保留所选字段的类型、单位、当时的字面量、公式/引用定义和已有求值缓存；未赋值与显式 `null` 保持区别。
以后更改名称、选择、值或删除来源对象都不会改写这份上下文。比较来源修订与当前项目修订可识别旧上下文，
需要新数据时明确捕获新对象。

首版只捕获指定的一张表及明确的行、列范围，不隐含选择整张表或完整项目。
引用/公式可以保留其他对象的 UUID，但不会递归附带来源表；文件索引行里的路径只是一项表格值，
不是文件内容副本。文件内容、运行日志、科学数组、连接凭据和模型请求均不自动附带。

在桌面 Python 面板中，先检查项目并明确选择范围：

```python
from uuid import uuid4

p = stk.project
snapshot = p.snapshot()
# 示例明确取第一张表的第一行、第一列；实际使用时替换为核对过的 UUID。
table = snapshot["tables"][0]
context_id = str(uuid4())  # 保留此 ID，用于查询和相同请求的显式重试。
context = p.contexts.capture(
    table["id"], [table["records"][0]["id"]], [table["fields"][0]["id"]],
    expected_revision=snapshot["project"]["revision"],
    title="讨论所用参数", context_id=context_id,
)
print(p.contexts.get(context_id))
print(p.contexts.list())
```

捕获不提升编辑修订，也不进入撤销栈。旧修订或非法范围会拒绝请求。已删除或找不到的表、记录、字段
仍保留在选择范围中，并通过 `diagnostics` 标明缺失；对象若实际属于另一张表则拒绝，不能改选其他对象。
上下文读取返回保存时的内容，不能把读取当作刷新当前数据。

每次明确选择 1–100 个不同记录和 1–64 个不同字段，行列乘积不超过 1000。
每项字面量、定义或求值缓存上限为 16 KiB；超限时保留 `omitted` 状态、`value_limit` 原因、大小和 SHA-256，
不写入该值。缺失或损坏的求值缓存标为 `evaluation_unavailable`，不会遍历未选中的依赖去重新计算。
完整上下文总量超过 256 KiB 时，整个内容标为 `context_limit`，仍保存选择、诊断及内容大小/校验和。
`omitted_values` 统计逐项省略的数量；整个内容是否省略还须检查 `content.state`，即使计数为零也可能是
`context_limit`。不能把省略记录视作完整数据快照。列表省略 `content.value`，使用 `get` 查看保存的详情。

`content.size_bytes` / `content.sha256` 描述逐项省略处理后内容的规范 JSON；逐项省略标记里的
大小和校验和描述该项原存储 JSON 的 UTF-8 字节。缺失缓存使用空字节的大小和校验和。
这些标记用于识别省略内容，不能凭校验和恢复其值。

### 从原生共享选择明确捕获

桌面 Python 可使用 `p.selection()` 取得当前已载入的表格、记录 UUID 和修订，或先通过
`p.select(...)` 明确选择一行。选择不会自动捕获上下文；字段范围仍由调用者提供。
下面选取快照中核对过的一行和一个字段，再单独保存上下文：

```python
from uuid import uuid4

p = stk.project
snapshot = p.snapshot()
table = snapshot["tables"][0]
record_id = table["records"][0]["id"]
field_ids = [table["fields"][0]["id"]]  # 明确选择字段，不读取区域内的字段焦点。
p.select(table["id"], record_id, expected_revision=snapshot["project"]["revision"])
selection = p.selection()
if (selection["table_id"] != table["id"] or selection["record_id"] != record_id
        or selection["revision"] != snapshot["project"]["revision"]):
    raise RuntimeError("选择或项目已变化，请重新核对")
context_id = str(uuid4())
context = p.contexts.capture(
    selection["table_id"], [selection["record_id"]], field_ids,
    expected_revision=selection["revision"], title="选中行的讨论依据", context_id=context_id,
)
```

共享选择可能被某个区域的筛选隐藏，查询不会返回该区域可见行集合，也不会调整筛选。
没有选中表格或记录时，`selection` 中相应 ID 为 `None`，应先明确选择。
选择接口只针对桌面已载入的项目，不打开项目或切换页签；写入选择会保护正在输入的文字，
具体前提见[Python 指南](scripting.md#查询和改变原生共享选择)。外部修改即使尚未显示在桌面，
捕获仍在数据库中校验 `expected_revision`，不会把过期选择静默当作新修订。

## 记录文字与草案来源

```python
message_id = str(uuid4())
message = p.discussion.add(
    "请检查这组参数；这里记录讨论，不执行修改。",
    message_id=message_id, context_id=context_id, role="user",
)
print(p.discussion.get(message_id))
print(p.discussion.list())
```

角色只接受 `user` 或 `assistant`，仅描述文字的来源类别，不代表模型调用、身份认证或审批。
每条消息必须引用已保存上下文，非空文字最多 64 KiB UTF-8。消息保存后不可覆盖；
新问题或更正使用新的消息 ID。关闭重开可查询原消息及其上下文，恢复不会运行消息中的任何内容。

已经明确保存的修改草案可以关联到消息：

```python
draft_id = str(uuid4())
draft = p.drafts.save(
    [{"op": "create_table", "name": "讨论后的参数表"}],
    expected_revision=context["source_revision"],
    title="待检查的方案", draft_id=draft_id,
)
proposal_id = str(uuid4())
proposal = p.discussion.link_draft(message_id, draft_id, proposal_id=proposal_id)
print(p.discussion.proposals())
print(p.discussion.proposals(draft_id=draft_id))  # 按草案查唯一来源关联。
# 关联只记录来源。随后仍需载入草案、查看差异，再明确应用。
```

上下文与草案必须属于同一项目，并且上下文来源修订等于草案基础修订；每份草案最多关联一条消息来源。
项目已经变化时，
不要仅替换修订号重试保存；先捕获和检查新上下文，再创建对应草案。关联记录不会更改草案状态，
也不会把上下文的选择范围当作草案的授权范围；修改仍由普通命令校验与显式应用入口控制。

## 重试、恢复与边界

调用者为上下文、消息和来源关联分别提供规范 UUID，并保留原请求。相同 ID 与相同请求的重试
返回原记录；用同一个 ID 改内容会冲突。响应不确定时先按 ID 查询，不能另生成 ID 后重复创建。
列表支持 `offset` / `limit` 分页，默认每页 100 项；按 `next_offset` 继续查询，直到返回 `null`。

上下文、消息和关联独立于表格撤销历史；撤销表格不会删除它们，也不会重置草案应用回执。
关闭项目、重启桌面桥或重新打开数据库只恢复记录，不自动捕获、生成、应用、运行脚本或提交任务。
这些记录包含在数据库备份中；外部文件仍遵守[数据库备份边界](project.md#数据库备份与显式升级)。

本轮为不依赖模型的可追溯基础。模型提供方、密钥、流式回复、工具调用、消息搜索、内容压缩、
文件附件、完整 AI 主页面及多设备会话同步仍待后续实施。
