## 更新并启动

在仓库根目录执行 `git pull --ff-only`，然后运行对应的[快速启动脚本](../desktop/QUICKSTART.md)。
本次需要增量编译，不使用 `--launch-only`；已装依赖和编译缓存会复用。

```bash
# macOS
bash desktop/setup-macos.sh --demo
```

```powershell
# Windows
powershell -NoProfile -ExecutionPolicy Bypass -File desktop/setup-windows.ps1 --demo
```

选择 **文件 → Python → 运行 Python 文件**，填入仓库中 `examples/project_scan/offline.py` 的绝对路径，
明确点击“运行文件”。脚本创建新的本机项目，显示项目表格、Viewer 和 Python 三个区域。
无需服务器；输出是合成测试场。目录和布局恢复步骤见[离线演示](../examples/project_scan/OFFLINE.md)。

新建演示项目使用格式 8。测试已有旧项目时，普通打开不会迁移：草案保存最低需要格式 6，
讨论需要格式 7，请求记录需要格式 8。请明确点击 **备份并升级项目**；它先创建并校验数据库备份，再升级。
外部文件需另行备份，范围见[备份与升级指南](project.md#数据库备份与显式升级)。

应显示受影响记录；搜索错误信息可进一步缩小范围。检查后撤销该编辑。公式操作见[项目指南](project.md)。

在 Python 面板先执行 `p = stk.project`、`print(p.selection())`，再按
[共享选择示例](scripting.md#查询和改变原生共享选择)用快照中的明确 UUID 和当前修订调用
`p.select(table_id, record_id, expected_revision=...)`。分别选择同表另一行、另一张表的一行：
两个区域的共享选择应更新，筛选条件、区域类型、页签和已有修改检查草案保留，项目修订不增加。
被筛选隐藏的目标仍可由 `p.selection()` 读到，不会隐式打开或切换项目。
在一次普通数据修改后用旧修订再次选择，应报告 `conflict` 并保留原选择；重新核对后再操作。

只读查询可在其他区域仍有文字输入时执行；写入选择遇到任意窗口的活动文字输入应返回 `busy`，
保留输入。切到 Python 时通常会结束原编辑，因此只有确实仍在输入的情况下才按此项判断。
关闭重开项目后应重新取得 `p = stk.project`；区域筛选不会跨重开恢复。

## 保存草案、重开与重新检查

这组步骤测试持久草案，详细规则见[草案指南](project-drafts.md)和[预览指南](project-preview.md)。
先清除筛选，记录 Controls 的 Offset 当前值和项目修订，输入一个不同的有效值。

1. 点击 **检查此单元格修改**，在 **修改检查** 查看 Offset 与派生值差异、完整定义及
   **公式错误**。此时实际表格和修订不变；错误列表也包含未变化的原有错误。
2. 展开 **已保存草案**，填写名称并点击 **保存已检查草案**。列表显示基础修订与 **待处理**，
   保存不会应用参数。先 **清除草案** 再 **刷新保存列表**，原保存记录仍应存在。
3. 关闭并重新打开项目，进入修改检查页。草案不会自动载入或应用；展开保存列表，选中记录并点击
   **载入待处理草案**。如果编辑区已有内容，先核对再明确清除，不能被新载入覆盖。
4. 点击 **计算预览**，重新核对差异后才点击 **应用已检查的修改**。数据一起更新，草案显示
   **已应用** 与应用修订；一次撤销应恢复数据，但草案仍为已应用，不会再次执行。

可选过期场景：另存一份待处理草案，然后修改项目中的数据。载入旧草案后应禁止直接预览和应用；
明确点击 **以当前修订另起草案并检查**，核对新候选，原保存记录保留。
编辑载入命令的文本也会形成未保存副本，不覆盖原记录。不需要的待处理记录可 **标记为已丢弃**，
应保留终态记录且不能再应用。结束后清除当前编辑区，方便下一组检查。

## 讨论、冻结数据与草案来源

这组检查不需要模型服务；**讨论** 保存人工输入的文字，只有后面的 **请求** 流程会明确发送给模型。
完整步骤与捕获上限见[上下文指南](project-contexts.md)。先清除筛选，并在 Cases 选中一行。

1. 切到 **讨论**，展开 **捕获选定上下文**，填写名称，点击 **使用当前数据行及其全部字段**。
   核对行/字段数及 **检查选定 ID**，再点 **在当前修订捕获**。搜索结果不会自动成为捕获范围。
2. 在 **捕获单元格** 中检查字面量、派生计算值、字段/单位与状态；选中单元格并展开
   **选中的捕获单元格** 查看完整保存内容。**捕获数据与诊断** 提供完整记录，捕获不改变项目修订。
3. 在 **填写消息** 输入说明及一段代码文字，点击 **保存消息**。在 **消息** 列表选择该项并
   **查看选定记录**，文字应原样保留；**查看消息上下文** 应回到相同上下文 ID，代码不会运行。

可选来源关联检查应在修改实际数据之前进行，以保持相同基础修订：

1. 到 **修改检查** 计算一份预览并保存草案，暂不应用。回到 **讨论 → 消息** 查看刚才的消息，
   核对上下文 ID，再点 **关联当前已保存草案**。关联只记录来源，参数及草案待处理状态不变。
2. 清除修改检查编辑区，再从 **讨论 → 提案** 选中关联并点 **载入草案以检查**。
   检查页应显示来源消息和上下文 ID；本项可保留草案待处理。若决定应用，仍须 **计算预览**、
   核对差异并明确应用，载入本身不执行命令。
   基础修订与上下文不同的草案应拒绝关联；不要只替换修订号重试。

随后修改 Cases 的实时值，再查看原上下文：**捕获单元格** 应保留捕获时的值及定义，并提示项目已变化。
可选地在测试项目删除来源字段，原捕获内容也应保留；完成后撤销删除。
若捕获本身包含缺失或省略，状态及详情应说明原因；省略整个内容时显示说明，不用实时数据补值。

关闭重开项目后，按需刷新 **上下文 / 消息 / 提案** 列表，明确查看详情或载入仍待处理的关联草案，
保存记录应仍可读取。程序不会自动恢复上次详情、捕获新数据、生成回复、应用草案或提交任务。
未点击保存的消息输入不属于持久记录；已过期草案按上一节另起草案并重新检查。

首版重点测试 41/41、Linux 完整回归 602/602 通过，均无跳过；`852b343` 的桌面及 Runtime CI 全部通过。

先在测试项目使用合成数据，不需要凭据即可完成准备、历史和取消检查：

1. 从项目页头或 **文件 → AI 工作区** 打开，确认原项目表格/Viewer 标签保留。
   在表格选中一条记录，再 **捕获选中记录**，核对全部字段、单位及捕获修订；改变实时值后捕获值仍不变。
2. 输入模型 ID 和问题，从空输入直接打字后点击一次 **准备问题（不发送）**，应保存完整文字、显示 **尚未发送**，
   不改参数、修订或历史。同次会话的当前相同输入重复准备应打开原记录；改变问题再准备产生新问题/请求。
   请求创建失败可能留下已保存消息，保持输入重试应复用消息身份；跨重启不要求继续原准备事务。
3. 在 **已保存问答** 之间切换，核对文字、来源和模型始终属于同一请求；刷新列表不发送。
   草稿输入不被历史覆盖。保持文字处于编辑中切换项目，再返回，原文字只属于原项目。
   同时打开两个 AI 区域，历史选项与所显示问答保持一致；未准备输入各区域独立。
4. 切换中英文、缩小窗口，核对长英文段落及中文单行回复完整换行、可滚动读取；窄窗口仍能展开数据与模型设置。
   没有凭据时发送不可用；取消待发送请求后，详情保持 **已取消**，不会多出回复。
5. 关闭重开项目，保存问答可重新读取且不自动发送。未准备输入仅存在于原编辑器内存，不要求跨程序重启恢复。

真实模型验收在确认套餐适用并按[请求指南](project-requests.md)配置凭据后单独进行：准备新问题并明确
**发送这条已保存的问题**，完整回复落库后应自行显示。运行中/不确定记录约每秒只读一次本地状态，
最多 90 秒；出错或到期显示暂停，**刷新回复** 可恢复本地观察，不能重发或自动核对遗留执行。
读取期间仍可请求取消；切换项目后旧回复不能写进新项目页面。重开后应能读到原请求与完整回复，
参数/修改历史不变。Linux 已有一次合成单元格真实账号链路通过，不能替代这里的原生双平台验收。
流式请求应先显示标为“临时回复（尚未保存）”的片段，完整成功后改为正式回复；取消后临时文字立即消失。
断流或桥退出后不应把半条回答显示成已保存的正式回复；其他桥/旧桥无片段时仍可查看正式状态。
当前不验收工具执行、自动仿真或默认 AI 主页切换，它们尚未实现。

## 请求记录与取消

本组首先验证不发送的本机行为。按[请求指南](project-requests.md)配置模型 ID 后，在 **讨论 → 请求**
点击 **准备请求（不发送）**，或用 Python 与明确保存的用户消息 UUID 创建请求意图，再刷新列表并查看。

1. 列表和详情均应显示 **尚未发送**，模型名与保存配置一致。创建不增加项目修订或修改历史。
2. **查看原消息** 应打开对应文字及上下文；**查看保存的回复** 不可用，因为尚未发送。没有本机凭据时
   **发送给模型** 不可用；即使通过 Python 调用 `start`，也应在预检失败后保持原待发送记录。
3. 回到请求，点击 **请求取消**，列表和详情应显示 **已取消**。重复取消或刷新不创建新消息。
4. 关闭重开项目，刷新请求列表后仍可查看取消记录；不会启动执行或改变表格参数。

在确认套餐允许本应用使用并配置自己的凭据后，可另外准备一条新请求，明确点击 **发送给模型**，
随后 **刷新请求记录**；完成后查看保存的回复，核对源上下文、参数修订和消息文本。关闭重开后回复应保留，
输入中的代码不执行。2026-09-30 已在 Linux 真实桥进程中，用 `qwen3.7-plus` 对人工单元格完成一次
发送、保存回复和 SQLite 重开验证；macOS/Windows 原生按钮的真实账户流程仍待真机验收，
不能由受控 HTTP 测试替代。取消不保证远端停止或不计费。
