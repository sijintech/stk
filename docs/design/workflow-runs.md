## 目标

P3 验收中的“一份流程应用于多行运行；参数变化后保留并标明旧结果，按范围重算”。用户选中参数表的若干行，
明确点击运行：每行按工作流的步骤顺序执行，结果按行保存；之后修改参数、分析或工作流，旧结果保留并标为过期，
可只重算过期的行。整个过程不调用模型，不在打开或刷新时自动运行。

## 现有基础

- 分析运行（格式 9）：冻结完整分析、输入快照与文件映射，本机执行，单次尝试、不可变（[说明](../project-analysis-runs.md)）。
- 仿真批次：`muferro/1` 模板在 Runtime 上运行，准备、提交、刷新、收集各自明确（[说明](../simulation-batches.md)）。
- 文件索引与输入快照：内容按 SHA-256 冻结；仿真输出须先登记并捕获才能作分析输入。
- 示例项目的合成求解器 `synthetic_field()`：本机几毫秒写出 `field.vtk` 与 `metrics.json`。

## 决定一：工作流运行记录（项目格式 10）

新增两张只追加的表，与分析运行一样不提升编辑修订、不进入撤销栈：

- `workflow_run_plans`：一次运行的冻结计划——工作流 UUID、名称、规范文档及其 SHA-256、来源修订、所选行 ID、
  每行用到的参数值（`$field` 绑定和模板参数的当时取值）、每个被引用分析的完整文档与内容哈希、模板 ID/版本、输出目录。
- `workflow_run_events`：按（步骤、行）记录每次**尝试**：尝试序号、状态（等待、运行、成功、失败、取消）、
  所产生对象的 ID（分析运行 ID、输入快照 ID、输出文件记录）与错误；事件链带哈希，像分析运行事件一样防篡改。

旧项目通过已有“备份并升级项目”显式升级到格式 10；打开旧项目不自动迁移。

## 决定二：步骤 × 行是任务，每次执行是一次尝试

（ADE 做法 1，来自 Orca 的 task/dispatch。）

- 每个（步骤、行）在一次运行中是一个任务；每次执行是编号尝试，绑定**同一份冻结输入**，不重新读取当前定义。
- 只接受当前尝试的结果：完成记录必须带尝试序号，迟到的旧尝试不能覆盖新尝试。
- **重试**：对失败或取消的任务在同一运行中开始新尝试；成功的任务不重做。
- 依赖：一行内按工作流的数据流与 `after` 顺序；某行某步失败只阻塞该行后续步骤，其他行继续。

## 决定三：首版执行的步骤种类

| 种类 | 运行中的行为 |
|---|---|
| `table` | 提供所选行与各行字段值（冻结在计划中） |
| `simulation` + `demo-synthetic/1` | 新注册的本机模板：按行的温度参数写出 `field.vtk`、`metrics.json`，**不经 Runtime**，明确标注“合成数据，不是物理模拟” |
| `simulation` + `muferro/1` | **首版不在工作流运行中执行**（需要 Runtime，长时间运行）：准备运行时拒绝并说明“该模板的按行运行尚未支持”（校验不报问题，只查看的工作流不受影响）；继续用仿真批次面板 |
| `files` | 所选快照的全部文件供各行共用 |
| `analysis` | 每行准备并执行一次分析运行（复用格式 9 的冻结与本机执行），图参数按行取值 |

- **仿真输出成为分析输入**：由用户明确启动的运行在每行仿真完成后，只登记模板声明的输出文件并捕获为该行的输入快照，
  再交给下游分析；不扫描目录、不猜测文件。
- **按行参数**：分析运行的准备增加可选的参数覆盖值，冻结在分析计划中；旧计划没有该项，含义不变。
- **模板参数**：`demo-synthetic/1` 声明参数 `temperature`（K），仿真步骤用 `{"$field": 温度字段}` 绑定；
  校验沿用类型与单位检查。该模板接受任意参数表的行（`muferro/1` 仍只接受自己的案例表）。
- 输出位置：`results/workflow-runs/<运行 ID>/<行号>/<步骤 ID>/`，运行记录保存相对路径与哈希。

## 决定四：提交不阻塞、阶段可见、说明快照

（ADE 做法 3 与 14。）

- 工作流编辑器新增“运行”区：选择参数表的行（全部或表格中的选择），说明
  “运行使用点击时冻结的工作流、分析与各行参数，之后的编辑不影响这次运行”，点击 **运行所选 N 行** 后立即返回。
- 每行 × 步骤显示阶段：等待 → 运行 → 登记输出 → 完成，失败显示原因与 **重试**；运行中可 **取消**（已完成的保留）。
- 运行期间的修改照常进行；运行看到的始终是冻结计划。完成的分析结果可在分析图“运行”页打开或在查看器显示。

## 决定五：过期与按范围重算（W4c）

- 每行每步与当前定义比较：工作流中该步骤及其上游的规范 JSON、被引用分析的内容哈希、该行用到的字段值、模板版本。
  任一不同即标为**过期**，并说明原因（例如“温度从 325 K 改为 330 K”“分析已修改”）。旧结果保留、可查看。
- **重算过期的行**创建一次新的运行（新计划，只含这些行）；不修改旧运行，不自动重算。
