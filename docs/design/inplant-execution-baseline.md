## 节点 2 拟实施的部署约束

1. **拒绝优先**：使用企业批准、可核对版本的部署策略，登记实际设备/服务、调用者、用途与资源范围。
   未登记目标、未知适配器、失效授权、地址/服务身份变化或缺少必要条件时，在派发前拒绝并留下厂内诊断。
   网络准入覆盖应用调用、子进程、插件及部署出口；单靠 location 字段或环境变量白名单不足以验收。
2. **问题链完整留厂内**：用户问题、聊天、记忆、上下文、附件和派生查询继承同一边界，公开标注也不豁免。
   OCR、检索、embedding、重排、语言/材料模型、工具、日志和备份均遵守；厂内服务不可用时不能回退至厂外。
3. **桌面也遵守策略**：手工添加端点、选择 Runtime、安装模块或导出资源不得绕过已生效部署约束。
   修改由企业授权入口实施；资料、模型回复、脚本和代理不能更改策略；本节点不借机放宽 S2 或启用自主训练。
4. **离线依赖先准备**：按批准清单准备 STK、模型运行时/权重、Python 包、求解器、力场及必要许可与版本摘要。
   先用合成项目在无外网的新设备验证安装、启动、计算与恢复；当前在线下载器不直接充当离线安装方案。
5. **公共资料受控进入**：外部环境独立研究公共主题，审核资料包的来源、许可、版本、摘要、条件和质量后导入厂内。
   不把内部问题改写成公开查询外发；包中文字仅作为数据，不执行嵌入脚本或改变权限。

## 可观测验收与留证

使用明确合成的内容与本机测试服务，先形成调用者→输入/派生内容→目标→资源/日志→出口的完整清单。
至少覆盖公开/私有/结构标注、自由问题、会话记忆、planner、子请求、附件解析、工具参数和派生查询。
负向夹具包含“公开表 + 厂内自由问题”、未登记/变更目标、厂内模型失效后尝试外部回退、取消/重启和授权撤销。
逐项检查应用派发记录与部署出口观测：拒绝发生在发送前，故障期间没有厂外 DNS/连接/上传或外部备份回退。
同时核对子进程、插件、安装器、日志/诊断、缓存与备份；仅查看 gateway 日志或一次离线成功不足以证明边界完整。
保存策略/依赖版本、观察范围、允许与拒绝结果、故障证据和剩余未审定路径；缺项明确记录为未通过或未审定。
验收通过后才接入企业内部资料与聊天；材料质量、PET 物性及智能体训练授权仍按各自后续节点验收。
