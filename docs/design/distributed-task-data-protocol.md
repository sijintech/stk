## 1. 契约基线与改动边界

已发布契约继续有效；以下新增对象和字段只是建议，不得直接作为旧请求的额外键发送。

| 当前事实与证据 | 本草案的承接方式 |
|---|---|
| [Runtime HTTP API v1](../runtime.md#http-api-v1-与代码入口)，`suan/runtime/{models,store,service,supervisor,worker}.py`：持久 TaskSpec、任务、输入副本、取消意图和退出核实 | Runtime task 保持执行事实身份，不由 Web 或项目数据库另建一份可调度事实 |
| [Hub](../hub.md)：配对、复核、持久 action、出站节点连接；`suan/control/store.py:create_action/complete`，`agent.py:execute/dispatch` | action 表示投递与处理操作的事实；action 成功不等于其启动的任务成功 |
| [项目运行记录](../project-runs.md)，`suan/project/runs.py`、`suan/desktop_bridge/project_runs.py`：冻结方案、固定提交键、追加观察 | 项目运行记录保存科研来源与远端引用，不接管远端调度；已有 accepted task ID 不可替换 |
| [输入快照](../project-snapshots.md)、[项目模型](project-model.md)：项目稳定 ID、编辑修订、不可变清单与内容对象 | 大文件保留为资源；项目编辑事务、执行观察和传输进度保持独立 |
| [desktop bridge v1](../specs/stk-desktop-bridge-v1.md) §§3、7、9、12、14：私有 stdio、显式操作、可恢复传输、能力发现、本机会话 | 复用业务应用服务；不把私有方法全集或 `hello` 直接暴露成网络服务 |
| [monitoring events v1](../specs/stk-events-v1.md)、[统一数据格式](../specs/stk-data-format-v1.md#11-result-manifest-stkresult1) | 保留原事件、结果和科研状态语义；控制消息另行版本化 |
| [peer v1](../specs/stk-peer-1.md)：独立、有界、显式授权的原型协议 | 不将其本地原型证据称作已交付跨平台执行、传输或远程桌面 |

当前 Runtime、Hub 和节点代理仍是 Linux 服务，Runtime 是个人可信程序环境，**不提供多租户程序隔离**。Windows/macOS 全功能执行节点、云账号关联、分布式 Lease、下述授权及数据对象均需后续实现与验收。已有 MPI/PBS/Slurm 能力不等于任意绑定电脑自动组成一个求解器集群。

## 2. 归属：一项任务只有一个调度权威

建议使用 `TaskRef = {authorityId, taskId}`。`authorityId` 是经过绑定验证的后端持久实例身份，不是连接别名、URL、端口或一次 WebSocket 连接 ID；同地址重建服务不能冒充原实例。服务恢复须连同任务记录、幂等记录和实例身份一起恢复；从备份分叉出可独立写入的实例须获得新身份。

- 本地独立使用时，本机共享后端是 authority，可以不依赖官方账号或云连接运行；云账号绑定使已获授权的远程入口能访问它，不把本地事实改成云端所有。
- 当前 Hub 路径中，Hub 负责 action，原 Runtime 负责 task；节点代理转交操作。Web 经 Hub 访问原 Runtime，不增加一个 Synthrix 调度器。
- 将来需要跨节点排队时，由同一后端应用服务为**尚未派发**的任务选择执行节点并保存授权；同一 Task 的调度权不能同时留给云端和节点端两个实例。执行节点只在授权范围内执行和报告。
- 本轮建议不支持运行中的 authority 自动迁移。断网时其他部署角色读取带时间的投影；不能把远端未决任务复制为本地新任务。离线创建的独立本地任务以后同步其引用与授权范围内的事实，不在云端重新创建执行。

项目编辑仍沿用一项目单写者与 `expected_revision` 规则。项目写权不等于任务调度权；撤销项目编辑不取消真实任务；任务观察不推进可编辑项目修订。SQLite/PostgreSQL 等适配器执行同一应用服务规则，不通过双写建立两套权威。

## 3. 建议领域对象

以下名称用于讨论及后续 schema 设计，没有新增现有 API 方法。

| 对象 | 最小建议内容及不变量 |
|---|---|
| `Task` | `TaskRef`、创建主体、冻结请求及摘要、输入清单引用、执行器版本、资源/放置要求、当前状态与版本；同一身份不得改写原请求 |
| `Attempt` | `attemptId`、`TaskRef`、确定节点身份、执行器/环境证据、原调度器作业 ID 或本机进程身份、启动与退出回执、当前授权 epoch；一次实际启动的证据不能移给另一节点 |
| `Lease` | authority、attempt、执行节点、单调递增 epoch、授权动作、有效期、续期与撤销记录；只是执行授权，**不是进程存活或停止证明** |
| `TaskEvent` | task/attempt、生产者身份与启动代次、生产者序号、事件类型/版本、受限负载、内容摘要、authority 接收游标；重复消息必须可核对和去重 |
| `CommandReceipt` | 原操作身份、主体/目标/请求指纹、接受或拒绝事实、固定结果引用；持久提交必须能恢复原回执 |

首次实现建议将现有 Runtime task 映射为一个 Task 和一个实际执行 Attempt，不向旧接口暗中引入自动重试。资源暂时耗尽、尚未执行用户程序的启动等待可按现有门禁处理；已经可能执行用户程序的尝试不能因此视作“从未执行”。明确重新运行继续创建新方案、新提交键和新 Task，可额外记录 `retryOf`，不更换旧项目运行记录已接受的 task ID。多 Attempt 的自动重试策略留待单独版本化及执行器能力审查。

`Lease` 不能仅靠新增数据库时间列获得安全性。启用前必须同时具备节点执行门禁、持久日志、续期/撤销行为、过期处理及提交端 epoch 核对。当前的 Hub 连接替换、节点进程内 `_inflight` 去重、action 结果缓存与 Runtime 的 CAS 是可复用基础，并不等同于这些新保证。

## 4. 状态和证据分轴保存

任务执行沿用现有词汇：`preparing → queued → submitting → running → succeeded/failed/cancelled`，不确定时为 `unknown`；实际允许路径仍以现有状态机为准，不因本图新增跳转。`cancel_requested` 是独立的持久意图，`unknown` 不在现有 `TERMINAL` 集合中。

| 轴 | 应表达的事实 | 不得据此推导 |
|---|---|---|
| 执行状态 | worker/原生调度器核实的当前或最终任务事实 | 网络超时不能写为 failed；程序自报完成不能替代 Runtime 核实 |
| 观察状态 | 当前可达性、观察时间、来源与是否陈旧 | 节点离线不证明进程停止或结果丢失 |
| 取消 | 请求已持久接受、是否送达、节点是否确认停止或已自然结束 | 点击取消、HTTP 成功或桥超时不等于 cancelled |
| 租约 | 当前授权 epoch、期限、续期/撤销事实 | 过期或撤销不证明旧节点已执行停止动作 |
| 结果与科研评价 | 完整性、输入新旧、验证、既有四层科研状态分别保存 | 运行成功、字节校验成功、Agent 回复均不升级物理/计量/专家结论 |

现有 `stk.result/1` 的 `state`、`outcome`、`scientific_status`、`verification` 与 Runtime 状态不是同一个枚举，不做无损假定或名称替换。结果仍遵守 `fold(events) + files + verification`；unknown/pending/skipped 等原语义和四层结论均保留，本文不增加科学阈值、审批或自动归档规则。

## 5. 幂等、断网与恢复

建议命令流程是：校验当前身份与原目标访问权 → 严格解析已协商版本 → 在原 authority 查持久操作 → 核对当前回执读取权限后同指纹返回原结果、异指纹拒绝 → 新操作再执行当前业务授权、CAS、放置与资源检查 → 原子保存接受事实及待执行工作。读取旧回执不重新执行副作用，也不重新扣预算或要求再次审批；不因曾经获准就重新授予已撤销的执行权限。此流程需要映射现有每项操作，不能假定旧系统已拥有统一回执表。

**Synthrix 迁移差异。** 当前网页后端基线 `a15ab6b006ae348ef862b03773d6380b2e4abb3d` 的 `server/src/domain/pipeline.ts:447–453` 在 `claimIdempotency` 缓存命中时直接返回历史响应；该处仅传操作/用户作用域的键和 TTL，领域授权的 `decide` 在执行分支随后检查（约第 530 行）。因此“回执读取核当前权限”和持久完整请求指纹是需要明确迁移、分别验收的规则，不是现有管线已满足的事实；撤权后重放、TTL 到期后原操作恢复均须覆盖。当前网页工作树不能沿用历史 `90d7c4a` 可选 Hub slice 的接线结论，具体共同后端适配见[架构映射](shared-backend-architecture.md#4-直接证据与现有模块映射)。

旧记录缺失原请求、指纹或过期回执时，不得根据当前参数补造历史事实，也不能把缓存未命中解释为从未执行。
迁移应保留可证明的原身份与未决状态，限制为获准的只读核对；只有核实原执行并满足明确新操作条件后才可另建任务。
完整原请求重放只对已有充分证据或按新合同创建的记录成立，迁移验收必须单列不可恢复的旧记录。

1. 调用者发送前持久保存原 authority、目标、操作身份、完整冻结请求及输入引用。传输请求 ID、Hub action ID、Runtime task ID、项目 run ID 分开保存。
2. 新协议的幂等范围建议包含 authority、已验证主体、操作类型和稳定目标；同键比较完整规范请求，不只比较输入 hash。规范化/默认值规则必须版本化。**现有 Runtime store 中键的范围是该 Runtime 库，Hub action 的 ID 派生规则保持原样**；不能为适配新范围改掉旧哈希或重放算法。
3. 响应丢失时查询原 action/TaskRef，或明确重发同键同请求；不换键、不换 authority、不换节点猜测重提。恢复已接受意图不重新从当前可编辑参数生成 argv。
4. 节点在可能产生副作用前持久保存接受/启动身份；事件与退出回执进入本地可恢复发送日志。重连核对原 authority、task、attempt、epoch、已有外部作业/进程证据，再续传事实；不是重放所有历史执行命令。
5. 控制事件按生产者代次和序号去重；同身份不同内容视为冲突。允许乱序到达时标记缺口并补读，禁止只凭墙钟排序宣告最终状态。节点时间作展示，authority 接收序列作同步游标；租约还需明确计时及最大授权窗口规则。
6. 当前日志与 monitoring events 继续使用**字节偏移**及原返回游标，不能改成控制事件序号。旧求解器可不发监控事件；缺少 `run.completed` 也不替代 worker 核实。

网络分区下不承诺 exactly-once。尤其是有 license 的程序、GUI 点击、外部提交、文件覆盖和付费操作：租约过期后先保留 uncertain/unknown 事实并核实原节点，不自动转派。节点恢复前可能仍在执行，节点故障也可能已经完成副作用。fencing token 只能阻止**能够核验它的受控提交端**接受旧写入，不能撤销已发生的任意软件操作。无副作用、隔离输出的纯计算只有在执行器显式声明且验收了可重试语义后才可讨论重叠尝试；首版不默认启用。

**离线默认规则（建议）。** 对依赖远端协调授权或续租的节点执行通道，失联后停止接收或启动新任务，也不启动新的 GUI 动作；失联前排队但尚未启动的命令同样等待重新授权。已经运行的 batch 只能依据接受时冻结的、有限的离线执行授权窗口和许可约束继续；未授予该窗口、窗口到期或无法证明仍有效时，节点请求原执行器停止。未核实实际停止时保留 `unknown`，不能宣告 cancelled。具体时长待执行器及产品策略测量后决定，本文不设秒数。离线期间无法保证立即获知云端撤权，重新连通后先核对当前授权再接收新工作；许可窗口或租约过期均不自动重派。**本机 authority 拥有、且本地用户已授权的独立本地任务仍可启动，本地完整版保持离线可用**；但不得把原远端未决命令换身份转成本地任务以绕过这些限制。

取消是一项独立幂等命令。取消先到而启动尚未发生时，节点必须在执行门禁前检查取消记录；启动已发生时，由原执行器核实结束。自然结束与取消竞态保留真实退出结果和取消意图，不把已成功强改为已取消。UI 关闭、终端退出、订阅取消、等待超时、连接断开都不等于任务取消。

## 6. Artifact、Replica 与 Transfer

| 对象 | 建议职责 |
|---|---|
| `Artifact` | 不可变逻辑版本：所属授权域、来源 Task/Attempt 或项目快照、内容 hash 算法和值、字节数、类型/schema、相对清单、原始类型/单位/来源。派生预览另有身份和来源关系 |
| `Replica` | 某节点/存储适配器上的一份副本：ArtifactRef、私有定位符、当前可达性、最近校验时间与完整性证据。离线、缺失、损坏分别记录 |
| `Transfer` | 本次授权下从明确源向明确目的复制：操作身份、ArtifactRef、授予范围、声明长度/hash、分块进度、校验和最终发布回执 |

内容 hash 只标识字节，不证明来源、授权、科学真实性或所有副本可用；相同字节可共享内部存储，但不同项目/用户之间不因此获得读权限。不能向未授权主体暴露跨域去重命中作为存在性探针。逻辑资源版本、项目记录 ID 和临时下载 URL 也不能互相替代。

沿用现有快照、上传和下载原则：流式复制到私有暂存区 → 核验完整大小与 SHA-256 → 原子发布 → 保存可用副本回执。旧 transfer offset 以接收端实际持有的字节为准；断线保留进度，重新校验源身份/内容后续传。源内容变化产生新不可变版本，不续写到旧资源身份。暂存文件、未校验 blob、数据库中孤立的清单都不能称为完成副本；现有项目文件快照并非 OS 级多文件原子快照。

大文件默认留在数据所在节点；云端保存获准的引用、摘要和进度。先送计算到数据附近，确需搬运时明确源、目的、字节预算和授权。目录同步、缓存复制、预览、文献索引、全文上云和模型出站是分别授权的动作。浏览器选中文献或绑定节点不触发整库/目录上传。远程消息使用受限资源引用与规范相对路径，不将本地绝对路径、凭据、环境变量或任意文件读取权放进公开元数据。

当前 Runtime 产物是完成任务的 `{path,size,sha256,media_type}` 清单，首次登记后缓存；后续修改由下载校验发现。它还不是上述通用资源注册表。现有 Hub 通用 blob 与设备上传配额/导入引用也不能直接当多租户 Artifact ACL；上线前须补齐每个读取、续传和去重查询的授权。备份仍必须包含项目数据库与 `.stk/objects`/相关资源，不能只同步数据库就宣告数据完整。

## 7. 身份、放置与本地能力

云账号、调用设备、执行节点、节点进程代次和当前登录桌面会话是不同身份。节点通过显式配对绑定持久身份、可轮换凭据和能力声明，优先主动连出；Web 不通过任意 URL 访问节点。账号绑定不自动授予全部项目、shell、文件、Computer Use 或模型权限。每个命令校验当前主体、目标项目/节点、操作、数据出口、资源预算和有效期；节点执行门禁再次检查自身实际能力及许可。

放置条件包括执行器及版本、OS/架构、CPU/GPU/内存、输入可用副本、数据移动许可、软件 license、本地交互会话和预算。有 license 的软件必须在获授权本机执行；上传配置或镜像不转移 license。商业许可的具体有效性由相应配置/执行器核实，本协议不推定许可条款。

Computer Use 另授 `desktop.control`/`browser.control` 能力，绑定明确节点、用户会话和范围；必须有可用 GUI 会话，headless 在线不能假装有桌面。锁屏/注销、会话重建、权限撤销时不能把旧点击交给新会话。接受但响应丢失的 GUI 动作需先观察结果，禁止透明自动重放。当前 bridge 的 `ui.request` 是同机私有 stdio、30 秒过期且不重放的机制，不是远程桌面协议或既有网络权限。

截图、PDF、网页、插件输出均是非可信输入，不能为自己增权。已有项目私有数据不得发送外部模型；模型端点、密钥和网络策略仅由明确桌面操作配置。Web 对本地节点的授权也不能绕过这一边界。密钥和连接凭据不得进入 TaskSpec、普通项目字段、幂等指纹原文、公开事件、日志或 Artifact 清单；任务环境应使用执行侧的受限秘密引用，后者仍待设计实现。

共享算力首版调度完整任务、参数扫描的独立项或显式 DAG 步骤。单任务多机计算需要执行器本身支持的 MPI/分布式协议、明确网络/存储/拓扑与 license 验证；不把不同电脑 GPU 显存或文件系统默认为统一资源。

## 8. 版本协商和旧端兼容

- 同一后端代码发布仍需握手：协议主版本、schema、应用服务/执行器版本、必需能力、限额和身份。功能存在不等于当前主体获准使用。具体新字段和网络路由名称须在实施前另定 schema，本文件不注册一个虚构的 v2 API。
- 保持现有 Runtime `/v1`、bridge `protocol:1`、`stk.peer/1`、`stk.graph/1`、`stk.payload/2`、`stk.result/1` 各自版本，不因本架构统一而合并版本号。项目格式升级继续显式迁移、验证备份，并按现有较新格式读取限制处理。
- bridge v1 请求 params 是闭集，新增可选字段/方法须先更新 schema 和能力声明；结果/事件未知键可忽略，错误码仍是闭集。删除或改变原含义需要 protocol 2；peer 严格信封遵守其独立契约，不能套用 bridge 的开放结果规则。
- 不支持的新能力返回明确不支持，或留在安全的本地已有路径。对 lease fencing、资源授权、校验输入、秘密引用等安全必需能力不得静默删除字段后重试。对纯展示的未知可选元数据可保留而不解释。
- 当前 Runtime 支持 `input_checksums` 时，才可依赖 `inputs` 与完整 `input_hashes` 的固定输入；旧 TaskSpec 省略 `input_hashes` 时序列化及幂等摘要保持原样。不能给旧请求补默认值导致不同的重放身份。

**精确读取兼容点。** bridge v1 §7 的旧描述仍允许 heartbeat snapshot；当前 `HubBackend.task` 在双方支持时经 `read/task.get` 精确读取，默认旧调用仍可回退到快照，`require_live=True` 则拒绝缺少能力的旧端。Hub CLI 已将最多 200 条列表标为 `heartbeat_snapshot`。因此新工作台恢复/最终核实必须要求节点 `features` 与 Hub `policy.read_kinds` 均支持精确 `task.get`，不把旧快照未命中当作不存在，也不擅自改变旧调用行为。该文档差异应在正式实现时同步校准，本提案不修改既有契约。

## 9. 兼容场景

| 场景 | 保留现有行为；新设计需要增加的部分 |
|---|---|
| `p.runs.submit(run_id)` 响应丢失 | 再次明确 submit 恢复同一冻结方案/键，已有 task ID 只返回记录；新设计增加可信 authority 绑定，不改旧 plan 或重新读取参数生成命令 |
| Hub 收下 `task.submit` 后 Web 退出 | 保留 action ID、原键与请求；原节点通过该 action 身份调用 Runtime.submit。原 action 处理成功只表示取得任务，最终状态按原 task 精确读 |
| 同机 Runtime 地址换了另一实例 | 现有无凭据 URL/SSH/node 指纹只能防配置误指向，不能认证实例；新设计要求持久 authority 身份，失败时拒绝把新实例当原服务 |
| 执行节点断网且云端 Lease 过期 | 展示最后观察和未核实事实；不假定停止、不在另一节点再次启动带副作用任务。恢复后核对原 task/attempt/外部作业，独立收取最终回执 |
| 下载中断/源节点离线 | 现有 `.part` 与 transfer journal 续传、接收端 offset、最终大小/hash 验证；新设计记录 Replica 可用性，不能以断网删除 Artifact 或自动上传所有输入 |
| Windows 本机有授权 GUI 软件，Web 发起任务 | 当前尚未交付该执行节点能力；未来须同时满足节点执行器、许可与对应用户会话授权。不能改派 Linux 云节点或把已有本机 `ui.request` 当远程支持证明 |

## 10. 实施前必须查证与后续接口落点

1. **身份和事务**：authority 身份签发/备份分叉；同一应用服务的本地/云适配器；当前幂等作用域与用户隔离；接受事实、outbox、取消与启动的事务边界。原 TaskSpec 哈希、Hub action ID、项目 operation/run ID 不能被一次通用 envelope 改写。
2. **生命周期**：在现有 `Store.reserve/claim/update`、`RuntimeService.submit/cancel`、supervisor/独立 worker 门禁上审查新增 Attempt/Lease 所需变化；验证旧 worker 冻结副本、API 重启、提交不确定与调度历史核对仍有效。不可仅以 HTTP mock 或 TTL 单元测试宣告重复副作用已解决。
3. **数据与授权**：映射项目快照、Runtime workspaces/artifacts、Hub blobs 和 transfer journals 的身份、路径和保留边界；新数据注册表不能凭 hash 接管全部资源。多租户执行隔离、存储根/配额/保留策略和 license 适配器要另作明确设计与验收，不能沿用当前个人可信程序权限对外开放。
4. **入口兼容**：Desktop、CLI、Python、Web 以同一应用服务/只读观察语义接入；精确 task.get 能力门、原操作恢复、不同版本拒绝、Viewer/草稿保护与跨 OS 节点按[验收方案](distributed-workbench-acceptance.md)验证。Synthrix 的具体集成接缝仍需读取其当前契约后映射，本文不推定旧可选 Hub slice 已接入正式启动入口。

既有 owner 待定项继续保持：合作方 S3/MuPRO 电场扫描口径、S2c prepare/run 代理权限、分析修改提案持久形式。本文不代选这些决定，云账号绑定也不授予模型数据出站权限。
