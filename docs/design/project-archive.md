# 项目对象归档（方案）

更新：2026-10-08。状态：**所有者已确认（2026-10-08）；A1–A3 已实现**，按下文“所有者决定”与“实现细节”，进度见“增量”，桌面行为见“桌面”，限制见“已知限制”。来源：[ADE 参考](ade-references-2026-10.md) 做法 9，
[体验包](ux-package-2026-10.md) 中暂缓的一项。

## 要解决的问题

项目里的对象分两类：

- **可编辑对象**（工作流、保存的分析、仿真批次、参数行）存为表格记录，删除是一次可撤销的项目编辑。
- **不可变记录**（工作流运行、分析运行、仿真运行、AI 问答及其消息、上下文、草案）是只追加的日志，
  保证“旧结果不被改写”，因此**不能删除**。

用得越久，运行记录、问答历史和“需要处理”里的旧失败越多，只能逐个“已看”或一直留在列表里。
可编辑对象也只能删除，没有“先收起、需要时再找回”的中间状态。

归档要做到：**收起不再需要的对象，数据和身份完全保留，随时恢复**；不删除、不改写任何运行、回执或结果。

## 对象与现状

| 对象 | 存储 | 现在能否删除 | 归档后从哪里收起 |
|---|---|---|---|
| 工作流 | 受管表格 Workflows（可编辑记录） | 可以（可撤销） | 工作流列表、工作台搜索 |
| 保存的分析 | 受管表格 Analyses | 可以（可撤销） | 分析列表、工作流可选对象 |
| 仿真批次 | 表格“仿真批次”（`suan/workflows/batches.py`） | 可以（删行） | 已保存批次列表 |
| 工作流运行 | `workflow_run_plans` / `_events` 日志 | 不能 | 运行记录、需要处理 |
| 分析运行 | `analysis_run_plans` / `_events` 日志 | 不能 | 分析“运行”页、需要处理 |
| 仿真运行 | `run_plans` / `run_observations` 日志 | 不能 | 仿真运行记录、需要处理 |
| AI 问答 | `project_requests`（及其问题与回复消息） | 不能 | AI 助手历史、需要处理、搜索 |

草案已有“放弃”（关闭后不再待审），上下文只作为问答的来源出现；首版不单独归档这两类。

## 数据表示：四个候选

| 候选 | 做法 | 优点 | 问题 |
|---|---|---|---|
| A 每类加字段 | 受管表格新增可选“已归档”字段 | 归档是普通可撤销编辑；旧版本忽略多出的字段，仍能打开 | **只覆盖可编辑对象**，运行与问答是不可变日志，无法加字段；每次归档推进可编辑修订，使待审的 AI 草案无法直接应用（草案只能在其保存时的修订上应用） |
| **B 独立归档记录（推荐）** | 项目中新增只追加的归档表（项目格式 11）：`(kind, object_id, archived, changed_at, note)`，当前状态取每个对象的最后一条 | **七类对象统一**；不推进可编辑修订，不影响草案、过期判断和撤销历史；与运行、问答等日志同一类数据 | 需要一次先备份的显式升级到格式 11（与格式 9、10 相同）；旧版本拒绝打开格式 11 的项目；恢复靠“取消归档”而不是撤销 |
| C 一张受管“归档”表 | 可编辑表格存放归档标记，不升级格式 | 统一，不升级格式，可撤销 | 与 A 一样每次归档推进修订、使待审草案失效；归档标记成为可被直接改写的表格行 |
| D 只记在本机 | 像“已查看”一样存在服务状态目录 | 不改项目 | 不随项目移动，别人打开同一项目看不到；不符合“归档”是项目状态的含义 |

推荐 **B**：只有它能覆盖不可变记录，而且不打扰编辑修订。归档本质上是“列表里收起”，
和运行状态、问答状态一样属于项目的日志数据，而不是参数编辑。

## 推荐的行为

- **归档 / 恢复**：明确的操作，可一次选多项（每次最多 100 项），可附一句备注；记录时间。不推进可编辑修订，
  不进入撤销；变化后通知已打开的界面重读列表。
- **列表**：默认不显示已归档；每个列表有“显示已归档（N）”，已归档项灰色并标“已归档”，带“恢复”。
- **打开已归档对象**：可以查看。可编辑对象（工作流、分析、批次）**编辑、运行或准备前需先恢复**（页面顶部横幅“已归档 · 恢复”），
  避免收起的对象在看不见时被改动或被运行。
- **需要处理**：不列已归档对象。失败的运行可以直接从“需要处理”归档，作为“已看”之外的长期收起方式。
- **工作流与它的运行**：归档工作流时询问“同时归档它的 N 次运行”（默认勾选）；运行也可单独归档。
- **引用**：工作流仍可引用已归档的分析，校验给出提示“引用了已归档的分析”（不是错误），已有运行不受影响。
  （实现按所有者决定 2 细化：列为工作流的问题 `archived_reference`，保存与编辑不受影响，只是恢复前不能运行，见“实现细节”。）
- **搜索**：默认包含已归档对象，排在后面并标注，方便找回。
- **删除不变**：可编辑对象的删除仍是可撤销编辑；被删除对象的归档记录保留但不再显示。

## 服务与脚本接口（草案）

- `project.archive.set {handle, items: [{kind, id}], archived: true|false, note?}` → `{changed}`；`kind` 为
  `workflow`、`analysis`、`batch`、`workflow_run`、`analysis_run`、`simulation_run`、`request`；未知对象被拒绝。
- `project.archive.list {handle, kind?, offset?, limit?}` → 已归档对象及时间与备注。
- 现有列表方法每项增加 `archived`，并接受可选过滤 `archived: false | true`（不传时仍返回全部，兼容现有脚本与旧客户端）。
- 事件 `project.archive.changed {handle, kinds}`。
- Python：`stk.project.archive(kind, ids, note=None)`、`stk.project.unarchive(kind, ids)`、`stk.project.archived(kind=None)`。

## 实现细节

- **类别**：`workflow`、`analysis`、`batch`、`workflow_run`、`analysis_run`、`simulation_run`、`request`、`draft`、`context`。
- **存储**：表 `project_archive(id, kind, object_id, archived, at, note)`，只追加；对象的当前状态取其最后一条。不推进可编辑修订、不进入撤销；
  旧项目经已有的“备份并升级项目”显式升级到格式 11。
- **归档的前提**：对象存在；进行中的对象（运行中或正在取消的工作流/分析运行、仍在 Runtime 上的仿真任务、正在回复的 AI 请求）先取消或等它结束。
  未发送的问题与待审草案可以归档。
- **只读的含义**（服务端检查，提示“先恢复”）：已归档的工作流与分析不能保存修改，也不能为它们准备新运行；已归档的批次不能准备或提交；
  已归档的运行不能开始、重试或恢复；已归档的草案不能应用或放弃；已归档的上下文不能再提问；已归档的 AI 请求不能发送。查看与读取结果不受影响；
  可编辑对象的删除仍是普通的表格编辑，不受归档限制。
- **列表**：各列表方法接受可选 `archived`（`false` 只列未归档、`true` 只列已归档，不传为全部，兼容现有脚本），在 SQL 中过滤，分页与总数随之正确。
  界面默认只列未归档，“显示已归档（N）”切换到只列已归档并可恢复。
- **其他**：“需要关注”不列已归档对象；搜索结果带 `archived` 标记、排在同类后面；归档工作流时可选同时归档它的运行。
- **服务方法**：`project.archive.set {handle, items, archived, note?, include_runs?}`、`project.archive.list {handle, kind?}`
  （当前已归档的对象、时间与备注，及各类数量），事件 `project.archive.changed`；Python `stk.project.archive/unarchive/archived`。
- **引用已归档的分析**：工作流校验把引用已归档分析的步骤列为问题 `archived_reference`（“引用的分析已归档”），工作流仍可编辑和保存，
  恢复分析前不能运行；准备运行时同样拒绝（“Step X uses an archived analysis; restore it to run this workflow”）。

## 桌面（A2、A3）

- **共同状态**：`ProjectArchive`（`project.archive.list` 的结果，`project.archive.changed` 或自己的修改后重读）给出各类已归档的 ID 与数量；
  归档不推进修订，因此各列表记下“读取时用的过滤与归档版本”，归档集合或过滤变化时从第一页重读。
- **列表**：工作流、工作流运行、保存的分析、分析运行、AI 问答历史（AI 助手与项目页“讨论”共用一个选择）、上下文、保存的草案、仿真运行默认只列未归档，
  服务端过滤；仿真批次是表格行，在界面按归档 ID 过滤。“显示已归档（N）”只在该类有已归档对象（或已打开）时出现，切换后只列已归档。
- **只读**：已归档的工作流与分析仍显示，标“已归档：恢复前只读”，编辑与运行按钮不可用；已归档的运行不能重试或提交；已归档的草案不能载入审阅或放弃；
  已归档的上下文不能添加消息或提问；已归档的 AI 问题不能发送、不能生成草案；已归档的批次不能准备或提交。每处都有“恢复”。
- **工作流**：“归档”同时归档它不在运行中的运行，“恢复”同时恢复它的运行；运行也可单独归档（运行中不可）。
- **需要关注**：已看过一项之外，“归档”把它长期收起（不再列出，状态栏计数随之更新）；运行中的项目没有“归档”。

## 已知限制

- “显示已归档（N）”在该类没有已归档对象时不出现（方案原写每个列表都有）；工作流运行与分析运行的开关不显示数量，因为数量按整个项目统计，不只是当前工作流。
- 恢复工作流时会恢复它的全部运行，包括之前单独归档的运行（服务端 `include_runs` 不区分归档来源）。
- 只读检查覆盖专门的保存/准备/开始/应用/放弃/提问操作，不拦截直接对受管表格的 `project.apply` 编辑；批次的刷新、取消与收集不受归档限制。
- 已归档的上下文中的消息仍在“讨论”的消息列表中（消息列表不按上下文归档过滤）。
