# 草案、对话上下文与恢复边界

状态：2026-09-30。格式 6 的[持久草案与应用回执](../project-drafts.md)、格式 7 的
[显式上下文、文字消息及草案来源关联](../project-contexts.md)已实现；格式 8 增加
[请求记录与本地执行生命周期](../project-requests.md)，现已接入阿里 Token Plan 的显式文字发送路径。
实现与离线协议测试已具备，Linux 已通过一次 `qwen3.7-plus` 的合成单元格真实调用及持久化核对。
macOS/Windows 原生界面的真实模型调用仍待验收；完整 AI 主页面、流式显示、远端查询及工具提议仍待开发。
本轮沿用格式 8，不增加数据库迁移。

原生项目编辑器的“讨论”页提供显式选行/字段捕获、分页记录、消息填写及当前已保存草案的来源关联，
并支持从已保存的用户消息准备请求、明确发送、查看详情、取消、核实遗留执行和打开关联消息。
准备请求只保存意图；“修改检查”显示来源并提供明确刷新入口。
文字以普通文本展示，不渲染 Markdown 或执行代码。
本机与跨平台验证状态分别记录在[开发计划](../development-plan.md)和[验收记录](../runtime-validation.md)，
此处不把实现等同于全部平台验收完成。

## 统一修改接口

普通项目命令共用 `apply` 与只读 `preview`。原生检查展示确定性差异和公式错误；
`stk.project.review` 可以把 Python 提出的命令送入该视图。持久草案保存稳定命令、项目 UUID、
基础修订及终态回执，不保存模型授权、差异快照或审批身份。

保存不更改参数；应用参数修改、准备运行方案和提交计算分别由明确操作触发。
重开项目不执行草案；已有回执不会因撤销参数而恢复为待执行状态。这些边界保持不变。

## 显式上下文捕获

格式 7 的首版仅捕获一张表中明确给出的记录与字段 UUID。项目 UUID、读取修订、捕获时间、
显示名称、类型与单位随内容保存；后续焦点、排序、改名或删除都不改变已经捕获的选择。
缺失对象保留诊断，已属于其他表的对象拒绝捕获，不静默改选对象。

捕获只读取选中范围的字面量、引用/公式定义和已有求值缓存。不为上下文计算而遍历未选中的依赖，
也不自动读取文件、日志、大型科学数组、程序源代码或连接凭据。文件路径和摘要不能代表完整文件副本。

范围限制为 1–100 行、1–64 列、最多 1000 个单元格；单项内容限 16 KiB，上下文限 256 KiB。
超限内容保留省略原因、大小和校验和；缓存缺失或损坏有独立诊断，不把省略内容当作已捕获。
这些限制约束读取与保存规模，不靠先读取整个项目再裁剪。具体字段和返回形式见[使用指南](../project-contexts.md)。

捕获对象不可变。项目修订继续推进后，旧对象保留来源修订；明确重新捕获产生新身份，
不在后台刷新、替换旧消息引用的内容。未来文件附件与运行摘要需要单独定义内容身份、预算和恢复语义。

## 消息与可执行提案分开

每条消息是引用一个已保存上下文的不可变文字记录，角色仅为 `user` 或 `assistant`，不表示经认证的身份。
普通文字、Markdown、代码块或模型声称的“已批准”都不能直接变成操作，也不会交给 Python 控制台执行。

提案来源记录引用消息、上下文和已保存草案，要求项目身份一致且上下文来源修订等于草案基础修订。
每个草案最多有一条来源记录。上下文用于解释修改依据，其选中范围不是草案命令的授权范围；
命令仍由已有预览、差异检查、修订校验与显式应用控制。

关联不会应用草案，也不会替换草案内容或回执。准备运行和提交任务继续采用各自接口和记录，
不能混入表格命令数组。格式 8 单独保存请求意图与执行观察；消息、请求状态及草案关联均不是执行授权，
也没有隐式生成或执行入口。

## 幂等与恢复

上下文、消息、来源关联和模型请求分别使用调用者保留的 UUID。同一身份及相同请求返回原记录，
同一身份改内容会冲突。响应丢失时按 ID 或关联查询核对记录，再决定是否明确重试原请求。
记录保存在项目数据库中，不提升表格修订，也不进入表格撤销栈。

关闭重开可以恢复原数据与关系，不能自动捕获、调用模型、应用修改、运行代码或提交计算。
应用回执仍引用原草案；撤销表格修改不重置回执，不能把“已记录消息”或“已关联草案”当作“已应用”。
升级使用已有备份优先事务，格式 1–7 可显式升级到 8；旧项目打开时不自动迁移。

验收应覆盖固定选择与内容、大小/缺失诊断、跨表拒绝、同一基础修订关联、请求重试与身份冲突、
编辑后历史保持、重开不执行，以及格式迁移/备份。原生入口还需覆盖已有输入保护、过期回调丢弃、
草案来源刷新和不确定响应恢复；测试结果在开发计划中单独记录。

## 请求生命周期（格式 8，已实现）

`project_requests` 独立保存请求身份、输入摘要、执行所有者及当前观察。桥和 Python facade 开放
`project.requests.create/get/list/cancel/provider/start/recover`；创建仅保存意图，只有明确 `start` 才能发送。
`provider` 只检查本机配置存在性；`recover` 只核实本机旧执行器，不查询远端。
原生列表和详情的刷新只读取 SQLite，没有自动轮询、自动发送或任意适配器配置入口。

本地库 `suan.project.request_executor.RequestExecutor` 默认适配器映射为空，由可信调用方注入；
桌面桥明确注册固定版本 `aliyun-token-plan/1`。可控测试回复不作为真实账号验收结果。
这些能力不改变项目修订、撤销历史、草案或任务，也不发出桥事件；其他客户端需显式刷新。
方法参数与返回字段以[桌面桥契约](../specs/stk-desktop-bridge-v1.md)为准。

### 请求身份与明确输入

一个请求引用一条已保存的 `user` 消息及其唯一上下文，完整结果对应一条助手消息；
后续才接结构化修改提案。不会因打开讨论页、切换选择、保存消息或恢复项目而自动发送请求。
用户发送前可以查看将要引用的上下文、来源修订、缺失/省略信息及文字。未选入的历史消息、
当前实时表格、文件内容、运行日志和其他项目不自动补入请求。

完整公开记录是以下 16 个平铺字段，`get` 和分页 `list` 返回同一形式：

```text
{id, project_id, context_id, message_id, assistant_message_id, source_revision,
 configuration, prompt_version, input_sha256, created_at, status,
 cancel_requested, executor_id, updated_at, error_code, result}
```

调用者保留稳定的请求 UUID；助手消息 UUID 从项目与请求身份派生并预留，手工消息不能占用。
同一 UUID、相同消息和规范化配置返回原记录，即使已经完成或取消；改变输入必须新建 UUID。
当前没有覆盖、删除、重新置为待执行或“替代请求”关联接口。

`configuration` 只接受必填 `adapter`、`model` 和可选 `temperature`、`max_output_tokens`。
标识为 1–128 个 ASCII 字符，以字母或数字开头，其余允许字母、数字、`.`、`_`、`:`、`/`、`-`，
禁止 `//`。温度是 0–2 的有限数；输出 token 上限是 1–32768 的整数，默认 4096。
返回记录保存规范化后的当时取值；名称只匹配可信调用方提供的适配器映射，不作为动态导入路径。
保存配置的接口不接受 URL、认证字段或任意扩展参数，也不读取凭据；不要把凭据写进项目消息或配置标识。
提供方存在性检查和发送前准备才读取本机环境变量，密钥不进入请求输入、摘要或项目数据库。
阿里适配器在领取发送权前额外要求温度小于 2；它不会改写已保存的配置来满足提供方限制。

`prompt_version` 固定为 `stk.text/1`。`input_sha256` 覆盖保存的完整上下文、用户消息、规范化配置及
该组装版本的规范化 UTF-8 JSON；本地执行输入总量限 1 MiB。每次读取在同一事务内验证请求状态校验和、
上下文和消息的来源校验和及完整输入摘要。来源修订即使已经过时，也不会换成实时值或遍历未选中的依赖。
列表和详情只返回元数据，消息全文与上下文内容通过原有接口读取。

完整回复继续遵守 64 KiB UTF-8、非空文字限制，不截断后冒充完整结果。`result` 完成前为 null，完成后是
`{message_id, text_sha256, metadata}`；观察字段只允许 `model`、`remote_request_id` 及非负 64 位整数的
`input_tokens`、`output_tokens`。两个文字观察字段沿用配置标识的限制；不保存原始响应头或异常原文。
当前不在本机计算模型 token 数或预判各型号的 token 上下文预算；发送前检查本机字节上限与参数，
提供方返回的受限用量字段只在完整回复保存时记录。上下文不会为适配模型预算而被静默裁剪。

### 状态与发送边界

持久消息、模型请求、修改草案和应用回执分别表达不同事实。格式 8 已保存以下状态：

| 状态 | 表达的事实 | 后续处理 |
|---|---|---|
| `pending` | 请求意图已保存，尚未领取发送权，能够证明没有发出 | 本地服务显式开始，或在发送前取消；重启不自动发送 |
| `running` | 执行所有者已持久领取发送权，可能已经发送；不证明远端已接受或所有者仍活跃 | 接收结果、请求取消，或显式核实执行器是否丢失 |
| `completed` | 完整有效的响应及其助手消息关联已经持久保存 | 查看结果；是否创建草案和是否应用仍是后续明确操作 |
| `failed` | 已知本次尝试失败，例如派发线程启动失败、确定拒绝、完整响应校验失败 | 保留受限错误码；检查后可建立新的请求 |
| `cancelled` | 发送前已经取消，或已获得足以证明远端取消完成的终态证据 | 保留记录，不恢复生成、不发布迟到内容 |
| `uncertain` | 已经可能发送，但缺少完整确定结果 | 核对已有本地记录；不能当作未发送，也不能自动重试；远端查询待实现 |

开始前取得 `.stk/request-locks/<请求 UUID>.lock` 的非阻塞系统锁，再在 SQLite 写事务内领取唯一发送权。
锁使用 POSIX `flock` / Windows 字节锁及同进程保护，持有到工作线程退出；锁文件保留，不能以文件存在与否
判断活跃状态。其保证限于本机具有正确文件锁语义的项目文件系统，不是跨设备分布式协调。
重复开始不派生第二次发送；没有匹配的可信适配器时保留 `pending` 并报错。
适配器可提供 `prepare(frozen_input)`，在持锁且尚未领取发送权时校验本机配置并返回准备好的发送对象。
阿里适配器在此处固定密钥与序列化请求体，之后环境变化不会改变这次发送；预检失败不消耗请求身份。

必须先提交 `running` 与 `executor_id`，再调用适配器的 `send(frozen_input, cancel_event)`；发送时不持有
SQLite 事务。若恰在提交与调用之间崩溃，记录也无法证明未发送：显式恢复只会转为 `uncertain`，不会退回
`pending`。打开项目本身不做此状态更改。适配器不得自行重试提交。

确定失败使用 `DefinitiveFailure`，确定取消使用 `ConfirmedCancellation`；未知异常或超时记为
`transport_uncertain`，完整响应校验失败为 `response_invalid`，本地完成保存失败为 `local_save_failed`。
错误使用固定代码及更新时间，不把异常原文、认证信息或原始响应写入项目。提供方幂等性、远端请求 ID 的
中途观察和远端查询仍待接入；本机请求 UUID 不能代替提供方幂等保证。

### 结果保存、取消与迟到响应

请求在创建时固定用于助手消息的身份，接收结果时核对请求 UUID、原项目及执行器代次。
同一所有者的相同完整结果重复到达只完成一次本地保存；相互矛盾的结果返回冲突，不覆盖原消息。
助手消息插入与请求完成标记在同一 SQLite 事务内提交，任一步失败均回滚，不存在先发布半条结果的阶段。
读取完成记录时再次验证助手消息的项目、固定 ID、上下文、角色和文字摘要。

当前只接收完整文字，没有流式片段、输出暂存或远端结果查询。若收到文字后、原子保存完成前中断，
不会把它标记完成；保存失败且仍能更新记录时保留 `uncertain/local_save_failed`。
本地已丢失的文字不能自动恢复，也不能因此重新调用适配器。

取消先持久保存意图。待开始请求直接变为 `cancelled`；已开始请求变为 `uncertain/cancel_unconfirmed`。
桥通过自己的执行器取消时，随后设置它所拥有的工作线程的取消事件；其他执行器或其他进程只写入意图，
不能直接触发这个事件。工作线程及阿里适配器在提交前发现取消时跳过发送；已发送的请求只有取得明确终态
证据才能记为取消完成。当前阿里适配器没有远端取消接口，提交后的本地取消不证明远端停止；
仍可能收到完整回复并按原请求保存。

完成与取消竞争时以持久记录的条件更新决定本地先后：

- 已经完成保存的结果保持 `completed`；稍后的取消不撤销助手消息，更不撤销已明确应用的项目编辑。
- 已确认取消的请求保持 `cancelled`；迟到响应不发布为新消息或草案，当前没有独立的迟到响应日志。
- 已请求取消但仍不确定的请求，可以通过经过身份核对的完整响应确认最终结果；
  即使核对为完成，也只关联回原请求并标明取消意图，不抢占当前输入、切换页面或执行提案。
- 项目已关闭、切换或桥已重启时，旧代次的 UI 回调不能更新新项目或覆盖正在输入的文字。
  持久结果只能写回已绑定且重新校验身份的原项目，不能使用此刻的“当前项目”替代目标。

### 重启后的核对

打开项目只读取保存的记录，不恢复网络生成或工具执行，也不自动改写状态。`pending` 等待显式开始；
原生界面把保存的 `running` 显示为“已启动，需核实”，不声称后台已经确认仍在接收。
桥、Python 与原生入口的显式 `recover` 必须取得该请求空闲的系统锁，才能把遗留 `running` 标为 `uncertain/executor_lost`；
有活跃执行器持锁时拒绝恢复。恢复不发送、不查询提供方、不重试，也不把请求重新置为 `pending`。

关闭项目句柄或切换桌面项目不会取消已经接受的工作；结果仍绑定原项目 UUID 和数据库。
桥退出时调用执行器的非阻塞 `shutdown`：立即阻止后续回复发布，并在后台尽力将活动请求记为不确定，
不为等待数据库写锁而延长退出。仍未退出的工作线程继续持锁，守护线程不阻止进程退出；进程退出后
操作系统释放锁。数据库暂时不可写或进程先退出时可遗留 `running`，需之后显式核实。
外部创建的本地执行器仍由其调用者管理寿命，关闭桥不会控制这些执行器。
迟到结果不能改用当前项目，旧 UI 回调仍受项目句柄和原请求身份保护。

原生刷新只读取数据库，核实遗留执行需要独立明确操作。未知远端结果仍需用户核对；另建请求保留旧记录，
不能宣称新请求是旧请求的安全重放。远端查询、结果暂存与进一步收尾协议列入后续集成。

## 阿里 Token Plan 文字适配器（已实现，Linux 单次真实调用通过）

`aliyun-token-plan/1` 固定使用用户指定的
`https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，不允许项目配置替换端点。
密钥只从 `STK_TOKEN_PLAN_API_KEY` 读取；`STK_TOKEN_PLAN_MODEL` 可提供显式型号，缺失或不合法时显示为空，
不猜测默认型号。原生准备请求时保存选定型号；后续环境变化不会改写它。
`provider.configured` 只表示发现符合本机格式要求的凭据，不证明认证成功、余额或型号可用。

版本固定系统提示与输入组装政策：只提交已保存的上下文及所引用的用户问题，明确缺失数据与不执行操作的边界。
传输采用一次经 TLS 验证的 Chat Completions POST，`stream=false`、`enable_thinking=false`，不声明工具。
只接收单条助手文字且 `finish_reason=stop`；不完整、超长、工具/函数调用或只有推理而无答案的输出均不发布。
HTTP 响应限 1 MiB，使用 60 秒 socket 超时并在操作之间检查已用时间；不使用代理、不跟随重定向、不重试。
部分明确拒绝记为已知失败，网络异常、超时及无法判定的状态保持不确定。详细限制见[请求指南](../project-requests.md)。

固定端点依据阿里[第三方工具接入说明](https://help.aliyun.com/zh/model-studio/more-tools)，
非流式请求和参数依据[Chat Completions 文档](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。
Linux 已通过一次真实账号验证：实际 `ProcessBridge` NDJSON 链路使用注册的阿里适配器与 `qwen3.7-plus` 型号，
只发送合成的 `temperature=300 K` 单元格和简短问题，明确开始一次且无重试，得到完整回复 `300 K`。
提供方报告输入 668、输出 4 tokens；助手消息的上下文和文字 SHA-256 核对通过，参数快照与编辑历史保持不变。

## 后续模型集成

以下能力尚未实现，须单独定义提供方能力和契约。

### Token 预算、远端观察与流式显示

后续补充具体型号的 token 预算检查，超限在发送前报告，不静默裁剪上下文。
远端幂等提交、按请求 ID 查询和确认取消仍待接入；当前本机 UUID 只防止同一请求被本机重复发送。

如果提供方支持查询，用户明确核对后只能查询原来那次尝试，保存仍在执行、完成、取消或确定失败的证据。
没有查询能力、丢失远端 ID 或暂时不可达时保留不确定，不能把“查不到”解释为“从未执行”。
需要在未完成阶段保存远端 ID、观察序列或回复暂存时，应显式扩展格式和契约；当前 `result.metadata`
只在完整结果保存时记录有限观察字段。

流式显示另行接入：片段仅用于显示进度，不是完整消息、可执行提案或最终成功证据。
需要覆盖重复片段、断流、取消和桥重启，完整回复通过校验并保存后才可进入 `completed`。

### 模型文字、工具提议与草案

提供方首包只发布文字，不开放工具执行。之后的结构化输出分成独立的文字与操作提议，
不能从 Markdown 代码块、自然语言中的“请执行”或“已批准”推导出命令。
第一种可接入的提议只允许已有普通项目编辑命令；模型提供的项目 ID、候选快照、应用回执或审批声明
均不能替代本机已有记录。执行 Python、准备运行和提交任务继续是各自明确的操作，不混入编辑命令数组。

用户明确选择检查/保存提议后，复用已有 `preview` 和 `drafts.save`，基础修订固定为原上下文修订，
校验通过后保存稳定命令；以固定的草案/来源关联 ID 记录本次提议，复用现有格式 7 的消息与草案关系。
助手消息完成不要求草案也保存成功。生成期间项目发生变化时，消息仍可保留在原上下文下，
但旧基础修订的草案保存/应用应冲突；不能只提高修订号后重试。需要新数据时明确捕获新上下文并重新核对方案。

来源记录说明提议参考了哪份数据，不证明其命令只修改选中单元格，也不构成用户授权。
已有草案或正在输入的文本仍受原生检查保护。最终应用仍由用户明确发起，并保留当前原子应用回执、
普通撤销及“撤销不重置旧回执”的规则；恢复模型请求不会走应用入口。

### 分步实施与验收

1. **本地生命周期已实现。** 格式 8 请求表、七个桥方法、原生准备/发送/查看/取消/核实及可注入执行器；
   可控适配器覆盖重复开始、取消竞争、进程退出、丢失执行器、保存回滚与数据库替换。
2. **单一提供方文字路径已实现。** 阿里 Token Plan 适配器覆盖预检、凭据固定、HTTP 传输、完整文字校验及保存。
   自动化测试使用 stdlib HTTP 编解码与内存传输，不依赖真实密钥；Linux 已另行通过一次 `qwen3.7-plus`
   合成单元格真实调用和持久化核对。各平台证据在开发计划和验收记录中维护，不把可控测试回复当作真实提供方回复。
3. **下一步完善交互与提供方观察。** 补充 macOS/Windows 原生界面的真实模型调用验收；
   逐步加入模型预算与受限流式显示，并按提供方能力定义远端查询/取消/幂等协议。
4. **接普通编辑提议。** 通过已有预览、保存草案、来源关联和明确应用完成闭环；
   先验证项目已变化、格式错误和已有输入冲突，再考虑其他独立工具类别。

各阶段应通过以下行为验收，测试不依赖真实密钥或不可控网络时序：

- 请求使用固定上下文和配置快照；后续表格、配置、选择变化不改写原请求，凭据不进入记录、摘要或日志。
- 同一 UUID 的重复开始只触发一次适配器发送；不同输入复用 UUID 被拒绝。发送前后各个崩溃点均可解释，
  重开不自动发送；超时不能误标为尚未发送或确定失败。
- 取消先到、结果先到、迟到结果、重复片段及桥重启均不覆盖其他请求或当前输入，
  不产生重复助手消息、草案或应用；未知远端结果持续显示不确定。
- 完整响应与本地保存之间中断后可按固定身份核对；超大、非法或不完整响应不会变成有效消息/命令。
  不支持结果查询的适配器保持可诊断边界，不假装具备恢复能力。
- 编辑提议使用原上下文修订，过期方案不被自动重定位；查看、保存、恢复消息或提案均不改变表格或任务。
  明确应用后可正常撤销，旧应用回执仍防止重放。

多上下文历史组装、上下文压缩、文件附件、任意工具循环及多设备会话同步留给后续独立设计，
不作为首个文字请求闭环的前置条件。
