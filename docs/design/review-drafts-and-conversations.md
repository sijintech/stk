# 草案、对话上下文与恢复边界

状态：2026-09-29。格式 6 的[持久草案与应用回执](../project-drafts.md)已实现；格式 7 增加
[显式上下文、文字消息及草案来源关联](../project-contexts.md)。首版不依赖模型服务。
完整 AI 主页面、模型生成请求与工具执行仍是后续开发范围。

原生项目编辑器已增加“讨论”页，提供显式选行/字段捕获、分页记录、消息填写及当前已保存草案的来源关联；
“修改检查”显示来源并提供明确刷新入口。文字以普通文本展示，不渲染 Markdown 或执行代码。
本机与跨平台验证状态分别记录在[开发计划](../development-plan.md)和[验收记录](../runtime-validation.md)，
此处不把实现等同于全部平台验收完成。

## 统一修改接口

普通项目命令共用 `apply` 与只读 `preview`。原生检查展示确定性差异和公式错误；
`stk.project.review` 可以把 Python 提出的命令送入该视图。持久草案保存稳定命令、项目 UUID、
基础修订及终态回执，不保存模型授权、差异快照或审批身份。

保存不更改参数；应用参数修改、准备运行方案和提交计算分别由明确操作触发。
重开项目不执行草案；已有回执不会因撤销参数而恢复为待执行状态。这些边界保持不变。

## 显式上下文捕获

格式 7 的首版仅捕获一张表中明确给出的记录与字段 UUID。项目 UUID、读取修订、捕获时间、
显示名称、类型与单位随内容保存；后续焦点、排序、改名或删除都不改变已经捕获的选择。
缺失对象保留诊断，已属于其他表的对象拒绝捕获，不静默改选对象。

捕获只读取选中范围的字面量、引用/公式定义和已有求值缓存。不为上下文计算而遍历未选中的依赖，
也不自动读取文件、日志、大型科学数组、程序源代码或连接凭据。文件路径和摘要不能代表完整文件副本。

范围限制为 1–100 行、1–64 列、最多 1000 个单元格；单项内容限 16 KiB，上下文限 256 KiB。
超限内容保留省略原因、大小和校验和；缓存缺失或损坏有独立诊断，不把省略内容当作已捕获。
这些限制约束读取与保存规模，不靠先读取整个项目再裁剪。具体字段和返回形式见[使用指南](../project-contexts.md)。

捕获对象不可变。项目修订继续推进后，旧对象保留来源修订；明确重新捕获产生新身份，
不在后台刷新、替换旧消息引用的内容。未来文件附件与运行摘要需要单独定义内容身份、预算和恢复语义。

## 消息与可执行提案分开

每条消息是引用一个已保存上下文的不可变文字记录，角色仅为 `user` 或 `assistant`，不表示经认证的身份。
普通文字、Markdown、代码块或模型声称的“已批准”都不能直接变成操作，也不会交给 Python 控制台执行。

提案来源记录引用消息、上下文和已保存草案，要求项目身份一致且上下文来源修订等于草案基础修订。
每个草案最多有一条来源记录。上下文用于解释修改依据，其选中范围不是草案命令的授权范围；
命令仍由已有预览、差异检查、修订校验与显式应用控制。

关联不会应用草案，也不会替换草案内容或回执。准备运行和提交任务继续采用各自接口和记录，
不能混入表格命令数组。本轮不保存待恢复的模型调用，也没有隐式生成或执行入口。

## 幂等与恢复

上下文、消息和来源关联分别使用调用者保留的 UUID。同一身份及相同请求返回原记录，
同一身份改内容会冲突。响应丢失时按 ID 或关联查询核对记录，再决定是否明确重试原请求。
记录保存在项目数据库中，不提升表格修订，也不进入表格撤销栈。

关闭重开可以恢复原数据与关系，不能自动捕获、调用模型、应用修改、运行代码或提交计算。
应用回执仍引用原草案；撤销表格修改不重置回执，不能把“已记录消息”或“已关联草案”当作“已应用”。
升级使用已有备份优先事务，格式 1–6 可显式升级到 7；旧项目打开时不自动迁移。

验收应覆盖固定选择与内容、大小/缺失诊断、跨表拒绝、同一基础修订关联、请求重试与身份冲突、
编辑后历史保持、重开不执行，以及格式迁移/备份。原生入口还需覆盖已有输入保护、过期回调丢弃、
草案来源刷新和不确定响应恢复；测试结果在开发计划中单独记录。

## 后续模型集成

下一步在已验证的上下文与草案接口上设计模型提供方、密钥配置、流式响应、工具调用和请求恢复。
持久消息不代表仍在运行的请求；生成请求、返回消息、草案保存和明确应用需要各自状态及来源关系。
恢复必须能区分未开始、进行中、失败、已返回和结果不确定，不能因缺少本地响应自动再次提交任务。
上下文压缩、文件附件与多设备会话同步另行设计与验收。
