# STK 主体的分布式科研工作台

更新：2026-11-03。状态：所有者已确定产品方向，本文记录目标、增量顺序和验收要求；
具体新增协议仍是设计，已发布的 `docs/specs/` 契约继续有效。实际实现与证据见
[开发计划](../development-plan.md)、[运行验收](../runtime-validation.md)和[当前交接](../../handoff.md)。

## 所有者已经确定的方向

STK 是平台主体，将已有科学前后处理、专业可视化、任务执行与 Synthrix 的 AI 对话和科研管理结合。
完整本地工作台汇聚本机、其他电脑和自有云主机的能力；Web 是托管资源和文献、数据容量受成本限制的轻量入口。
Web 可以调用用户已经连接并授权的节点。部署后的轻量 CLI 应能跨位置提交任务、观察状态、日志及产物。
框架参考 Synorder 的对话、文件、任务、能力分发与深度插件扩展，但现有 STK 原生工作台、公开协议和科学证据继续保留。

这次决定更新此前仅把 STK 当作 Synthrix 可选 Runtime 的产品定位。接入应先形成边界清楚的纵向闭环，
不以目录合并、界面嵌入或两套数据库直接互写代替功能融合。

## 部署与功能边界

| 部署 | 目标能力 | 数据与执行位置 |
|---|---|---|
| 完整本地 STK | 对话与科研管理、表格/节点/Python/Viewer、完整本地文献和数据、可用本地模型、Computer Use、远程任务 | 本机服务可独立工作；按能力和授权调用其他电脑或自有云 |
| 自托管团队部署 | 团队身份、科研复核、节点连接、任务路由、共享结果及能力目录 | 所有者配置的服务与节点；不要求官方云保存全部原件 |
| 官方托管 Web | 对话、科研记录、有限托管计算/索引/存储、任务和结果入口 | 默认使用托管额度；有授权连接时可把任务发到用户节点 |

本地完整版表示功能上限完整，实际执行仍取决于操作系统、安装的引擎/插件、硬件和用户授权。
当前 Runtime、Hub 和节点代理服务仍仅支持 Linux，Mac/Windows 客户端及 peer 原型不等同于完整跨平台执行节点。
新增跨平台节点按可用能力逐项实现和验收，不修改既有支持矩阵来冒充交付。

Web 的控制入口与任务执行位置分别建模。连接节点不自动上传其文件树、全文文献或完整数据库。
默认保留节点原件与本地索引；共享元数据、检索摘录、预览和产物须有明确范围、身份和当前授权。
私有数据禁止发送外部模型的既有规则继续有效，模型端点、密钥和网络策略仍只经明确桌面操作配置。

## 共同对象与事实归属

| 对象 | 必须明确的身份与责任 |
|---|---|
| 节点 | 稳定设备身份、当前连接代次、OS/架构、引擎/插件版本、CPU/GPU/内存、数据位置、可授权工具 |
| 工作空间/项目 | 所有者、当前修订、资源绑定；本地项目与科研团队项目可映射，不能把会话 handle 当永久 ID |
| 对话/Agent 会话 | 节点与工作空间绑定、消息和工具事件、所用模型、预算、人工决定、恢复身份 |
| 科学运行 | 冻结定义/输入摘要/执行环境、原操作和提交键、Runtime 任务身份、日志、用量、校验产物 |
| 科研证据 | 计算、实测、推断、合成的来源区别，单位/原始数值、版本、操作者、资产摘要和复核判断 |
| 能力包 | 稳定 ID/版本、完整内容摘要、依赖、操作和查询、权限、UI 扩展、安装和回退状态 |

运行状态由执行器核实；科研授权、预算、样品、实验、导师复核、四层判定由相应领域服务管理。
执行成功不自动升级为物理合理或专家通过。Agent 会话、科学任务、客户端连接的寿命分别记录；
关闭聊天、终端或浏览器不表示取消已接受的科学任务。

本地 SQLite 与团队 PostgreSQL 的持久化适配应保留相应事务与授权语义；先统一对象引用和操作契约，
不让两个数据库通过隐式双写争夺同一业务事实。跨设备打开项目副本、同步版本和多人协作也须分别验收。

## 节点与任务控制

复用现有 Runtime、Hub、出站节点代理、SSH 和 peer 的已有能力。协调服务负责认证、授权、路由和观察，
执行节点负责实际任务及本地数据。单机模式可使用本机协调，不引入必需的官方账号或云连接。
远程优先复用主动出站的认证通道；对等直连属于独立优化，不以打开公网端口代替接入设计。

任务路由考虑所需引擎、OS、CPU/GPU/内存、许可、数据位置、用户授权与资源预算。
首阶段通过独立任务、参数扫描和流程步骤共享算力；跨节点 MPI 或分布式训练仍由支持它的引擎实施。

提交前保存原操作身份、完整冻结请求、输入摘要、目标和资源上限。响应丢失后查询原任务，
不自动换 ID 重算。节点离线、任务未知、任务失败、取消意图和实际进程退出分别表示。
心跳列表是有界发现视图，不是持久任务存在性的权威；已知 ID 必须有精确状态读取路径。
日志和事件支持游标；产物下载验证大小与 SHA，恢复观察不重新运行。

CLI、Web、桌面、Python/SDK 和 AI 复用同一操作与校验规则。CLI 客户端不需要安装目标求解器或完整 GUI。
新增命令要明确本机/SSH/Hub 目标、固定操作身份、审批/排队、不确定状态、机器可读结果与等待退出码。
现有 `suan` 命令保持兼容；本文的未来命令形状不能作为已发布 CLI 承诺。

## Computer Use 与可替换 Agent

科学 API、CLI 和结构化操作优先；浏览器与桌面控制补充没有直接接口的流程。
`browser.control`、`desktop.control` 与普通文件/任务权限分开，并绑定具体节点和桌面会话。
无头节点不声明不存在的图形能力；节点在线不意味着用户已登录、窗口可控或屏幕状态仍匹配。

Agent 的会话、工具协议和执行环境应可替换，避免把某模型供应商的 thread ID 当 STK 科学运行身份。
模型建议不替代授权；屏幕、PDF、网页或插件返回的内容不授予执行权限。
准备/运行/发送/保存仍是明确操作，旧 S2c Agent 权限待决项保持，不从本次方向决定推导自动批准。

## 插件与能力分发

稳定壳提供对话、资源、任务、项目引用和能力目录。领域包通过统一目录声明：

- 类型与对象引用、只读 Query、带权限/副作用/回执/恢复语义的 Action；
- 科学引擎、数据连接器、图节点、工作流、检索服务和 AI 技能；
- 通用声明式卡片/表单，以及 Viewer、节点画布、科研工作台等专用深度 UI 模块；
- 版本、依赖、内容摘要、安装授权、兼容范围、升级迁移与回退。

Synthrix 的对话和科研管理业务逐步接入这一体系，保留实验/导师复核和来源约束。
Python 服务、原生编辑器和 Web 展示不各自建立一套业务写入规则。
当前 CMake 编辑器对象库不等于运行时二进制插件 ABI；现有原生文档视口也不等于可直接运行完整 React 的通用插件宿主。
具体 UI 承载和持久化适配需独立技术验证，不先强制重写 C++ 或迁移整套前端。

能力市场先交付目录、受审安装、版本锁定、权限说明、升级回滚与离线分发；商业交易后续单独验收。
安装或导入不自动执行未知脚本，发现能力包不等于加载其可信服务代码。

## 增量顺序与完成证据

| 顺序 | 交付 | 必须核实的证据 |
|---|---|---|
| 0 | 稳定已有 WIP、文献 profile/服务、复现 I/O 与平台补修 | 当前源码的回归、真实本地资产、失败历史、包来源与实际 CI；保留旧检索质量失败 |
| 1 | CLI 经现有 Hub 选择节点并长期追踪任务 | 审批/未知响应保原键；超出心跳列表的旧任务仍可读；日志/产物/取消与直连/SSH兼容 |
| 2 | 共用对象/操作与最小能力包契约，持续跨平台节点增量 | 发现与权限一致；缺能力明确；节点重启、撤权、断线和来源变化反例 |
| 3 | Synthrix 科研服务与对话接入、本地部署闭环 | 原始数值/单位/摘要一致，计算与实测分离，独立导师复核，重开与来源报告可核验 |
| 4 | 本地文献/数据与授权检索、Computer Use、多节点流程 | 原件留节点；明确授权的查询和控制；拒绝陈旧会话；两节点参数扫描真实执行 |
| 5 | 轻量云配额、插件分发、离线安装与完整发行 | 干净机、Mac/Windows/Linux能力矩阵、预算/存储/传输边界、升级回滚及端到端验收 |

旧八项通用路线继续覆盖：表格/节点、工作台与技能、P4 报告、S3 训练、S4 协作、S5 文献、S6 真实复现、P5/S7 发行。
本方向重新组织其共同底座与交付顺序，不删去真实 MuPRO 论文、硬件 GPU/IME/DPI、跨站网络、独立留出评价、
toolkits 兼容整合和 ABACUS 按依赖接入等原完成条件。PET 新专项继续后置。
合作方 S3 格式/MuPRO 电场扫描、S2c 权限、分析修改提案持久形式仍待所有者决定，不选未批准选项。

首个跨入口验收：电脑 A 执行固定小算例，电脑 B 的 CLI 与 Web 读取同一运行；丢回复、客户端退出、
协调服务重启后不重复启动，节点断线保持待核实，重连按原凭据恢复；结果进入科研记录并在 STK 中分析。
新 UI 按固定起点记录实际点击数，并保护 Viewer 和全部隐藏草稿。

## 调研依据（2026-11-03 已读取）

- [Codex app-server](https://learn.chatgpt.com/docs/app-server)：多客户端会话/事件/审批协议；
  [自托管执行环境](https://developers.openai.com/api/docs/guides/agents-api/environments/self-hosted)：执行器主动出站。
- [Claude Code Remote Control](https://code.claude.com/docs/en/remote-control)：控制入口与原机器执行分离。
- [OpenCode Server](https://opencode.ai/docs/server/) 与 [Web](https://opencode.ai/docs/web/)：共享会话服务；
  [OpenHands 架构](https://github.com/OpenHands/OpenHands/blob/main/docs/architecture.md)：多 Agent Server 与 UI 分离。
- [GitHub self-hosted runner](https://docs.github.com/en/actions/reference/runners/self-hosted-runners)：标签/分组路由与出站连接；
  [gh run watch](https://cli.github.com/manual/gh_run_watch)：跨入口观察和失败退出码。
- Synorder 只借鉴对象服务、统一操作、能力包锁与执行器边界；当前 SDK 的深度 Code UI 有设计内容，
  社区目录不等于已上线交易商城。STK 内旧 Synorder 插件不是当前框架权威，亦不形成必需外部宿主依赖。

上述调研证明可借鉴的机制，不证明 STK 当前已实现目标架构。公开仓库文档不包含私有框架源码或身份配置。
