# PET 研发数据字典草案

更新：2026-10-13；字典版本 `pet-data-dictionary-draft/0.1`。本文落实
[材料数据闭环节点 1](pet-materials-data-loop.md#交付顺序与验收节点)的业务字典与合成导入样例。
这是设计草案，**不是已发布的数据契约或项目格式**；普通项目仍使用格式 13，
[已发布协议](../specs/)和[项目模型](project-model.md)仍是实现依据。
专用关系校验、材料业务界面、权限和训练契约留待后续节点。

## 身份与最小关系

先复用通用表、字段、记录、引用、修订、文件索引与输入快照。展示名称不作为身份。
业务 `id` 保留来源中的稳定标识；项目记录/字段 UUID 是项目内引用身份，两者的映射随导入回执保存。
导入相同 CSV 会创建新的普通表和 UUID，**现有 CSV 导入不提供业务去重、合并或身份解析**。
关联是可回查关系，不表示执行任务；任何计算或训练仍需要各自的准备和开始动作。

| 对象 | 最小字段 | 关系与含义 |
|---|---|---|
| 材料 | `id`、名称、预期材料族、说明 | 研发对象；不是单个制备批次 |
| 配方版本 | `id`、`material_id`、版本、计划组成、实际组成 | 计划和实际分别记录；实际组成尚无证据时为未知，不复制计划值 |
| 制备批次 | `id`、`formulation_id`、制备状态、过程说明 | 同配方的独立制备分别登记；失败记录仍保留，不虚构样品或数值 |
| 样品与分样 | `id`、`batch_id`、`parent_sample_id`、样品角色 | 分样保留父样品和原批次；不同分样不冒充独立制备 |
| 状态事件 | `id`、`sample_id`、顺序、状态类型、接触介质、条件 | 干燥、接触、脱附分别追加；顺序不代替真实时间和暴露程序 |
| 原始观测 | `id`、材料/状态/批次、依据观测、来源类型、值/单位/值状态、原始资源、说明 | 原曲线、仪器文件或文献位置是证据；推断关联依据；未知与失败不填零 |
| 处理记录 | `id`、`observation_id`、方法版本、结果/单位/状态、排除理由 | 每条处理保留输入和固定方法；纠错追加版本，冻结结果不改写 |
| 复核与用途 | `id`、`processing_id`、复核人、状态、允许用途、依据 | 专业意见与用途准入分开；姓名或对话角色不能代替认证身份 |
| 材料决定 | `id`、材料/配方、复核依据、决定、理由、下一轮任务 | 保留继续/调整/排除依据及缺口；决定不是自动执行授权 |

原始资源复用现有文件索引，保留稳定资源 UUID、项目相对路径、内容摘要和快照。
上述业务版本、追加修订和用途规则是规划语义，当前普通表仍可编辑，本例未强制执行这些规则；
已有文件快照保存独立内容，不因普通编辑改写历史对象。
生产字典后续还需明确文献定位/许可、实验或计算执行、复核修订、观测到多个证据及决定到多个证据的关系。
本例一条处理对应一条观测、决定引用一条复核，只演练最小单链，不能表达所有多证据场景。

## 来源、缺失与适用条件

每条业务记录保存 `source_kind`：

| 值 | 定义 |
|---|---|
| `literature` | 已取得的文献内容，保留原文位置、访问/许可与实验或计算条件 |
| `calculation` | 实际执行的计算，保留输入、方法/软件/参数版本和结果证据 |
| `measurement` | 实际测量，关联样品状态、仪器/方法、条件与原始曲线 |
| `inference` | 由证据形成的解释或假设，关联输入及方法，不能冒充直接测量 |
| `synthetic` | 软件演练或合成数据，不能支持真实材料验证和实验预测准确度 |

字典中的来源描述证据性质，不能解除厂内部署要求。混合证据分别登记，不以一条“实测”标签覆盖计算和推断。
后续推断记录还应保留人工/专家/模型等产出者类型、方法或模型版本与输入证据，
同一个 `inference` 分类不能抹去专家判断和模型预测的区别。
本例**所有**业务记录、曲线和说明实际为 `source_kind=synthetic`，且逐条 `synthetic=true`。
`represented_source_kind` 仅说明演练的文献/计算/实测/推断角色；不是证据已经取得的声明，也不是生产契约字段。

数值列明确声明 `number` 或 `integer`，JSON 的 `null` 和数值 CSV 空格导入为 `None`。
文本 CSV 空格导入为 `""`，因此本例仅将空文本关联解释为“未指定”，并不声称已有业务空值校验。
`value_status` 分开保存缺测、失败、未量化和合成可用值；零是数值，不能表示未知。
质量鉴别、来源/单位核对、计算收敛、实测重复性和独立批次验证仍是不同维度。

本例曲线只有点序号和无量纲人工响应，单位 `1`，不是 Tg、模量、扩散、回弹或接触实验结果。
真实曲线必须保存时间轴和物理量/单位，材料组成、温度、频率、应变率、几何、取向、热史与接触条件依任务补齐。
未指定介质与条件明确记录为 `not_specified`；没有酒液配方、阈值或合格判据。
单位变换、条件差异和用途准入的自动校验属于后续工作，当前通用文字字段不能替代它们。

## 节点 1 的可运行演练

[离线样例](../../examples/pet_data/README.md)将九张小 CSV 表导入用户指定的新项目，
用现有 `set_reference` 将外部身份标识替换为项目内记录/字段 UUID 引用。
原始文件和导入清单全部复制到项目相对目录，并通过已有文件索引与快照冻结。
回执保留业务标识到 UUID 的映射、文件摘要和快照身份；重新打开、重命名展示名称或移动项目仍可回查。
CSV 值导出会物化引用，不能作为关系或项目备份；完整移动需要项目数据库和文件目录一起保留。

夹具有两批完成制备的模拟身份、各一个父样品与分样、每个分样三种状态，另有一个失败制备记录。
人工曲线保留一个缺失末点；处理和复核保留缺测、失败与排除原因。两批、三状态是软件关系演练数量，
**不是材料统计充分性或独立训练评价标准**。

实施边界：不导入企业实际数据/聊天，不发送模型请求，不启动求解器或训练，不修改端点、网络或公开标注。
本例验收使用 ProjectStore API；桌面脚本门面及完整 UI 导入/导出路径不在本例验收范围。
节点 2 厂内边界验收之前，后续演练继续使用明确合成的夹具。
后续节点 3 需发布经过迁移/恢复验证的关系与状态校验；节点 5 需另行制定 PET 预测目标、
版本化数据集、批次分组、用途准入/复核版本及独立评价。本文不扩展现有 `stk.dataset/1`。
