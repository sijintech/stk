# 可移植工作空间

所有者要求表格可按 CSV、Excel、JSON 交换，并将当前桌面的全部窗口和参数打包到另一台机器恢复。
表格交换和工作空间迁移是两个独立入口：前者交换表数据，后者保存桌面会话与项目资源。
本地工作空间文件使用 **`.stkworkspace`**，容器契约为 [`stk.workspace/1`](../specs/workspace-1.md)。

桌面通过文件菜单直接导出或导入工作空间，无需先打开项目。导出选择一个新文件；导入先核验预览与资源诊断，再选择新的目标目录并明确采用。
已导入目录可再次搬移，通过文件菜单打开该目录或其中的 `workspace.json`，无需保留原包。

## 迁移对象

一次明确导出捕获所有窗口、各窗口中的全部编辑区域和隐藏标签、布局和可序列化编辑器状态。
桌面层提供 `stk.desktop.workspace-state` 第 1 版状态：窗口布局、项目选择、Viewer 设置及当前资源引用。
编辑器的工作空间 hooks 独立于日常布局保存；因此可携带项目表格、节点和工作流的未保存编辑稿，
而不把这些编辑稿自动写入项目，也不把它们加入普通启动布局。
分析编辑器还分别保留结果列表选择和已固定的历史图身份；恢复只读本地记录与已收集结果，重建浏览位置和表格选择。
历史图可在原可变分析被删除后继续恢复，定义读取失败保留分离稿与诊断，不反复请求或自动运行任务。

工作空间可没有已打开项目，例如只打开 Viewer、Python 和技能库的桌面。
有项目时，包中包含当前项目的 SQLite 一致备份、公开项目目录中的输入和结果文件、
`.stk/objects` 中的冻结输入，以及 `.stk/analysis-runs` 中已收集的分析结果。
显式选择的 Viewer 文件或目录可作为独立资源打包，项目和资源中的空目录由独立清单保存。项目文件 UUID、表格视图、快照、分析和工作流来源保持原有身份。
各编辑器通过独立资源 hook 声明已打开输入；Python 页已打开的外部 `.py` 同时携带磁盘版本与当前缓冲区草稿，
导入后重定位源文件路径，保留原 SHA 保存冲突检查。尚未打开的路径框、输出目标和文件树浏览目录不据此递归读取。

恢复是一个新会话：保留参数和本地编辑稿，重新绑定新机器上的项目开口与本地路径。
导入过程不提交、恢复执行或取消任何 Runtime 任务，不运行 Python、分析图、材料模拟或模型请求。
正在运行的进程、SSH 会话、线程、GPU 上下文和远程服务不能随文件迁移。
原项目中的运行来源和签名链保留为历史，新的运行仍需在目标机器明确选择环境并启动。

## 资源和路径

可读范围只有当前项目和调用者明确列出的资源。遇到状态中的未知绝对路径，后端保留该参数并给出诊断，
不会根据任意字符串递归读取文件系统。已登记的外部项目文件需要桌面入口明确列为打包资源。
显式目录资源支持 Viewer 的 manifest 与 blobs 整体迁移；目录内部仍遵守文件类型和路径规则。

状态中的已识别路径转成 `stk-project://` 或 `stk-resource://` 引用。
导入到全新的目标目录后，项目位于 `project/`，外部资源位于 `resources/`，
`workspace.json` 保存可搬移的状态与原始路径映射。再次移动该目录时，按当前位置重新计算映射。
项目根与资源可保留有上限的旧路径 aliases，再次导出会继承原始和中间机器来源；
同一文件新旧登记路径可继续指向同一包内内容，二次、三次迁移不改 UUID 与历史。
项目数据库中的历史来源字符串不全局替换，以免改变冻结清单、运行计划或哈希链。
需要使用旧外部文件位置的项目读取器通过工作空间路径解析器获得新的本地位置。

绝对路径的处理采用精确匹配或明确资源目录的最长前缀匹配，不改写 Python 程序正文、普通文本段落或 JSON 编辑框内的路径子串。
这些文字保留原样；执行前的路径修改仍需用户在对应编辑器确认。原机器的可执行程序和依赖库不随包安装。

## 明确的恢复和完整性

导出输出不覆盖已有文件，目标包应放在被打包的项目和资源目录之外。
SQLite 通过在线备份读取明确修订；文件在读取前后核验身份、大小和修改时间，最后重新检查目录清单和项目修订。
若导出期间观测到更改，拒绝发布；这是文件一致性检查，不是暂停仿真或文件系统的事务快照。

预览会核验全部文件的大小、CRC 和 SHA-256，并显示项目、文件总数、字节数和资源诊断。
导入可携带预览的包 SHA-256，避免用户预览后源文件被替换。
完整包可直接明确导入。不完整包保留诊断，桌面应要求用户明确选择恢复现有状态；不能将其标为完整复刻。
某些诊断指向尚未存在的导出目标路径或缺少的远程结果，此时仍可恢复其他已携带内容。

导入在私有临时目录完成路径、摘要、状态与数据库身份校验，再原子发布到一个新目录。
已有目标目录即使为空也拒绝覆盖。失败时清理临时文件，不修改原包和原项目。
UI 也须在替换现有窗口前完成候选状态验证，并保护当前 Viewer 与未保存稿。

## 安全状态边界

不收集主机模型端点、密钥、网络策略、Runtime 凭据、SSH 私钥或用户配置目录。
工作空间状态拒绝具体凭据键；普通科学参数如 `key`、`token` 和名为 `endpoint` 的数值端点参数可保留。
Jobs 只保存提交参数表单与本地展示状态，不保存环境变量、连接凭据或待重试的提交。
AI 编辑器只恢复未发送稿和用途，不自动发送问题或迁移模型配置。

软链接、Windows reparse point、设备、FIFO、ZIP 路径穿越、重复成员、大小写或 Unicode 规范化后碰撞、
加密成员和不支持的压缩方式均拒绝或在导出时明确排除。默认总展开内容预算为 8 GiB，文件数不超过 20000。
完整边界和参数见版本化契约，不用扩展名作为可信判断。

## 实现与验证状态

后端实现为 `suan/project/workspace_bundle.py`，不依赖 Runtime、模型客户端或原生图形环境。
工作空间后端、bridge 和重定位共 **112 项**，已包含在 Python 3.11、3.12、3.14 各 **238/238 通过**的相关验证中，零失败、零跳过；
测试明确清空 `STK_TOKEN_PLAN_API_KEY`、取消 `STK_TOKEN_PLAN_MODEL`。
覆盖项目与冻结对象、无项目、外部 Viewer 目录、二次搬移重开、可信系统根别名与普通用户链接隔离、未知路径不读取、敏感配置排除、
修订冲突、源文件和目录清单变化、预览摘要绑定、无覆盖发布竞态、恶意 ZIP、私有输出权限、空目录、伪造目录清单及多次迁移别名。

原生编辑器的独立工作空间 hooks、菜单入口与异步恢复已实现；原生编译、异步编辑器恢复、跨平台 CI 和实际点击验收由本次交付的
[运行验收记录](../runtime-validation.md)记录；本文件不将尚未完成的验证写成通过。
导入恢复参数不等于在新机器获得相同的显示器、字体、DPI、渲染驱动或计算引擎环境。
