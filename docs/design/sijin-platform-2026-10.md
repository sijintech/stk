# 思劲平台方向：STK 承载材料智能体、联邦学习与领域知识库（方案）

更新：2026-10-09。状态：**所有者已答复三轮（见“所有者决定”），第二轮评估的决定已定；按 S1 → S7 推进，S1a–S1c 已交付；其余均未实现。** 来源：所有者 2026-10-08 对 STK 后续方向的描述。

## 一、所有者描述的目标（复述，供核对）

1. **材料智能体**：在 STK 中部署一个智能体，专门做材料计算和材料相关数据分析。
2. **联邦学习的商业模式**：与学校合作。课题组安装 STK 客户端，按思劲的要求准备数据；客户端自动用这些数据以联邦学习的方式
   训练思劲的**机器学习神经网络模型**（不是大语言模型）。数据留在课题组，训练出的模型可以被思劲使用。
3. **文献管理与知识库**：在公开资料中检索文献标题和摘要 → 在校内下载全文 → 通过客户端上传到统一的知识库 →
   做 RAG / 知识库搭建，积累领域知识。
4. **复现验证**：利用课题组资源，检验文章中的模拟实验场景能否复现，以此判断文章质量。
5. **本地交付与持续迁移学习**：整套智能体系统在客户本地交付；每当有新数据进入系统，就在思劲已有的材料预测模型上做迁移学习，
   用新数据不断迭代优化模型。
6. **客户端需要的能力**：
   - 分布式、可通信：能在校园网内网之间进行点对点通信，支撑联邦学习；
   - 内置智能体 harness，底层模型通过 API 调用，默认使用第三方官方 API；
   - 一键在本地部署安装合适的模型：大机器上部署不量化的大模型，笔记本上部署量化的小模型；
   - 可设置是否允许访问外网；
   - 智能体能按能力自动切换不同的模型。

## 二、需要先确认的理解

- 原话“在 **SDK** 里面部署一个智能体”，按上下文理解为 **STK**（同一段话其余处都说“STK 客户端”）。
- “默认使用第三方官方提供的那通”：不确定指哪一家。现有代码只接入了阿里云 Token Plan（`aliyun-token-plan/1`），见第八节第 2 条。
- “思劲已有的机器学习材料预测模型”：我不知道这些模型的任务、网络结构、训练框架、权重格式和输入数据格式，见第九节。

## 五、各部分方案

### 5.1 模型接入、本地一键部署与自动切换（S1）

- **统一接口**：智能体的所有模型调用都经“模型网关”。提供者分两类：官方 API（已有阿里云 Token Plan，再加任意 OpenAI 兼容端点，
  如 DeepSeek、通义等）与本地运行时。常见的本地运行时（llama.cpp server、Ollama、vLLM）都提供 OpenAI 兼容接口，
  因此网关只需一种协议（含工具调用）。凭据沿用现有做法：环境变量或 0600 文件，不进项目、日志与请求记录。
- **一键本地部署**：
  1. 硬件探测：CPU、内存、GPU 型号与显存、磁盘、操作系统；
  2. 推荐档位：多卡大显存服务器 → 不量化的大模型（vLLM）；单卡工作站 → 中等模型（FP16 / INT8）；笔记本 → 量化小模型（4 位 GGUF，llama.cpp）；
  3. 安装运行时（提供离线包与国内镜像源，例如 ModelScope）；
  4. 下载权重并校验 SHA-256，记录许可；
  5. 启动、健康检查、登记到“本机模型目录”。
  模型目录列出参数量、量化方式、所需显存或内存、许可与能力标签（工具调用、上下文长度、中文、代码）。
- **自动切换**：按能力分档（小：本地、快、可处理私有数据；中；大：推理强），路由依据为任务类型（问答、工具规划、代码、文献摘要、嵌入）、
  数据敏感级别、网络策略、可用性与成本。失败或超时时回退，用户可固定某个模型。每次调用记录所用模型，供审计与复现。
- **网络与数据策略**：
  - 三档网络：离线（只用本地模型、不访问外网）／只访问指定端点（内网或白名单）／允许外网；
  - 网页检索、文献下载等工具另有开关；
  - **数据边界**与网络开关独立：标为“私有”的数据（数据集或项目级）永远不发给外部模型 API，即使允许外网。新数据集默认为私有。

### 5.2 智能体 harness（S2）

- **工具面**：现有 `stk.*` 脚本 API 与技能目录（项目、表格、工作流、运行、分析、技能；以后加数据集、模型、文献），
  可经内置工具描述或 MCP 暴露。每个工具标注副作用级别：只读／生成草案／提交运行／访问外部网络。
- **安全边界**：智能体只提议，修改项目经现有草案与审阅；提交运行按策略确认（例如本地轻量计算可自动，集群作业需确认）；
  每一步（对话、工具调用、所用模型、输入摘要、结果）记入项目，可回看。
- **首批材料能力**：MuPRO / MuFerro 模拟的准备与结果分析（已有链路）、材料数据表的统计、拟合与可视化；
  S3 之后加材料性质预测，S5 之后加文献检索与引用。
- **与现有 AI 助手的关系**：现在的 AI 助手是单轮、只读上下文；harness 是多步工具循环，复用请求记录、草案与用量统计。

### 5.3 数据集规范、本地训练与迁移学习（S3）

- **数据准备规范**由思劲给出，落成数据集契约（例如 `stk.dataset/1`）：组分、结构文件、工艺或模拟参数、性质与单位、来源、许可、敏感级别。
  校验器在客户端本地运行，生成只留在本地的数据卡（统计、缺失、分布）。
- **本地训练运行器**：PyTorch 训练作为 Runtime 任务执行（排队、日志、取消、产物）。
  模型登记（版本、基模型、训练数据摘要哈希、指标、许可）放在项目中。
- **迁移学习**：在思劲基模型上微调（如冻结骨干只训练输出头，或全量微调）；以留出集与基模型对比，过评估门槛才替换，可回滚。

### 5.4 网络与联邦学习（S4）

- **连接方式**：沿用 hub 的模式——课题组节点**主动出站**连接思劲的协调服务（或客户自建的协调服务），用 TLS / WSS 完成身份认证、配对、
  中继与聚合。校园网一般允许出站 HTTPS，不需要开放入站端口。之后在可行时增加节点之间的点对点直连
  （打洞，失败时回落到中继），用于大文件或节点直接交换。部署须经校方网络管理同意，不绕过校园网的安全措施。
- **身份与授权**：节点密钥与证书、现有配对码机制；每个参与方的数据使用授权按数据集逐个开启（opt-in），可随时退出。
- **联邦学习**：先做 FedAvg / FedProx，只上传模型更新（权重差），可选安全聚合（协调服务看不到单个更新）与差分隐私；
  每轮记录参与方、样本量、指标与发出的内容摘要，课题组可审计“离开本组的是什么”。
- **框架**：评估见[联邦学习框架评估](fl-framework-evaluation-2026-10.md)：没有现成框架满足全部需要；建议把 Flower 当作算法库（含 SecAgg+ 与差分隐私），通信、身份、审计与调度由 STK 的出站通道负责（Flower 的传输不能直接替换，需要写适配层）。

### 5.5 文献与知识库（S5）

- **检索**：公开元数据源（OpenAlex、Crossref、arXiv、Semantic Scholar；知网等须在授权范围内）→ 标题、摘要、DOI、引用关系。
- **下载**：在校内由用户本人用机构权限下载全文到本地文献库；客户端不自动绕过付费墙。开放获取（OA）论文可直接获取。
- **解析**：PDF → 结构化文本（GROBID、MinerU 类工具），抽取方法、参数、结果表格，可人工校对。
- **知识库分两层**：
  - 本地层（课题组或客户本地）：全文索引与向量检索；
  - 统一层（思劲侧）：在许可允许的范围内存元数据、摘要、开放获取全文、抽取出的事实与参数、用户笔记和嵌入向量。
  付费全文能否集中存放需要法律确认（第八节第 7 条）。
- **RAG**：回答必须给出出处（文献与段落），结果可被智能体引用。

### 5.6 复现验证与文献质量（S6）

- **流程**：从文献抽取模拟设置（方法、材料参数、边界条件、网格、温度等）→ 生成 STK 工作流或批次 → 在课题组资源上运行 →
  与原文结果对比（数值容差、曲线比对）→ 复现报告与评分。评分考虑参数是否齐全、结果能否复现、对未给出参数的敏感性。
- **起点**：先从 MuPRO 已支持的问题（如铁电畴）开始，因为运行与分析链路已完整。
- **定位**：评分是辅助判断，不代替同行评议；报告列出缺失信息与所做假设。

### 5.7 本地交付与持续迁移学习（S7）

- **交付包**：桌面客户端，加 Linux 服务端（Runtime、协调服务、本地模型运行时、知识库、训练运行器），加基模型与本地语言模型；支持离线安装。
- **持续迁移学习**：新数据入库 → 校验 → 按策略（定时、数据量阈值、手动）触发训练 → 评估门槛 → 新版本 → 可回滚。
  模型更新与指标是否回传思劲按合同约定，默认不回传。
- **模型保护**：交付到客户本地的基模型权重属于思劲的知识产权，需要确定保护程度（许可校验、加密存放、水印）。
  完全防止提取不现实，要与合同条款配合。

## 六、必须写进设计的约束

- **数据**：课题组数据不离开课题组，离开的只有模型更新；参与按数据集逐个授权，可退出；每轮发出的内容可审计；
  标为私有的数据永不发往外部模型 API。
- **网络**：节点只做出站连接，点对点直连属于可选优化；部署须经校方网络管理同意。
- **文献版权**：付费全文的下载与集中存放受出版商许可约束，统一知识库默认不集中存付费全文，具体由法律确认。
- **合规**：涉及个人信息与重要数据时，遵守《数据安全法》《个人信息保护法》及学校的数据规定；与学校签数据使用协议。
- **模型来源与许可**：本地部署的开源大模型逐个记录许可（部分模型禁止商用或有用户数限制）。
- **可追溯**：智能体每一步、每次模型调用、每次训练与联邦轮次都留记录（沿用 STK 现有的“冻结、可审计”做法）。

## 八、需要所有者决定

1. **理解确认**：“SDK”即 STK，智能体部署在 STK 中（桌面客户端加 Linux 服务端）。（建议：是）
2. **默认模型 API**：“第三方官方 API”默认用哪家？建议默认沿用已接入的阿里云 Token Plan，并允许配置任意 OpenAI 兼容端点。
3. **本地模型运行时**：建议笔记本与工作站用 llama.cpp（GGUF 量化），GPU 服务器用 vLLM（不量化或 FP8），统一经 OpenAI 兼容接口接入。
   另一种做法是全部用 Ollama（安装简单，但大模型多卡部署弱）。
4. **分期顺序**：建议 S1 → S2 → S3 → S4 → S5 → S6 → S7。理由：模型接入与智能体单独就有用、风险低；联邦学习需要合作协议与数据规范到位。
   如果联邦学习是最先要向学校展示的能力，可改为 S1 → S3 → S4 → S2 …。
5. **联邦学习框架**：建议用 Flower 的策略与客户端接口，传输走 STK 已有的认证出站通道；或者完全自研（可控但工作量大）。
6. **网络方式**：建议先做“出站连接到协调服务加中继”，点对点直连作为后续优化；协调服务由思劲托管，也支持客户自建。
7. **文献全文**：建议付费全文只留在课题组或客户本地，统一知识库只存元数据、摘要、开放获取全文、抽取的事实与嵌入；是否集中存全文待法律确认。
8. **数据边界**：建议“私有数据永不发往外部模型 API”作为不可关闭的规则，新数据集默认私有。

## 所有者决定（2026-10-08）

1. “SDK”即 STK，智能体部署在 STK 中。
2. 默认模型 API 按建议：沿用已接入的阿里云 Token Plan，并允许配置任意 OpenAI 兼容端点。
3. 本地模型运行时按建议、取最方便的安装方式：笔记本与工作站用 llama.cpp（GGUF 量化），GPU 服务器用 vLLM，统一经 OpenAI 兼容接口接入。
4. 按 S1 → S7 的顺序推进。
5. （评估见[联邦学习框架评估](fl-framework-evaluation-2026-10.md)）联邦学习框架**先评估现有框架能否满足需要**，再决定用现成框架还是自研（评估在 S4 之前完成）。
6. （评估见[节点跨校园网组网评估](node-networking-evaluation-2026-10.md)）节点通信需评估：类 P2P 的方式；WireGuard 或 ZeroTier / Tailscale（理解为原话“zeroscale”）一类的虚拟组网；Shadowsocks 一类的代理技术。
   评估时注意：Shadowsocks 主要用途是伪装流量、绕过网络过滤，不是组网工具，用于校园网或跨境存在合规风险，预计不推荐。
7. 付费全文**只留在客户本地**；用类似 BitTorrent 的方式共享：有人需要下载查看时，持有者负责上传自己有的部分。
   机制按内容寻址分块、按需由持有者提供；付费全文跨机构共享仍属于把副本交给他人，默认只在开放获取文献与同一机构内启用，
   跨机构共享付费全文待法律确认。
8. 数据默认不对外发，只有人工标注为“公开”的数据才可以发给外部模型 API。

补充（2026-10-08）：思劲**目前还没有自己的材料预测模型**，计划训练两个：**铁电**领域的预测模型与**锂电池**的预测模型。因此：
- S3 先做“从零训练”（数据集、训练运行器、评估、模型登记），迁移学习是其后的一步；
- 铁电模型可以直接利用 STK 已有的 MuFerro 相场模拟链路：参数扫描与按行工作流运行能批量产生带标签的模拟数据，作为预训练或数据增强来源；
- 锂电池模型的数据来源、预测目标与模拟工具（如有）需要另行确定；
- 联邦学习（S4）的第一个场景建议选铁电模型，因为数据格式与模拟链路都已在 STK 中。

## 所有者决定（第二轮，2026-10-08，针对两份评估）

1. 联邦学习采用评估中的 A：Flower 只作算法库，通信、身份、审计与调度由 STK 自己的通道负责。
2. 把 STK 及其 Web 框架升级到 Python 3.11 以上，使 Flower 与 STK 可装在同一环境（具体版本约束待核实：Flower 锁定的 Web 框架版本可能比 STK 现在的更旧）。
3. 训练节点暂按推荐用 Linux；将来自研联邦学习框架时再支持 Windows。
4. 每轮至少三个课题组；首批测试与合作方在北京、珠海、聊城的三个课题组一起进行。
5. 学校不会开放端口，节点之间必须先以内网穿透的方式建立连接。（说明：评估中“只做出站连接”本身不需要学校开放任何端口——
   节点主动连到思劲的公网服务，RustDesk、ZeroTier 的内网穿透也是先连公网会合服务器、再打洞直连、打不通时中继；具体方式另行评估。）
6. 文献由各课题组自己保存在组内的 Linux 服务器上。
7. 文献不经思劲中转，课题组之间直连；可以晚些再做。
8. 必须采用某种内网穿透方式，可参考 RustDesk 或 ZeroTier（另行评估）。
9. 中心服务与中转放在思劲的服务器上。
10. 默认不做跨机构共享，只允许“借阅”：别人要看文章，只能远程连到持有文献的 STK 客户端上查看，不能把文献下载到自己那里。
11. 新需求：像 VS Code Live Share 那样，可以共享某个对话、作图给别人看，也可以共享页面让别人直接看自己的操作，参与者之间可以语音和文字交流。
    排期待定（建议在节点间连接打通后做，复用同一套穿透连接）。

## 第二轮评估结论（2026-10-09，待所有者决定；均未实现）

四份评估：[内网穿透](nat-traversal-evaluation-2026-10.md)、[共享会话](live-share-evaluation-2026-10.md)、
[文献借阅](literature-lending-evaluation-2026-10.md)、[Python 3.11 与 Flower](python311-flower-upgrade-2026-10.md)。
每份都经独立核查（对照源码、许可文件与条文），错误已在文中改正；涉及法律的内容只是交给律师的问题。

- **连接**：内网穿透的每一步都由校内主机向外发起，学校不需要开端口。RustDesk 客户端与服务端是 AGPL-3.0，不能嵌入；
  ZeroTier 1.16 起控制器连高校、非营利组织的使用也算商业使用，且要虚拟网卡（校方视为 VPN）。建议用 WebRTC 作会话层
  （ICE 打洞，思劲自建 TURN over TLS 443，DTLS 端到端加密），借阅与共享会话共用；iroh 作备选。直连不能保证
  （公开测量约七成，中国校园网无数据），须在北京、珠海、聊城三校实测。
- **文献直连失败时**与第 7 条（不经思劲中转）有冲突：只能 (a) 拒绝这次借阅，或 (b) 经思劲服务器上端到端加密、不落盘的中继（思劲看不到内容）。
- **共享会话**：参照 Live Share 的权限模型（邀请、审批、只读、移除、跟随），先做文字聊天与结构化共享（对话、作图），再做语音与窗口共享；
  媒体栈建议自托管 LiveKit（Apache-2.0），但其预编译 C++ 包含 H.264/H.265 代码，对外分发前要法律意见。
- **文献借阅**：只能做到“不交付文件”——持有者节点只发带实名水印、限分辨率的页图（渲染用 pypdfium2），不发 PDF 与文本层。
  出版商合同是主要障碍：订购方是学校（对外借阅须图书馆书面同意）；爱思唯尔 2026 版第 1.5.3 条禁止把文献交给外部 AI、禁止商业使用 TDM 产出、
  禁止公开由其得出的模型权重——**这同样约束 S5 知识库与用文献训练模型**，不只是借阅。
- **Python 与 Flower**：下限提到 3.11 代价很小（3.11 上全部非桌面测试通过），应当做；但与 flwr 1.33–1.39 同环境须把
  fastapi/starlette/uvicorn 降到 0.138.2/1.3.1/0.49.0，并引入有已知高危公告的 cryptography 46.0.7。Flower 的 SecAgg+ 掩码用 32 位种子的非密码学随机数
  （issue #7522，未修复），修复前不能当作隐私保证；flwr 默认开启遥测与更新检查，会连境外服务器。
- **贯穿各项**：桌面含 Blender 代码，只能按 GPL 发布；中继、TURN 与聊天涉及备案、增值电信许可与实名、日志留存，须法务确认；
  进校园网须征得三校网络中心同意，不设计任何绕开校方管控的方式。

需要所有者决定的事项（建议在括号中；2026-10-09 已逐项决定，见“所有者决定（第三轮）”）：
1. 连接层不嵌入 RustDesk、ZeroTier，改用 WebRTC（ICE + 自建 TURN/TLS 443）。（同意）
2. 接受直连只能尽力而为，先在三校实测，并请三校网络中心书面同意出站 443、UDP 与 IPv6。（同意）
3. 文献直连失败时：拒绝，还是允许经思劲端到端加密、不落盘的中继？请说明第 7 条是为隐私（中继可满足）还是为版权责任（交律师）。
   （默认允许中继，课题组可改为拒绝；公钥由课题组线下核对，不只信任思劲服务器）
4. 共享会话的顺序：文字聊天与结构化共享 → 语音 → 窗口共享；试点期语音先用各校已有的会议软件。（同意）
5. 共享中的私有数据：按“本次会话、本次接收方”单独授权并留审计，不改为公开；跨机构内容端到端加密；v1 不录制、不远程控制，跨机构加入须主机批准。（同意）
6. 文献借阅先做“陪读”，付费文献逐次人工审批；试点只用 CC 开放获取全文与作者接受稿；模型训练与知识库在律师意见前只用开放获取内容和自有数据。（同意）
7. Python 下限提到 3.11，默认部署用 3.12。（同意，可先做）
8. hub 不装 flwr、保持现有 Web 栈；联邦学习协调与训练节点在单独的进程与环境中运行 flwr——这修改了第 2 条“同一环境”的前提。（同意）
9. 安全聚合：SecAgg+ 修复前不对合作方宣称隐私保护；首批确需安全聚合时由 STK 自带修正的掩码生成器；所有部署关闭 flwr 遥测与更新检查。（同意）
10. 确认桌面按 GPL 发布；法律问题（出版商合同、版式设计权、个人信息同意、备案与电信许可、编解码专利）在对外试点前请律师确认。（同意）


## 所有者决定（第三轮，2026-10-09，针对第二轮评估）

所有者先答复三点，随后逐项选择了上面列出的决定：
- Flower 单独一个环境（保证安全）；对外的 hub 不装 flwr。（即原第 8 项。）
- 内网穿透：用思劲服务器辅助打通隧道，打通之后双方直接通信。说明：这就是 WebRTC/ICE 的做法——思劲服务器只做信令与 STUN（告诉双方各自的公网地址），
  双方同时发包打洞，成功后数据直连；GL.iNet 的 KVM 也是这样（其开源固件 [gl-inet/glkvm](https://github.com/gl-inet/glkvm) 用 Janus 做 WebRTC，
  STUN 在国内用小米的服务器，另有 TURN 中继账号用于打不通时）。若出站端口全部被封，任何方式都连不上；若只放行出站 TCP 443，只能经 TURN 在 443 上中转，不能直连。

逐项选择：
1. 连接层用 WebRTC/ICE：思劲服务器做信令、STUN 和 TURN；依次尝试 IPv6、UDP 打洞（加对称 NAT 的端口预测）、TCP 打洞，成功后直连；不嵌入 RustDesk、ZeroTier。
2. 不做前置的三校网络实测，直接开发、边用边测（产品内带网络自测与连接方式记录，用于了解实际走直连还是中继）。
3. 文献借阅打不通直连时，用端到端加密、不落盘的中继兜底（思劲看不到内容）；前提是公钥由课题组线下核对、三校网络中心同意。这修改了第二轮第 7 条。
4. 共享会话先做文字聊天与结构化共享（对话、作图），再做语音，最后做窗口画面共享；试点期语音先用各校已有的会议软件。
5. 共享中的私有数据按“本次会话、本次接收方”单次授权并留审计，不改数据标注；跨机构内容端到端加密；第一版不录制、不远程控制；跨机构加入须主持人批准。
6. 文献借阅先做“陪读”（持有者在场，节点只发带实名水印的页图），付费文献逐次人工审批；试点只用 CC 开放获取全文与作者接受稿；
   律师意见前，模型训练与知识库只用开放获取内容和自有数据。
7. Python 最低 3.11，默认部署 3.12。
8. 首批联邦学习不启用 SecAgg+ 安全聚合，向合作方说明思劲服务器能看到各组的模型更新（不是原始数据）；上游修复后再启用；所有部署关闭 flwr 遥测与更新检查。
9. 桌面按 GPL 发布；对外试点前请律师确认出版商合同、版式设计权、个人信息同意、备案与电信许可、视频编解码专利。
