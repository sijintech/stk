## 2. 验收环境与共同后端一致性

- **部署 A / B**：同一后端源码修订，分别使用本地 Core 配置和云端/团队配置；记录构建、领域模块、协议及仓储适配版本。
  两部署独立存储、各有对象归属；“同一后端”不表示共享数据库或允许两边同时执行同一写入。
- **客户端**：Web W1 发起任务，另一登录终端 Web W2 接续，Desktop D 使用原生 C++ / Python 查看完整结果；CLI C 作独立查询对照。
  同一部署中的各端必须读取同一任务事实；由 A 改连 B 不自动搬迁运行中任务。
- **执行节点**：L 安装经所有者授权使用的专业软件并有可用许可；G 有实际 GPU、驱动与后处理程序。L/G 可以同机，也须另测两台机器的交接。
  节点必须声明实际引擎、版本、资源和可用会话；在线、OS 标签或用户已登录都不等于可执行。
- **身份与数据**：所有者 U、授权协作者 V、未授权用户 X；公开合成算例、PDF 和已知摘要的结果基准。
  隐私负例使用合成标记，不读取真实私有项目。节点绑定、项目读取、执行、结果传输和模型出站分别授权。
- **执行前冻结**：用例版本、支持矩阵、预期结果/容差、超时、资源上限、布局及点击预算。未具备的依赖明确记为阻塞，不能临时删掉检查换取通过。

共同后端至少运行同一套契约用例两次：A 的本地部署一次、B 的云端部署一次。比较输入校验、授权、幂等冲突、状态转换、取消、审计、
产物引用及错误语义；仅对预先列明的生成 ID、时钟和部署地址做比较归一化，保留原值和关联映射。
配额或未安装能力可以不同，但必须由配置/能力声明解释，不能出现两套不同业务规则。各端语言或仓储适配器不同，不免除此项验收。

## 3. 固定布局、点击预算与草稿保护

每次 UI 运行先保存窗口大小、DPI、语言、可见区域、标签/分栏、滚动位置及数据状态。
主流程起点为已登录的项目任务页：测试工作流已安装，输入已登记，L/G 已绑定授权，但没有待提交任务草稿。
登录、绑定、安装和输入登记另列准备流程及实际操作数；不得把它们藏进“零点击”。
Desktop 起点为普通工作布局：Viewer 有固定相机和时间步，隐藏的 Python、表格、分析/流程页各有可辨认的未保存草稿。

## 4. 主场景：Web → 许可节点 → 换端追踪 → GPU → 原生结果

以下每步执行状态均为**未执行**。先在共同后端 A 完成，再在 B 使用独立任务与相同算例重复；不能把一次执行记成两个部署通过。

1. **预检与提交**：W1 选择冻结输入和参数，显式选择 L/G，显示软件、许可需求、资源/数据传输范围与预算。
   缺权限或能力时阻止运行。确认后固定原操作身份、完整请求指纹和回执，关联 Hub action、Runtime task 及执行尝试；这些身份不混用。
2. **许可执行**：L 在实际许可可用时启动专业软件。记录二进制/版本、许可检查与实际运行回执、受管进程身份、开始/退出和产物。
   不保存许可密钥。提交回执、入队或 `run.started` 都不能替代真实执行证据。
3. **客户端离开**：任务运行时关闭 W1/退出其观察会话。L 继续按已接受任务的策略执行；离开不产生取消命令或新执行尝试。
   同时记录后端和节点事实，以区别“观察中断”与“计算中断”。
4. **另一终端接续**：U 在 W2 登录，按原任务身份查看；CLI 查询作对照。状态、冻结输入、原回执和步骤归属一致。
   从已保存日志偏移/事件游标恢复，呈现观察缺口；查询、刷新、重连均不重新提交。任务即使已移出心跳最近 200 条也可精确读取。
5. **步骤交接**：L 的产物写入完成，验证大小、SHA、格式/单位和版本后才允许 G 消费。
   G 解析有授权的数据引用，不能直接把 L 的本地路径当成 G 可读路径；需要传输时只传获准输入，保留来源链。
6. **GPU 后处理**：G 使用声明的真实设备执行固定后处理，留存驱动/设备、实际执行观测、进程和结果。
   禁止把 GPU 标签、日志文本或 CPU 回退算作真实 GPU 通过；取消/失败时检查受管子进程和资源释放。
7. **双端结果**：W2 读取有范围限制的预览/轻分析，D 读取获准的完整数据做原生三维/Python 后处理。
   二者关联同一不可变产物及输入摘要，预览明确降采样/截断；数值、单位和探针来自原始数据，不能从配色反推。
8. **保存与重开**：显式保存研究记录和本地结果引用，关闭后重开可追溯原任务、软件、产物和复核状态。
   刷新/重开不启动计算或模型请求；Viewer、隐藏草稿和其他项目均保持。任务执行成功与科研复核结论分别展示。

真实计算的通过条件还包括：产物与预先批准的参考值、单位及容差吻合。若仅检查协议和可读产物，应标明未证明科学正确性。
监控事件遵守 [events v1](../specs/stk-events-v1.md)；程序自己的 `run.completed` 声明须与 Runtime 完成事实、退出和产物校验核对。
结果沿用 [data format v1](../specs/stk-data-format-v1.md) 的来源和单位约束；未支持的数据种类不能以本方案名义加入当前合同。

## 5. 失败注入与通过条件

每个用例单独记录注入位置、恢复动作、原身份和最终事实。下表是计划清单，尚无通过结果。

| ID | 注入/动作 | 必须观察到的结果 |
|---|---|---|
| F01 | 提交已持久化后丢失回复；冷重开后用原键/完整原请求恢复 | 返回原回执/任务；执行启动计数不增加。同键换输入/参数冲突；新计算必须显式使用新操作身份 |
| F02 | 相同键并发投递；不同键竞争同一流程修订 | 相同意图仅有一个接受结果；不同意图按版本/资源规则明确接受或冲突，无双写、无静默覆盖 |
| F03 | 节点控制链断开、Hub/协调服务重启、worker 在此期间完成 | 分开显示最后任务事实和观察可用性；恢复核对原任务，不将失联写成成功/失败，不自动换节点重算 |
| F04 | 任务未启动时节点离线；租约/授权到期或被撤销后旧连接回报/领取 | 未确认启动不伪称运行；过期代次不能授权新启动或覆盖新代次事实。原 attempt 的真实退出回执仍可按原身份核实入账，不能一概丢弃；记录离线继续执行与撤权延迟的明确策略及实际边界 |
| F05 | 队列取消、运行取消、取消回复丢失；子进程拒绝退出 | 取消意图幂等；只有核实受管计算退出后才显示已取消。无法确认时保持待核实，不提前释放仍占用的资源 |
| F06 | 许可不可用/到期/仅一席；两个本地或远程任务争用 | 不在无许可节点启动；按准入策略排队或明确拒绝。许可席位与实际软件 checkout/释放分开留证 |
| F07 | GPU 内存不足、设备消失、CPU/GPU/交互会话并发冲突 | 有确定排队/拒绝/失败原因，不静默降级。Web、Desktop 和 CLI 不绕开同一资源准入；检查失败后的释放 |
| F08 | L 输出半写、缺文件、错误 SHA、错误格式/单位；G 无读取权限 | 下游不启动；失败可定位到固定来源，不能采纳临时文件、相同文件名或任意节点路径 |
| F09 | 上传/下载中断、错误 offset、篡改块、路径穿越/链接、超额 | 只在当前权限下续传；完整校验后发布，不覆盖已存在的冲突文件，不读取范围外文件；配额按协议生效 |
| F10 | X 读取/取消；U/V 撤权后热缓存、冷重开或原键重放 | 当前原资源授权先于返回数据/成功回执；不因另一个项目或节点仍可访问而泄露原记录。登录不自动授予已绑定机器控制权 |
| F11 | 本地 Core 与云端暂时断连；本地继续工作，后续重连 | 本地所属任务/项目继续受本地事实管理；联网只同步获准投影，无隐式双写、重复任务或全库上传。跨实例迁移若未实现应明确拒绝 |
| F12 | 本机目录含合成隐私标记；Web 检索/预览、Agent 工具请求扩大范围 | 仅出现获准元数据/摘录/产物；原件/索引不自动出站。未授权模型/工具调用为零，错误和日志不含凭据或范围外正文 |
| F13 | 旧节点/客户端缺精确读取或新协议能力；任务超出心跳窗口 | 协商后明确提示不支持；已知任务不因列表缺失变成不存在，不用缓存冒充实时值；旧 v1 合同回归保持 |
| F14 | GUI 专业软件无图形会话/会话锁定/另一用户占用 | 不把“节点在线”当可用桌面。需要的会话、Computer Use 权限和停止能力独立预检；不能借浏览器控制权限操纵整机桌面 |
| F15 | 查看结果时切布局、关闭标签、切项目；有草稿或晚到响应 | 不丢草稿/Viewer 状态，不把旧项目/旧节点响应写进新页面；需要丢弃时显式决定，不隐式保存/运行 |

运行期不承诺任意外部程序的“绝对恰好一次”副作用。对不能核实的外部调度/许可操作保留不确定状态，并以原身份核对；
故障测试须检查真实启动次数和外部回执，不能仅统计 HTTP 成功数。资源共享先验收独立任务与明确步骤；跨节点 MPI/分布式训练另有引擎和科学验收。

## 6. PDF 标注与文献边界

此项属于后续原生 UI/协议实现后的验收，现有本地文献服务和页面 CPU 验证不能算它通过。

1. 打开已授权的固定 SHA PDF，在旋转/裁剪页的文本、图形边界创建原生标注；记录文档版本、页、坐标系及页框。
   经过缩放、旋转、换布局、保存/重开后，标注仍对应原内容；PDF 被替换时显式冲突，不贴到同名新文件。
2. Web 只读取明确共享的页面/缩略图/标注投影，展示范围与版本；未授权原件不可下载。
   Web 编辑标注只有发布了相应写合同后才验收，不能复用 desktop-only 方法来扩大权限。
3. Web 标注写合同发布且实现后，才测两端编辑同一修订的 CAS、冲突草稿和恢复；此前只测 native 修订冲突与 Web 只读投影。
   被动翻页/检索/刷新不保存、不重建索引、不调用外部模型。
   同时检查页资源在撤权、换项目和关闭时释放，以及晚到页面不会重新出现。

|---|---|
| `run-manifest.json` | 用例/阶段、UTC 起止、源码/构建/协议、部署配置、OS/硬件、节点及归属、资产 SHA、真实/stub 模式和已禁用模型请求 |
| `requests.jsonl` / `events.jsonl` | 原请求指纹/操作键、action/task/attempt 关联、当前授权检查、状态与观察时间、日志偏移/事件游标；敏感头和私有内容不入包 |
| `execution.json` | 实际软件/版本、脱敏许可检查/checkout 证据、进程身份、退出/取消、GPU 设备与实际参与证据；stub 明确标记 |
| `artifacts.json` | 输入/输出 SHA、大小、类型、单位、格式版本、来源链、完整校验和参考值/容差；Web 预览与完整结果分列 |
| `ui-actions.jsonl` 与画面 | 固定初始布局、每次真实点击及其他输入、响应结束状态、实际点击总数、Viewer/草稿断言；截图/录像与 DOM 或原生控件值互证 |
| `backend-parity.json` | 同修订两部署的逐项契约比较、允许差异及原始 ID 关联；新任务不与另一部署的独立任务混为同一运行 |
| `resources.json` | 本轮自有进程/容器/端口/临时目录、实际启动/退出/清理；保留产物另列，不清理其他用户或共享资源 |
| `assertions.json` | 用例、预期、实测、证据定位、结果与未覆盖条件；保留首次失败和后续修正，禁止把未运行改写为通过 |

结果使用 `not_run`（未执行）、`pass`、`fail`、`blocked`、`stub_only`。缺真实许可/GPU 时，可用确定性 stub 验证选择、授权、资源租约、
回执、状态、恢复和错误分支；只能记 `stub_only`，不得宣称许可 checkout、专业软件执行、实际 GPU 参与、原生 GUI 或科学质量通过。
真实执行仍按设备/版本/部署/平台分别判定，缺资产不作自然跳过后合并成全绿。

自动化环境保持 `STK_TOKEN_PLAN_API_KEY=` 为空、`STK_TOKEN_PLAN_MODEL` 未设置；无收费模型请求，刷新/恢复也不得调用模型。
AI 对话/工具链可以先用模拟提供者验收消息与操作关联；真实模型效果另有授权和数据边界，本方案不以模拟输出证明效果。
公开证据只使用公开合成资产；如后续必须处理受限输入，公开包保留必要摘要和脱敏断言，原始材料按其权限保管。
