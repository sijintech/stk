# 鸿蒙原生适配状态

目标仍是 ArkTS 宿主 + 原生自绘界面 + 本地三维，重型计算与后处理在服务器。当前实现没有把普通 Linux 二进制声明为鸿蒙版本，也没有可在模拟器运行的 Blender 原生包。

Blender 源码路线需要同时完成以下实际移植，只有 XComponent 壳并不足够：

1. GHOST：增加 OHOS 系统/窗口实现，桥接 NativeWindow、触控/鼠标/键盘、输入法组合文本、剪贴板、DPI 与窗口生命周期。
2. GPU：在目标 SDK/驱动支持的接口上创建和恢复原生绘制上下文；与 Blender GPU 层衔接。不能直接把此前 wgpu 的 OHOS 支持当成 Blender 已支持。
3. 构建：OHOS 工具链、Python 嵌入、字体、图片、OpenColorIO、TBB 等依赖的交叉编译与许可清单。
4. 宿主：ArkTS/XComponent 的 Surface 创建/销毁、焦点和生命周期与 GHOST 对应，网络桥接需改用可在应用沙箱中工作的宿主服务通道。
5. 验收：先模拟器验证创建窗口、中文输入、分区调整、三维交互及前后台恢复；再在鸿蒙电脑真机上测兼容性、性能、设备丢失和恢复。

`check_environment.py` 只做环境诊断，输出事实和缺失项，不伪造通过记录。当前开发环境未发现鸿蒙 SDK、`hdc`、`hvigorw`/`hvigor` 和模拟器，因此模拟器移植实现/运行尚未完成；真机验收仍是正式发布的必要条件。
