# 温度扫描：项目表格 → 冻结输入 → Runtime → 结果表格

仅想测试本机界面时，先用[无需服务器的离线演示](OFFLINE.md)。

这是工作流演示，计算确定性的合成三维高斯场，**不是物理求解器**。每个任务只需要服务端 Python
标准库，输出 `metrics.json`、`field.vtk`、`slice.png`。macOS/Windows/Linux 桌面均可作为客户端；
真实 Runtime 服务仍运行在 Linux，可通过已有直连或 STK 管理的 SSH 连接访问。

1. 更新 `main`，运行[桌面快速启动脚本](../../desktop/QUICKSTART.md)。在 Jobs 中保存并检查 Runtime
   连接，例如 `runtime:lab`。此最小示例暂不处理 Hub 创建工作区和上传时的审核暂停。
2. 在 VSCode 编辑本目录 `prepare.py` 顶部的 `CONNECTION`。默认温度为 300、325、350 K；每次运行
   使用新的 `~/STK Projects/temperature-scan-时间戳` 项目目录，也可明确指定其他空目录。
3. 打开桌面 **Python** 面板，选择 `prepare.py`，点击“运行文件”。它创建参数表，保存程序/输入快照，
   创建三个工作区并上传副本，然后保存执行方案。**这一步不会提交计算任务。** 项目会显示在工作台中。
4. 打开 **项目表格 → 运行记录 → 加载运行记录**。检查三个方案的冻结参数、输入哈希和命令，逐个点击
   “提交运行”，再按“刷新状态”查看进展。准备之后修改参数，不会重写已有输入或方案；要运行新参数须
   重新生成输入和准备方案。旧结果一直保留。
5. 任务成功后，在 Python 面板选择 `collect.py`，点击“运行文件”。它刷新状态、下载成功任务的结果，
   登记文件，并创建/更新“Results / 结果比较”表。未执行、待审核、排队或失败任务只报告状态。
   收集前重新对照远端产物清单校验本地文件 SHA-256，拒绝已修改的结果。
   可重复收集，不重复提交任务、不重复添加结果行；结果表使用稳定 UUID。删除已经下载的文件后，
   对应旧传输记录不会自动重新下载，需在 Transfers 处理或使用新的下载键。
6. 运行同目录 `show.py`，自动用共同数值范围打开最近收集的演示结果，切换到 Viewer；
   也可用 `stk.viewer.open(结果目录, preset="volume", parameters={"path": "field.vtk"})` 明确选择另一项。
7. 在结果表比较平均值和最大值；演示场的最大值应等于各自温度，平均值随温度等比例变化。
   输出的 VTK 路径会打印在 Python 面板；把它所在的结果目录拖到 Viewer，选择 `Volume of |v|` 预设，
   将属性中的 `Field file` 改为 `field.vtk`，即可查看三维标量场（当前不能直接拖单个 VTK 文件）。
   文件索引也可打开 PNG/JSON，或跳转 VSCode。原生 Viewer 的格式读取仍需要相应的科学/VTK 依赖。

关闭桌面后可重新打开项目，加载运行记录继续查看；不依赖原 Python 会话中的变量。收集脚本始终使用
本次执行开始时选中的项目。输入和程序副本存入项目 `.stk/objects`，程序使用实际冻结字节；结果文件
位于 `results/<run-id>/`，数值汇总只写入普通表格，不会改写运行方案。

示例不自动重试提交，不自动取消任务。准备中途传输失败时，已创建的项目、工作区和传输记录保留，
不会自动回滚外部操作；查看 Python/Transfers 的错误后决定如何恢复。关闭桌面不会停止已提交计算。
实际应用应将此处的 `solver.py`、输入生成和结果解析替换为自己的求解器流程。
